Definition

R ka R1, R2 mein decomposition lossless-join hai agar har legal instance r ke liye πR1(r) ⋈ πR2(r) = r.

Hamesha r ⊆ πR1(r) ⋈ πR2(r) hota hai (asli rows to wapas aati hi hain). Dikkat sirf extra (spurious) tuples ki hoti hai. Isiliye “lossy” = “extra rows”, jabki naam “loss” hai!

Trap

“Lossy” ka matlab rows gum hona nahi. Rows badh jaati hain. Yaad rakho: lossy ⇒ join ke baad rows zyada.

Ab tum try karo

Q. R(A,B,C) mein rows (1,x,p), (2,y,q). R1(A,B), R2(B,C) lossless hai ya lossy is instance par?

Ans. Join karo: B alag hai (x ≠ y) ⇒ (1,x,p), (2,y,q) hi aaye ⇒ is instance par lossless. Par decomposition tab lossless kehlaata hai jab har legal instance par ho — wo hum FDs se check karte hain (agle sections).

12.2 · Binary rule — 2 tables ke liye aasaan test 3 second ka kaam

Binary lossless rule

R ko R1, R2 mein todne par decomposition lossless hai agar aur sirf agar F+ mein ye dono mein se koi ek FD ho:

R1 ∩ R2 → R1 − R2  YA  R1 ∩ R2 → R2 − R1

Sadi bhasha: common attributes kisi ek tukde ko poori tarah determine karein (matlab common part us tukde ki superkey ho).

Kyun kaam karta hai? (picture)

Join mein har row ko common part (B) ke basis par match karte hain. Agar common B se doosre tukde ka baaki hissa ek hi value nikalta hai (B → C), to ek B ke saath ek hi C jud sakta hai ⇒ fake combination ban hi nahi sakta. Agar B ke saath kai C hon (B → C nahi), to har A ko har C se judne ka mauka milta hai ⇒ fake rows.

Step by step

  1. R1 ∩ R2 nikalo. Khali ho to lossy (koi FD “∅ → …” na ho to).
  2. Closure nikalo: (R1 ∩ R2)+ poore F ke hisaab se.
  3. Agar closure mein R1 ke saare attributes ya R2 ke saare attributes aa gaye ⇒ lossless. Warna lossy.

Traps (binary rule)
  • Closure poore R ke F se nikalo, sirf R1 / R2 ke andar ke FDs se nahi. (Row 7: A → C seedha nahi diya, par A+ = ABC.)
  • FD ka direction matter karta hai. Row 3 mein A → B hai par common part B hai, A nahi ⇒ lossy.
  • Common part ko R1 ya R2 mein se kisi ek ka superkey hona chahiye — dono ka nahi.
  • Yeh rule sirf 2 tukdon ke liye hai. 3+ tukdon ke liye chase (agla section), ya tukdon ko ek-ek karke jodte hue baar-baar binary rule.
Chain trick

Agar R ko R1, R2 mein lossless toda, phir R1 ko R11, R12 mein lossless toda, to {R11, R12, R2} bhi R ka lossless decomposition hai. BCNF algorithm isi se hamesha lossless hota hai.

Ab tum try karo

Q. R(A,B,C), F = {B → A}. R1(A,B), R2(B,C). Lossless?

Ans. R1 ∩ R2 = B; B → A = R1 − R2 ✔ ⇒ lossless.

12.3 · Chase (tableau) method — kisi bhi decomposition ke liye sabse powerful test

Binary rule 2 tukdon par chalta hai. 3, 4, 5 tukde hon to chase. Idea: hum maan lete hain ki ek row ke hisse alag-alag tukdon se aaye hain, aur FDs se dekhte hain ki kya wo ek poori original row ban sakti hai. Agar ban gayi ⇒ join se original row mil gayi ⇒ lossless.

Algorithm

  1. Table banao: har tukde Ri ke liye ek row, R ke har attribute ke liye ek column.
  2. Bharo: agar attribute Aj Ri mein hai to symbol aj (distinguished), warna bij (har jagah alag, unique).
  3. Har FD X → Y ke liye: jin rows mein X ke symbols bilkul same hain, unke Y ke symbols barabar kar do. Do symbols mein a ho to a rakho (b ko a bana do); dono b hon to koi ek rakho. Badlaav poore column mein har jagah karo.
  4. Jab tak koi badlaav ho FDs dohrate raho.
  5. Kisi bhi row mein saare a (a1 a2 … an) aa gaye ⇒ LOSSLESS. Nahi ⇒ LOSSY.
Yaad rakhne ki trick

a = “asli attribute is tukde mein hai”, b = “pata nahi / khali”. FD ek pull hai jo b ko a bana deti hai. Row mein sab a ban gaye = us row ko pura original tuple ban jaane ka raasta mil gaya.

Chase ke traps
  • Badlaav poore column mein karo, sirf ek row mein nahi — yahin sabse zyada galti hoti hai.
  • Do symbols mein a hamesha jeette hai.
  • FD tabhi lagao jab X ke symbols poori tarah barabar hon (ek bhi b alag to X same nahi).
  • Chase har bar same answer deta hai, FD kisi bhi order mein lagao. Chase sirf FDs ke liye sahi hai (MVD alag hota hai).
Ab tum try karo

Q. R(A,B,C,D), F = {A → B, C → D}; decomposition R1(A,B), R2(C,D), R3(A,C). Lossless?

12.4 · Dependency preservation — FDs kho to nahi gaye? bina JOIN ke check

Pehle picture

Maan lo R(A,B,C) mein rule hai A → C (har A ka ek hi C). Agar hum R ko R1(A,B), R2(B,C) mein tod dein, to A aur C alag tables mein chale gaye. Ab koi insert hone par check karna ho ki A → C tooti ya nahi, to R1 ⋈ R2 banana padega — mehnga kaam. Yani FD enforce karna mushkil. Isliye hum chahte hain ki har FD kisi ek tukde ke andar hi (ya unse nikal sake) ho.

Exact definition

Projection: Fi = Ri ke attributes par F+ ke wo FDs jinke dono taraf ke attributes Ri ke andar hon. (Dhyan: F+ se, sirf likhe hue FDs se nahi.)

Decomposition dependency-preserving hai agar (F1 ∪ F2 ∪ … ∪ Fk)+ = F+, yaani F ka har FD in tukdon ke FDs se nikal aaye.

Sabse bada trap: FD chhup ke bhi bach sakta hai

FD seedha kisi tukde mein na ho to bhi preserved ho sakta hai, agar wo tukdon ke FDs se derive ho jaaye. Isliye “FD ke saare attributes ek hi tukde mein hain?” sirf sufficient hai, necessary nahi. Neeche cycle example dekho.

Closure-based Z-algorithm (exam ka asli hathiyaar)

Projections Fi nikalna lamba hai (har subset ka closure). Isse chhota tareeka — har FD X → Y ke liye:

  1. Z = X se shuru karo.
  2. Har tukde Ri ke liye: Z = Z ∪ ( (Z ∩ Ri)+ ∩ Ri ). (Yaani Z ka Ri wala hissa lo, uska closure poore F se nikalo, aur sirf wo attributes rakho jo Ri mein hain.)
  3. Saare tukdon par baar-baar tab tak karo jab tak Z badalna band na ho.
  4. Agar Y ⊆ Z ⇒ ye FD preserved ✔. Warna ✘.
  5. Decomposition preserving hai tabhi jab F ke saare FDs preserved hon.

Kyun? Ri ke andar ka FD wahi hai jo F+ mein ho aur Ri ke attributes tak seemit ho. Z mein “Ri se bahar ka” kuch nahi jaata — ye step wahi dikhata hai ki sirf tukdon ke FDs se kitna aage badh sakte hain.

Example 1 — cycle: FD “chhup ke” bachta hai

R(A,B,C,D), F = {A → B, B → C, C → D, D → A}; decomposition {R1(A,B), R2(B,C), R3(C,D)}.

  • A → B R1 mein, B → C R2 mein, C → D R3 mein seedhe ✔.
  • D → A kisi tukde mein nahi (D sirf R3 mein, A sirf R1 mein). Z-algorithm: Z = {D}.

Example 2 — FD kho gaya

R(A,B,C), F = {A → B, B → C}; decomposition {R1(A,B), R2(A,C)}.

  • A → B ✔ (R1 mein).
  • B → C: Z = {B}. R1: Z ∩ R1 = B, B+ = BC, ∩ AB = B. R2: Z ∩ R2 = ∅. Z = {B} ⇒ C ∉ Z ✘. B → C preserved nahi.

Cross-check (projection se): F1 (AB par): A+ = ABC ∩ AB = AB ⇒ A → B; B+ = BC ∩ AB = B ⇒ kuch nahi. F2 (AC par): A+ ∩ AC = AC ⇒ A → C; C+ = C. Union = {A → B, A → C}. B+ iske hisaab se = B ⇒ B → C nahi nikalta ✘. Dono tareeke same.

Par ye decomposition lossless hai (R1 ∩ R2 = A, A → B ✔). Yaani: lossless ✔, preserving ✘.

Example 3 — BCNF ka FD kho jaana (Lesson 11 se)

TEACH(Student, Course, Instructor) → {(Instructor, Course), (Student, Instructor)}. F = {(Student, Course) → Instructor, Instructor → Course}. Z = {Student, Course}: (Instructor, Course) se Z ∩ = Course, Course+ = Course ⇒ kuch nahi; (Student, Instructor) se Z ∩ = Student, Student+ = Student ⇒ kuch nahi. Instructor kabhi nahi aata ⇒ FD kho gayi.

Ab tum try karo

Q. R(A,B,C,D), F = {AB → C, C → D, D → A}; decomposition {ABC, CD}. Preserving?

Ans. AB → C ABC mein ✔. C → D CD mein ✔. D → A: Z = D. ABC: Z ∩ = ∅. CD: Z ∩ = D, D+ = DA, ∩ CD = D ⇒ Z = D ✘ ⇒ preserving nahi. (Lossless ✔: ∩ = C, C → D.)

Important facts (GATE ke liye)

  • Lossless zaruri hai (information ki safety). Preserving achhi to hai, par kabhi-kabhi chhodni padti hai.
  • BCNF decomposition (Lesson 11 ka algorithm): hamesha lossless, preserving nahi bhi ho sakta hai (TEACH example). Kai relations ka koi BCNF decomposition preserving ho hi nahi sakta.
  • 3NF: hamesha lossless + dependency-preserving decomposition mil jaata hai (synthesis algorithm).
  • Lossless ⇏ preserving, aur preserving ⇏ lossless.
  • Agar koi relation pehle se BCNF mein hai to todne ki zaroorat hi nahi (trivial decomposition {R} lossless + preserving).

12.6 · Canonical (minimal) cover FDs ki safai

3NF synthesis se pehle F ko saaf karte hain: zaroorat se zyada kuch nahi, par F ke barabar (same closure).

  1. RHS single karo: A → BC ko A → B aur A → C mein todo. Duplicate hatao.
  2. Extraneous LHS attribute hatao: X A → B mein A tab extraneous hai agar B ∈ X+ (X+ poore F se). Tab FD ko X → B se badal do.
  3. Redundant FD hatao: X → B tab redundant hai agar usse hata kar bhi B ∈ X+ (bachi hui FDs se). Ek-ek karke hatao (har hatane ke baad recompute).
  4. (Optional) Same LHS wale FDs ko wapas jod do: A → B, A → C ⇒ A → BC.

Example 1

F = {A → BC, B → C, A → B, AB → C}.

  1. Split: A → B, A → C, B → C, A → B (duplicate), AB → C ⇒ {A → B, A → C, B → C, AB → C}.
  2. LHS: AB → C: A extraneous? C ∈ B+ = BC ✔ ⇒ haan, A hatao ⇒ B → C (pehle se hai). F = {A → B, A → C, B → C}.
  3. Redundant: A → C hatao to bachi {A → B, B → C} se A+ = ABC ∋ C ⇒ redundant. A → B hatao to A+ = AC ∌ B ⇒ zaroori. B → C hatao to B+ = B ⇒ zaroori.

Canonical cover = {A → B, B → C}.

Example 2

F = {A → BC, AB → D, C → D}.

  1. Split: {A → B, A → C, AB → D, C → D}.
  2. AB → D: B extraneous? D ∈ A+: A ⇒ B, C ⇒ D ✔ (A+ = ABCD) ⇒ haan ⇒ A → D. F = {A → B, A → C, A → D, C → D}.
  3. A → D hatao: A+ = A → B, C, then C → D ⇒ D ✔ ⇒ redundant. Baaki (A → B, A → C, C → D) mein koi hataya to bandh.

Canonical cover = {A → B, A → C, C → D} = {A → BC, C → D}.

Traps (cover)
  • Canonical cover unique nahi hota (order se badal sakta hai). Jaise F = {A → B, B → A, A → C, C → A, B → C, C → B} ke liye {A → B, B → C, C → A} bhi cover hai aur {A → B, B → A, A → C, C → A} bhi.
  • Extraneous check pehle karo, redundant check baad mein.
  • Extraneous test mein closure original F se nikalo (jisme wo FD abhi bhi hai).
Ab tum try karo

Q. F = {A → B, B → C, A → C}. Cover?

Ans. A → C redundant (A → B → C). Cover = {A → B, B → C}. (Handbook ka wahi example.)

12.7 · 3NF synthesis — lossless + preserving guarantee algorithm

  1. F ka canonical cover Fc nikalo (12.6).
  2. Fc ke har FD X → A ke liye ek relation Ri = X ∪ {A} banao. (Same LHS wale FDs ek hi relation mein jod do: X → A1, X → A2 ⇒ X A1 A2.)
  3. Check karo: kya koi bhi Ri mein R ki koi candidate key poori maujood hai? Agar nahi ⇒ ek aur relation R0 = koi ek candidate key jodo.
  4. Agar koi relation kisi doosre ka subset hai to use hata do.
Kyun chalta hai?
  • Preserving: Fc ka har FD kisi ek relation mein seedha hai.
  • Lossless: key waali relation hone se (chase se saabit) joins key se jude rehte hain.
  • 3NF: har Ri mein key ya prime se hi FD bachte hain.

Example 1 — key pehle se ek tukde mein

R(A,B,C,D,E), F = {A → BC, CD → E, B → D, E → A}.

  1. Cover: split ⇒ A → B, A → C, CD → E, B → D, E → A. Extraneous: CD → E: C hatao? E ∈ D+ = D ✘. D hatao? E ∈ C+ = C ✘. Redundant? A → B hatao: bachi FDs se A+ = AC ∌ B ⇒ zaroori. A → C hatao: A+ = ABD ∌ C ⇒ zaroori. CD → E, B → D, E → A: inke RHS (E, D, A) kisi aur FD se nahi nikalte ⇒ zaroori. Koi redundant nahi ⇒ Fc = F.
  2. Candidate keys: A+ = ABCD (B → D) ⇒ + E (CD → E) ✔; E+ ⇒ A ⇒ sab ✔; (BC)+: B → D ⇒ BCD ⇒ CD → E ⇒ E ⇒ A ✔; (CD)+: E, A, B ✔. CKs = A, E, BC, CD.
  3. Relations: A → BC ⇒ R1(A,B,C); CD → E ⇒ R2(C,D,E); B → D ⇒ R3(B,D); E → A ⇒ R4(E,A).
  4. Key A ⊆ R1 ✔ ⇒ extra relation nahi. Koi subset nahi.

Result: {ABC, CDE, BD, EA} — lossless + preserving + 3NF.

Example 2 — key kisi mein nahi aati ⇒ key-relation jodo

R(A,B,C,D,E), F = {A → B, C → D}.

  1. Cover = F. Keys: A, C, E RHS par nahi ⇒ core = ACE; (ACE)+ = ABCDE ⇒ CK = ACE.
  2. Relations: AB, CD. Koi mein ACE nahi ⇒ R0 = ACE jodo.

Result: {AB, CD, ACE}. (Agar ACE na jodte to {AB, CD} lossy hota: attribute E hi gayab!)

Example 3 — BCNF vs 3NF side by side

R(A,B,C,D), F = {AB → C, C → D, D → A}. CKs = AB, BC, BD (Lesson 11). R 3NF mein hai par BCNF mein nahi.

Traps (synthesis)
  • Key-relation wala step 3 mat bhoolo — nahi to lossless nahi.
  • Synthesis ka result BCNF hona zaruri nahi.
  • Cover pehle nikalo; warna redundant relations aa jaate hain.
  • Same LHS wale FDs ek hi relation mein jodo (A → B, A → C ⇒ ABC), aur agar koi Ri kisi Rj ka subset ho to hata do.
Ab tum try karo

Q. R(A,B,C,D,E), F = {A → B, BC → D, D → E}. 3NF synthesis?

Ans. Cover = F. Core = AC; (AC)+ = A, B (A → B), D (BC → D), E (D → E) = sab ⇒ CK = AC. Relations: AB, BCD, DE; AC kisi mein nahi ⇒ + AC. {AB, BCD, DE, AC}.

12.8 · Real GATE DA PYQ 2025 Q16

PYQ · GATE DA 2025 · Q16 Dependency preservation · MCQ

“If a relational decomposition is not dependency-preserving, which one of the following relational operators will be executed more frequently in order to maintain the dependencies?”  (A) Selection  (B) Projection  (C) Join  (D) Set union

  1. Not dependency-preserving ⇒ koi FD X → Y aisa hai jiske attributes alag-alag tables mein bikhre hain (12.4 ki picture).
  2. Us FD ko check karne ke liye X aur Y ko ek hi row mein laana padega — yaani un tables ko jodna padega.
  3. Tables ko attributes ke basis par jodne wala operator = Join. Selection / projection ek table par kaam karte hain; union same-type tables ke rows jodta hai (attributes nahi).
Official answer
Option C — Join. Isi ko “dependency preserve karne ka fayda = join ke bina check” kehte hain.
Aur PYQs jo is lesson ka hissa hain

GATE DA ne Lesson 11-12 se 2024-2026 mein ye hi pooche: 2025 Q57 (keys + BCNF), 2026 Q17 (candidate keys), 2026 Q61 (3NF relations count), 2025 Q16 (above). Pehle 3 Lesson 11 mein solve hain. Decomposition ke numerical (chase / Z-test) abhi tak GATE DA mein seedhe nahi aaye, par GATE CS mein bahut aate hain, isliye neeche practice mein hain.

12.9 · Practice questions jawab ke saath

Q1. R(A,B,C,D), F = {A → B, B → C, C → D}. Decomposition {AB, BC, CD}: lossless? preserving?
✔ Lossless ✔, preserving ✔.
A → B, B → C, C → D seedhe tukdon mein ⇒ preserving. Chase (12.3 Ex 2) ⇒ lossless.
Q2. Same R aur F. Decomposition {AB, CD}: lossless? preserving?
✔ Lossy, preserving nahi.
∩ = ∅ ⇒ lossy. B → C: Z = B; AB se B+ = BCD ∩ AB = B; CD se ∅ ⇒ Z = B ✘. (A → B, C → D ✔.)
Q3. R(A,B,C,D), F = {AB → C, C → D, D → A}. Decomposition {ABC, CD}.
✔ Lossless ✔, preserving ✘.
∩ = C, C → D = CD − ABC ✔ ⇒ lossless. D → A: Z = D ⇒ (CD) se D+ = DA ∩ CD = D ⇒ Z = D ✘.
Q4. R(A,B,C,D,E), F = {AB → C, C → D, D → E}. Decomposition {ABC, CD, DE}. Chase se lossless?
✔ Lossless ✔.
Rows: R1 = a1 a2 a3 b14 b15; R2 = b21 b22 a3 a4 b25; R3 = b31 b32 b33 a4 a5. C → D: R1, R2 (C = a3) ⇒ R1.D = a4. D → E: R1, R2, R3 (D = a4) ⇒ E: b15, b25, a5 ⇒ a5 ⇒ R1 = a1 … a5 ✔.
Q5. R(A,B,C,D), F = {A → B, C → D}. Decomposition {AB, CD, AC}: lossless?
✔ Lossless ✔.
12.3 ke “try karo” wala. A → B se R3.B = a2, C → D se R3.D = a4 ⇒ R3 sab a.
Q6. R(A,B,C,D), F = {A → B, B → C, C → D, D → A}. Decomposition {AB, BC, AD}: lossless? preserving?
✔ Dono ✔.
A → B ✔ (AB), B → C ✔ (BC), D → A ✔ (AD). C → D: Z = C; AB ∩ = ∅; BC: C+ = ABCD ∩ BC = BC ⇒ Z = BC; AB: B+ ∩ AB = AB ⇒ Z = ABC; AD: A+ ∩ AD = AD ⇒ Z = ABCD ∋ D ✔. Lossless: AB ∩ BC = B, B → A ✔; ABC ∩ AD = A, A → D ✔.
Q7. R(A,B,C,D,E), F = {A → B, BC → D, D → E}. 3NF synthesis karo.
✔ {AB, BCD, DE, AC}.
CK = AC (12.7 ka try-karo). Key kisi relation mein nahi ⇒ AC jodo.
Q8. F = {A → BC, AB → D, C → D} ka canonical cover?
✔ {A → B, A → C, C → D}.
12.6 Example 2: AB → D mein B extraneous ⇒ A → D ⇒ A → C, C → D se redundant.
Q9. (MSQ) Sahi statements: (a) Har relation ka BCNF mein lossless + dependency-preserving decomposition hota hai. (b) Har relation ka 3NF mein lossless + preserving decomposition hota hai. (c) Har BCNF decomposition lossless hota hai (Lesson 11 algorithm se). (d) Lossless decomposition hamesha dependency-preserving hota hai.
✔ (b), (c) sahi; (a), (d) galat.
(a) TEACH counter-example; (d) {AB, AC} wala 12.4 Ex 2.
Q10. R(A,B,C), F = {A → B}. Decomposition {AB, BC}. Lossless? preserving?
✔ Preserving ✔, lossy ✘.
A → B AB mein ✔. ∩ = B, B+ = B ⇒ lossy (12.1 wala example).
Q11. R(A,B,C), F = {B → A}. Decomposition {AB, BC}. Lossless? preserving?
✔ Dono ✔.
∩ = B, B → A = R1 − R2 ✔ ⇒ lossless. B → A AB mein ✔ ⇒ preserving.
Q12. R(A,B,C,D), F = {A → B, B → C}. {AC, BD} lossless? Kyun?
✔ Lossy.
∩ = ∅ ⇒ lossy. (Common attribute ke bina join = cross product.)

12.10 · Lesson 12 cheat box exam se pehle

Formulas / tests
  • Binary lossless: (R1 ∩ R2) → (R1 − R2) ya (R2 − R1).
  • Chase: a / b table; FD se b → a; ek row all-a ⇒ lossless.
  • Preservation: har X → Y ke liye Z = X; Z ∪= ((Z ∩ Ri)+ ∩ Ri) tukde-tukde, repeat; Y ⊆ Z?
  • Cover: split RHS → extraneous LHS → redundant FDs.
  • 3NF synthesis: cover → har FD ek relation → key relation jodo → subsets hatao.
Traps
  • Lossless ≠ preserving (4 combinations possible).
  • BCNF: lossless ✔, preserving kabhi ✘. 3NF: dono ✔ hamesha.
  • ∩ = ∅ ⇒ lossy.
  • Closure poore F se nikalo, tukde ke andar ke FD se nahi.
  • Chase mein rename poore column mein.
  • FD seedhe nahi dikhe to bhi preserved ho sakta hai (cycle).
  • Not-preserving ⇒ Join zyada baar (2025 Q16 = C).
