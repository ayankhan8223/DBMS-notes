L1–3  ER model and ER → relations

  • Relationship degree = number of participating entity types (binary 2, ternary 3). Cardinality: 1:1, 1:N, M:N. Participation: total (every instance takes part) / partial.
  • Mapping: strong entity → 1 table. Composite attribute → only its components. Multi-valued attribute → own table (owner key + value; key = both). Derived: not stored.
  • 1:N → FK on the N side (no new table). 1:1 → FK on either side (prefer total side) or merge. M:N → new table, key = union of both keys. n-ary → new table with all keys.
  • Weak entity → table with owner key + partial key; PK = (owner key, partial key). The identifying relationship adds no table.
  • Min relations = #entities (non-weak and weak) + #multi-valued attrs + #M:N relationships + #n-ary (n≥3) relationships. (Agar 1:1 relationship ke dono sides total hon aur merge karo to ek table kam: Lesson 3.)

L4–5  Relation, keys, integrity

  • Degree = #columns, cardinality = #rows (tuples). Relation = set: no duplicate tuples. SQL tables can have duplicates.
  • Superkey ⊃ candidate key (minimal superkey). If R has n attributes and the only candidate key is one attribute: superkeys = 2n−1. If only candidate key has k attributes: 2n−k.
  • Max number of candidate keys in R(n attrs) = C(n, ⌊n/2⌋).
  • PK: unique, NOT NULL. FK: references a PK/candidate key; may be NULL, may repeat.
  • FK break check: insert child, delete parent, update parent key, update child FK can violate. Insert parent and delete child never violate.

L8–9  SQL

  • Logical order: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. WHERE filters rows (no aggregates); HAVING filters groups.
  • NULL: any comparison with NULL = UNKNOWN; WHERE keeps only TRUE. Use IS NULL. x <> 2 drops NULL rows. NOT IN (subquery containing NULL) returns no rows. TRUE AND UNKNOWN = UNKNOWN; TRUE OR UNKNOWN = TRUE.
  • COUNT(*) counts rows; COUNT(col) skips NULL; SUM/AVG/MIN/MAX skip NULL (all NULL → NULL). COUNT(DISTINCT col) distinct non-NULL.
  • UNION / INTERSECT / EXCEPT remove duplicates; ALL keeps them.
  • Join rows: inner = Σ matches (a duplicates × b duplicates). LEFT = inner + unmatched left. FULL = inner + unmatched left + unmatched right.
  • Aggregate in subquery (e.g. > (SELECT MAX…)) is one number. Correlated: re-evaluated per outer row. ANY on empty set = false, ALL on empty set = true. EXISTS tests non-emptiness.
  • Derived table columns: only what the inner SELECT lists are visible outside.
  • CUBE(a,b,c): 23 grouping sets. ROLLUP(a,b,c): 4 grouping sets: (a,b,c), (a,b), (a), ().

L10  Functional dependencies

  • Armstrong: reflexivity (Y⊆X ⇒ X→Y), augmentation (X→Y ⇒ XZ→YZ), transitivity. Derived: union, decomposition, pseudo-transitivity (X→Y, WY→Z ⇒ WX→Z).
  • Closure X+: start {X}; keep adding RHS of any FD whose LHS ⊆ current set. X→Y holds iff Y ⊆ X+.
  • Key: X is a key iff X+ = R and no proper subset has this. Attributes never on any RHS must be in every key. Attributes only on RHS are in no key. If the must-have attributes already give R: that is the only key.
  • F ≡ G iff F covers G and G covers F. Minimal cover: single-attribute RHS → remove extraneous LHS attrs → remove redundant FDs.
  • If X+ = R but X is not minimal, X is a superkey, not a key.

L11  Normal forms

NFRule for every non-trivial X→A
1NFatomic values only
2NFno non-prime attribute depends on a proper subset of a candidate key
3NFX is a superkey or A is prime
BCNFX is a superkey (no exception)
  • BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF. Every 2-attribute relation is in BCNF. All attributes prime ⇒ 3NF. All keys single attributes ⇒ 2NF. 3NF but not BCNF needs overlapping candidate keys.
  • Test with all FDs, including those implied (use closures), and with all candidate keys.

L12  Decomposition

  • Binary lossless: R→R1,R2 lossless iff (R1∩R2)→R1 or (R1∩R2)→R2 in F+. Many parts: chase / table method.
  • Dependency preserving: (F1∪…∪Fk)+ = F+. Test each X→Y: Z := X; repeat Z := Z ∪ ((Z∩Ri)+∩Ri) for every Ri; preserved iff Y⊆Z. Cyclic FDs can survive through chains.
  • 3NF synthesis: always lossless and dependency preserving. BCNF decomposition: always lossless, may lose dependencies. Not dependency-preserving ⇒ checking needs a JOIN.

L13  File organization

  • Unspanned: bfr = ⌊(B − header) / R⌋ (header ho to pehle B me se ghatao), blocks b = ⌈r / bfr⌉. Spanned: b = ⌈r·R / B⌉ (no wasted space; usable bytes = B − block pointer). Pehle floor (bfr), phir ceil (blocks).
  • Heap: search avg b/2 (key found), worst b; insert at end 1. Sorted file: binary search ⌈log2 b⌉. Block accesses count blocks, not records.
  • Hash file: equality fast (about 1 access), no range / order.

  • Single-level search (binary on index): ⌈log2 (index blocks)⌉ + 1. Multilevel (fan-out fo = bfri): levels x = smallest with top level 1 block, i.e. x = ⌈logfo(index blocks at level 1)⌉ + 1; accesses = x + 1.
  • ISAM = static multilevel index on sorted file (overflow chains on inserts).

L15  B-tree and B+ tree

  • Order p = max child pointers per node (Lesson 15 ki Conv. 1: max keys = p−1). Kuch books order ko alag define karte hain: question ki apni definition jeete. Block B, pointer P, key K, record pointer Pr.
  • B+ internal: pP + (p−1)K ≤ B. B+ leaf: L(K + Pr) + Pn ≤ B (L = max keys per leaf, Pn = next-leaf pointer). B-tree node: pP + (p−1)(K + Pr) ≤ B. Example (2026 Q32: B=4096, P=10, K=11): 10p + 11(p−1) ≤ 4096 ⇒ p = 195.
  • Min occupancy (non-root): internal ⌈m/2⌉ children (⌈m/2⌉−1 keys); root ≥ 2 children. B+ leaf: ⌈L/2⌉ keys.
  • Max keys: B-tree of order p and h levels: ph − 1. B+ with h levels (root = level 1): leaves = ph−1, keys = ph−1 × L (e.g. p=23, L=22, h=3: 529 × 22 = 11,638).
  • Search cost = height (+1 data block). B-tree split: median goes up (moves). B+ leaf split: separator is copied up, internal split moves up. Insertion that overflows root grows height by 1.
  • Range query / ordered scan: B+ (linked leaves). Equality only: hash is enough. Hash cannot do range.

L16–18  Data transformation

  • Types: nominal, ordinal (order, no distance), interval (differences, no true zero), ratio (true zero).
  • Min-max: x′ = (x − min)/(max − min) × (new_max − new_min) + new_min. Result in [new_min, new_max]; outliers squash others.
  • z-score: z = (x − μ)/σ. Mean 0, SD 1. Check “population” vs “sample” SD (N vs N−1).
  • Decimal scaling: x′ = x / 10j, smallest j with max|x′| < 1.
  • Equal-width: width = (max − min)/k. Equal-depth: N/k values per bin. Smoothing by bin means / medians / boundaries.
  • Sampling: SRSWOR P(item in sample) = n/N; SRSWR: 1 − (1 − 1/N)n. Systematic k = N/n, start random in 1..k. Stratified proportional nh = n·Nh/N.
  • Compression: lossless (exact: RLE, Huffman, ZIP, PNG) vs lossy (JPEG, MP3). Fixed-length code = ⌈log2 s⌉ bits/symbol for s distinct symbols (e.g. 4 symbols: 2 bits). Huffman: merge two smallest repeatedly; total bits = Σ freq × code length. Ratio = original / compressed.

L19–21  Data warehouse and OLAP

  • Star: 1 fact + de-normalized dimensions. Snowflake: normalized dimensions (more joins, less redundancy). Fact constellation: several facts sharing dimensions.
  • Fact table = measures + FKs to dimensions; key = (combination of dimension keys). Max fact rows = ∏ (dimension cardinalities).
  • n dimensions, no hierarchies: 2n cuboids. With hierarchies (Li levels excluding ALL): ∏ (Li + 1). Base cuboid = most detailed; apex = ALL (1 cell).
  • Cells in the full cube if all combinations exist: ∏ (di + 1) (di = distinct values). Example 3 and 2 values: 12.
  • OLAP: roll-up (less detail / drop a dimension), drill-down (more detail), slice (fix 1 dim to 1 value), dice (sub-cube on 2+ dims), pivot (rotate).
  • Measures: distributive (SUM, COUNT, MIN, MAX): combine partial results. Algebraic (AVG, variance, SD): combine bounded summaries, e.g. (sum, count) or (count, sum, sum of squares). Holistic (MEDIAN, MODE, RANK): need the whole data.
  • Combined average = Σnix̄i / Σni (never average the averages). Variance = E[x2] − (E[x])2.
