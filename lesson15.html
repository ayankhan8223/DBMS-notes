15.1 · Tree index ki zaroorat multilevel index ka dynamic roop

Lesson 14 ka multilevel index tez tha, par static: naya record aaya to blocks bharte-bharte overflow chains ban gayi. Hume chahiye ek aisa index jo insert/delete par khud ko sambhal le aur hamesha balanced rahe.

Analogy: dictionary ke "thumb index" (A, B, C ... ke kaate). Pehle thumb-index (root) → sahi section (internal) → page (leaf). Koi bhi word dhoondhne me barabar steps — ye balance hai.

  • Binary search tree kyun nahi? Disk par har node = ek block read. BST me node chhota (1 key), height ~ log₂ N → bahut blocks. Hume moti (fat) nodes chahiye: ek node = ek disk block, aur usme sau-do-sau keys → height sirf 3-4.
  • Sorted array kyun nahi? Beech me insert → saara data khiskana.
B-tree / B+ tree = fat, balanced, multiway search tree
  • Multiway: ek node me kai keys aur kai children (fan-out bada).
  • Balanced: saare leaves ek hi depth par — har search ka cost same.
  • Node ek block ke barabar — ek node padhna = ek disk access.
  • Half-full rule: root ko chhodkar har node kam se kam aadha bhara — jagah waste nahi.

15.2 · Structure: B-tree vs B+ tree kaun kya rakhta hai

B-tree
  • Har node (internal ho ya leaf) me keys + unke record pointers hote hain.
  • Ek key sirf ek hi jagah aati hai (internal ya leaf).
  • Leaves linked nahi hote.
  • Key mil gayi to wahin ruk sakte hain (upar ke level par bhi).
B+ tree
  • Internal nodes: sirf raasta dikhane wali keys + child pointers (record pointer nahi).
  • Saari actual keys leaf level par hoti hain (+ record pointers).
  • Internal ki keys leaf keys ki copy bhi ho sakti hai (isliye ek key do jagah dikhti hai).
  • Leaves ek linked list me — range scan asaan.
  • Search hamesha leaf tak jaata hai.

Dono ke saare leaves same depth par hote hain. B+ tree ki internal nodes me data pointer na hone se fan-out zyada → height kam. Isi liye databases (aur GATE) me B+ tree zyada important hai.

15.4 · Block size se order nikalna GATE numerical, jaise 2026 Q32

Ek node = ek block (B bytes). Node me jo kuch bhi rakhna hai uska total size ≤ B hona chahiye. Largest m nikalo → floor (capacity!).

Symbols: P = tree (node) pointer, K = search key, Pr = record (data) pointer, Pn = next-leaf pointer.

NodeIsme kya haiInequalityLargest m (ya L)
B+ internalm tree pointers + (m−1) keysm·P + (m−1)·K ≤ Bm = ⌊ (B + K) / (P + K) ⌋
B+ leafL keys + L record pointers + 1 next pointerL·(K + Pr) + Pn ≤ BL = ⌊ (B − Pn) / (K + Pr) ⌋
B-tree node (internal ya leaf)m tree ptrs + (m−1) keys + (m−1) record ptrsm·P + (m−1)·(K + Pr) ≤ Bm = ⌊ (B + K + Pr) / (P + K + Pr) ⌋

Algebra kaise aaya? m·P + (m−1)·K ≤ B → m(P + K) ≤ B + K → m ≤ (B + K)/(P + K). Phir floor.

PYQ · GATE DA 2026 · Q32 (NAT)

Question: B+ tree index, key field par. Node size = 4096 B, Node Pointer = 10 B, Search Key = 11 B, Data Record Pointer = 12 B. Non-leaf node me maximum Node Pointers?

  1. Non-leaf me sirf tree pointers + keys (data record pointer nahi — wo distractor hai).
  2. p pointers, (p − 1) keys: 10p + 11(p − 1) ≤ 4096 → 21p ≤ 4107.
  3. p ≤ 4107/21 = 195.57 → p = 195.
  4. Check: p = 195 → 1950 + 194 × 11 = 1950 + 2134 = 4084 ≤ 4096 ✔; p = 196 → 1960 + 2145 = 4105 > 4096 ✘.

Official answer: 195. (Isi B+ tree ke leaf me L = ⌊(4096 − 10)/(11 + 12)⌋ = ⌊4086/23⌋ = 177 keys aate, agar next pointer 10 B maane.)

Worked example 2 · teeno ek hi parameters par

B = 1024, K = 10, P = 8, Pr = 8, Pn = 8.

  • B+ internal: m = ⌊(1024 + 10)/(8 + 10)⌋ = ⌊1034/18⌋ = ⌊57.4⌋ = 57. (57×8 + 56×10 = 456 + 560 = 1016 ✔; m = 58 → 464 + 570 = 1034 > 1024 ✘)
  • B+ leaf: L = ⌊(1024 − 8)/(10 + 8)⌋ = ⌊1016/18⌋ = ⌊56.4⌋ = 56. (56 × 18 + 8 = 1016 ✔)
  • B-tree node: m = ⌊(1024 + 10 + 8)/(8 + 10 + 8)⌋ = ⌊1042/26⌋ = 40. (40×8 + 39×18 = 320 + 702 = 1022 ✔; 41 → 328 + 720 = 1048 ✘)

Dekho: B-tree me fan-out 40, B+ me 57 — isliye B+ tree ki height kam ya barabar.

Ab tum try karo

B = 512, K = 8, P = 6, Pr = 6, Pn = 6. B+ internal m aur leaf L?

Answer: m = ⌊(512 + 8)/(6 + 8)⌋ = ⌊520/14⌋ = 37 (37×6 + 36×8 = 510 ≤ 512). L = ⌊(512 − 6)/14⌋ = ⌊36.1⌋ = 36.

15.5 · Height, levels aur capacity kitni keys, kitne levels?

Levels ki ginti: root = level 1, leaf = last level h. (Kuch kitaabein "height" me root ko 0 maanti hain — question me dekho.) Tree balanced hai isliye search cost = h node-reads; B+ me record fetch karne ko +1 data block.

Maximum keys (sab nodes full)

Treeh levels me max keysKyun
B+ tree (internal max m children, leaf max L keys)L × mh−1Root se neeche har level par ×m nodes → mh−1 leaves, har me L keys. (Internal nodes ki keys sirf copies.)
B-tree (max m children)mh − 1Level i par mi−1 nodes × (m−1) keys: (m−1)(1 + m + … + mh−1) = mh − 1.

Minimum keys (sab nodes bas aadhe bhare)

Shortcut approximations
  • Typical fill ≈ 69% (ln 2); isliye real fan-out ≈ 0.69 × m.
  • Levels (min) = ⌈logm(N / L)⌉ + 1 (sab full maan kar).
  • Levels (max) ≈ ⌊log⌈m/2⌉(N / (2⌈L/2⌉))⌋ + 2 (sab half full).

Counting problems (nodes / leaves)

  • Min leaves (sab full): ⌈1000/3⌉ = 334.
  • Max leaves (sab half full): 1000/2 = 500.

  • Min: t = ⌈5/2⌉ = 3; 2 × 3² − 1 = 17 (root 1 + 2 nodes × 2 + 6 leaves × 2 = 1 + 4 + 12 ✔).

15.6 · Search aur range query leaf links ka jaadoo

Point search (key = x): root se shuru. Har internal node me keys dekho: x kis do keys ke beech me hai → us child pointer par jaao. Leaf tak pahuncho, leaf me key dhoondo. Cost = h reads (+1 data).

Range query (a ≤ key ≤ b): (1) point-search se a wale leaf tak pahuncho. (2) Us leaf ki keys padho; next-leaf pointer follow karte hue aage ke leaves padho jab tak key > b na ho jaaye. Root par dobara wapas nahi jaana!

Cost = (h reads to first leaf) + (aur kitne leaves padhe). B-tree me ye asaan nahi (in-order traversal par upar-neeche jaana padta hai) — isliye B+ range queries ke liye best hai.

15.7 · Insertion — split step by step B+ tree

Analogy: ek dabbe (leaf) me jagah khatam ho gayi aur naya saaman aaya → dabba do dabbon me baant do, aur "kaunsa saaman kis dabbe me" ki parchi (separator key) upar wale register (parent) me chipka do. Agar register bhi full ho gaya to wo bhi baanto — ye upar tak chain reaction ho sakta hai. Root bhi split ho to ek naya root banta hai aur tree ek level upar se bada hota hai (isliye leaves hamesha barabar depth par rehte hain).

  1. Sahi leaf dhoondo (search ki tarah).
  2. Leaf me jagah hai to sorted jagah par daal do. Khatam.
  3. Jagah nahi (overflow = max + 1 keys) → leaf ko do hisson me split: left ko ⌈(max+1)/2⌉ keys, baaki right ko.
  4. B+ tree me separator = right leaf ki sabse chhoti key ka COPY — ye parent me jaata hai, aur leaf me bhi rehta hai (copy-up). (B-tree me middle key sachmuch upar chali jaati hai — push-up.)
  5. Parent bhi overflow ho gaya (max keys + 1)? Parent ko split: beech wali key upar MOVE hoti hai (internal split me copy nahi, move!). Isi tarah upar tak.
  6. Root split hua → naya root (1 key, 2 children). Height +1.
Do separator conventions — dhyan se

(a) Standard (Silberschatz, hum yahi demos me use karte hain): separator = right leaf ki smallest key. Search: key < sep → left, key ≥ sep → right.

(b) "Max of left" convention (GATE DA 2026 Q41 ka figure): separator = left leaf ki largest key. Search: key ≤ sep → left, key > sep → right. Dono sahi hain; question ka figure dekho — Q41 me root [5, 8] ke left leaf me 5 hai, matlab (b). Final answer (root me kitni/kaunsi keys) aksar dono me alag ho sakta hai, isliye figure ke hisaab se chalo.

Ab tum try karo

Demo 3 ke final tree me key 12 insert karo. Kya hoga?

Answer: 12 < 15 → leaf [5,10] → [5,10,12] (3 keys, max 3) — bas daal diya, split nahi.

Insertion ke traps
  • Leaf split → copy-up (key leaf me bhi rehti hai). Internal split → move-up. B-tree me hamesha move-up.
  • Even-size overflow me (jaise 4 keys) kaun si beech wali key jaaye — "left-heavy" ya "right-heavy" — question batata hai; ye lesson me hum left ko ⌈ ⌉ dete hain (Elmasri).
  • Split ke baad bhi min-occupancy pass honi chahiye: leaf max 2 → 1 + 2 splits theek; (max 2 ke saath 3 keys → 2 | 1 ya 1 | 2).
  • Root me min keys 1 (2 children) — root half-full nahi hona chahiye.
  • Sequential (ascending) inserts me B+ tree ke left leaves min-full reh jaate hain (jaise Demo 1) — real systems isme "right-biased split" use karte hain.

15.8 · PYQ · GATE DA 2026 · Q41 MCQ · B+ insertion

Question: B+ tree me leaf me max 2 keys aur non-leaf me max 3 pointers. Content figure jaisa (niche). Key 3 insert karne ke baad root me kaun si key(s) hongi?  (A) 5  (B) 8  (C) 3 and 5  (D) 3, 5 and 8

Given tree (separator = left leaf ki max key: key ≤ 5 left, 5 < key ≤ 8 middle, > 8 right)
Leaf [1,5] ko 5 hai, isliye root ka 5 "max of left" hai — Convention (b).
  1. 3 ≤ 5 → leftmost leaf [1,5]. Sorted: [1,3,5] → 3 keys > max 2 → overflow.
  2. Split (left ko ⌈3/2⌉ = 2): [1,3] | [5]. Is figure ki convention me separator = left ki largest key = 3. Root me 3 aata hai: [3, 5, 8] — 3 keys, 4 pointers, par max 3 pointers → root overflow.
  3. Root ko split: beech wali key 5 upar move. Left internal [3] (children [1,3], [5]), right internal [8] (children [7,8], [9,12]). Naya root = [5].
Step 2 · leaf split, root overflow
Root [3,5,8]: 4 pointers > 3 → overflow.
Step 3 · root split → final
Root = [5]. Height 2 → 3.
Official answer
(A) 5.
Galat options kyun: insert ke baad 4 leaves hain ([1,3], [5], [7,8], [9,12]). Root me max 3 pointers → root 4 leaves ko seedha point nahi kar sakta, to root ke neeche ek aur internal level aana hi hai aur root ke 2 hi children (1 key) honge. Isliye (C) 3 and 5 aur (D) 3, 5 and 8 (2-3 keys wale root) impossible. Bacha (A) 5 ya (B) 8: root = 8 hone par left child ko 3 leaves aur right child ko sirf 1 leaf milta — right internal node me 1 hi child → min 2 children ki shart tooti. Sirf root = 5 (2 + 2 leaves) valid.
Trick

Root overflow tab hota hai jab uski keys = (max pointers) → yahan 3 pointers max → 2 keys max. Naye separator se 3 keys ho gayi → beech wali (2nd) key upar. Keys sorted: 3, 5, 8 → beech = 5.

15.9 · Deletion — borrow aur merge jab node chhota ho jaaye

Delete me problem tab aati hai jab node minimum se kam ho jaaye (underflow). Ye fix karne ke do tareeke: pehle borrow, na ho sake to merge.

  1. Key wale leaf me jaao, key hatao.
  2. Leaf abhi bhi ≥ min keys? Khatam. (Internal node me jo copy-key hai wo wahin rehti hai — wo ab bhi valid separator hai!)
  3. Underflow → apne sibling (left/right, same parent) ko dekho. Agar sibling ke paas min se zyada keys hain → borrow (redistribute): sibling se ek key lo, parent ka separator update karo.
  4. Sibling bhi min par hai → merge: dono nodes ko ek karo, parent se un dono ko alag karne wala separator + pointer hata do.
  5. Parent ka bhi underflow ho sakta hai → wahi borrow / merge, upar tak. Root ke 1 hi child bache to root hata do, height −1.

Deletion demo · Demo 1 ke final B+ tree par (min: leaf 1 key, internal 2 children)

Start
Root [50]; [30] → leaves [10,20],[30,40]; [70] → leaves [50,60],[70].
Delete 20 → koi dikkat nahi
Leaf [10,20] → [10]: 1 key = min ✔. Koi change nahi.
Delete 70 → BORROW
Leaf [70] khaali (underflow). Left sibling [50,60] ke paas 2 keys > min → 60 le lo → [50] | [60]; parent separator 70 → 60.
Delete 60 → merge, parent underflow
Leaf [60] khaali; sibling [50] min par → merge → [50]; separator 60 hata. Parent internal ke 1 hi child → underflow.
Parent bhi merge → height −1
Parent ka sibling [30] (2 children = min) bhi nahi de sakta → merge, root se 50 neeche aati hai: [30,50] with 3 children. Root khaali → hata. Height 3 → 2.
Deletion traps
  • Key delete karne par internal node ki wahi key zaroori nahi ki hat jaaye (B+ tree me copy hai). Fir bhi tree valid rehta hai.
  • Pehle borrow try karo, tab merge. (Kuch kitaabein pehle merge bhi allow karti hain; question ke rule dekho.)
  • Merge ka matlab parent ka separator neeche aata hai (internal merge) ya hat jaata hai (leaf merge, B+ me).
  • Root ko min-occupancy se chhoot, par root ke 1 child bacha to root hat jaata hai.

B-tree me deletion (thoda alag)

  • Key leaf me hai: seedha hatao, underflow ho to borrow/merge.
  • Key internal node me hai: usse apne predecessor (left subtree ki sabse badi key) ya successor (right subtree ki sabse chhoti) se replace karo; phir wo predecessor/successor leaf se delete karo (aur underflow fix karo).
  • Borrow B-tree me rotation hota hai: sibling ki key parent me jaati hai aur parent ki key neeche aati hai.
Delete 40 (root) · predecessor 30 se replace
40 → 30. Leaf [30] se 30 hatao → khaali. Sibling [10] min par → merge [10,20]; parent [20] ka 1 child → underflow.
Final (merge cascade)
Parent ka sibling [60] bhi min → root se 30 neeche aakar merge [30,60]. Root khaali → hata. Height 3 → 2.

15.11 · Practice 14 questions

Q1. B = 512, K = 8, P = 6, Pr = 6, Pn = 6. B+ internal ka max pointers m aur leaf ki max keys L?
✔ m = 37, L = 36
m = ⌊(512 + 8)/(6 + 8)⌋ = ⌊520/14⌋ = 37 (37×6 + 36×8 = 510 ≤ 512; m = 38 → 524). L = ⌊(512 − 6)/(8 + 6)⌋ = ⌊506/14⌋ = 36.
Q2. B-tree node: B = 1024, K = 12, P = 8, Pr (data ptr) = 8. Max m?
✔ 37
37×8 + 36×(12 + 8) = 296 + 720 = 1016 ≤ 1024; m = 38 → 304 + 740 = 1044 > 1024. Formula: ⌊(1024 + 12 + 8)/(8 + 12 + 8)⌋ = ⌊1044/28⌋ = 37.
Q3. Order m = 5 (max 4 keys). Non-root node me min keys aur min children? Root me?
✔ Non-root: 2 keys, 3 children. Root: 1 key, 2 children
⌈5/2⌉ = 3 children → 2 keys.
Q4. Full B+ tree, m = 4, L = 3, 3 levels: keys? Min keys?
✔ Max 48, min 8
3 × 4² = 48. Min: 2 × ⌈4/2⌉1 × ⌈3/2⌉ = 2 × 2 × 2 = 8.
Q5. Full B-tree m = 5, height 3 (levels): kul keys?
✔ 124
5³ − 1 = 124. Min (t = 3): 2 × 3² − 1 = 17.
Q6. B-tree (max 2 keys/node) me keys 1, 2, 3, 4, 5, 6, 7 order me insert. Final root aur nodes?
✔ Root [4]; 7 nodes; 3 levels
Steps: [1,2] → 3 aane par 2 upar; 5 par 4 upar (root [2,4]); 7 par 6 upar → [2,4,6] overflow → 4 upar. Root [4]; [2]→[1],[3]; [6]→[5],[7].
Q7. B+ tree (leaf max 2 keys, internal max 3 pointers, copy-up smallest-of-right) me 1…7 insert. Root?
✔ Root [5]; leaves [1,2] [3,4] [5,6] [7]
3 par split: root [3]; 5 par: root [3,5]; 7 par: root [3,5,7] overflow → 5 upar. Left [3]: [1,2],[3,4]; right [7]: [5,6],[7].
Q8. GATE 2026 Q41 wali tree (figure convention) me 6 insert karo (3 ki jagah). Root?
✔ Root = [7]
5 < 6 ≤ 8 → middle leaf [7,8] → [6,7,8] overflow → [6,7] | [8]; separator (left ki max) = 7 → root [5,7,8] 4 pointers → overflow → beech 7 upar. Root [7]; left [5] → [1,5],[6,7]; right [8] → [8],[9,12].
Q9. B+ tree 3 levels, leaves me record pointers. Ek key search (record tak) me block accesses?
✔ 4
3 node reads + 1 data block = 4.
Q10. B+ tree order 4 (L = 3), 1000 keys: min aur max leaf nodes?
✔ Min 334, max 500
Min: ⌈1000/3⌉ = 334. Max: har leaf ≥ ⌈3/2⌉ = 2 keys → 1000/2 = 500.
Q11. B+ tree me key 30 delete karne ke baad kya 30 internal node se bhi hat jaati hai?
✔ Zaroori nahi
Internal me sirf separator copy hai; tree valid rehta hai. Hataana tabhi padta hai jab merge/redistribute me separator badalna ho.
Q12. Same block size par B-tree aur B+ tree me kiski height kam hoti hai (generally) aur kyun?
✔ B+ tree
Internal node me record pointers nahi → zyada keys/pointers → bada fan-out.
Q13. Range query "salary BETWEEN 40000 AND 60000" B+ tree par kaise hota hai? Cost?
✔ Leaf of 40000 tak jaao, linked leaves padho
h reads + (extra matching leaves). Root par wapas nahi jaate.
Q14. m = 195 (internal max pointers) B+ tree: ek internal node me max keys, aur 2 levels (root + leaves, leaf L = 177) me max keys?
✔ 194 keys; 195 × 177 = 34,515
Max keys = L × mh−1 = 177 × 195 = 34,515 (195 × 177 = 195×100 + 195×77 = 19,500 + 15,015 = 34,515).

15.12 · Lesson 15 cheat box

Formulas
  • Order m = max children (Conv. 1): max keys m − 1; min children ⌈m/2⌉.
  • B+ internal: m = ⌊(B + K)/(P + K)⌋
  • B+ leaf: L = ⌊(B − Pn)/(K + Pr)⌋
  • B-tree: m = ⌊(B + K + Pr)/(P + K + Pr)⌋
  • B+ max keys: L·mh−1; min: 2⌈m/2⌉h−2⌈L/2⌉
  • B-tree max keys: mh − 1; min: 2th−1 − 1, t = ⌈m/2⌉
  • Search cost B+: h (+1 data block)
  • Range: h + (extra leaves)
Traps
  • Pehle order ki definition.
  • Leaf split = copy-up; internal split = move-up; B-tree always move-up.
  • Pointers = keys + 1.
  • Sirf root half-full rule se bahar.
  • Capacity (m) = floor.
  • Deletion: pehle borrow, phir merge; B+ internal copy-key bachi reh sakti hai.
  • Separator convention: < vs ≤ — figure dekho (2026 Q41 = max-of-left).
  • Q32 jaisi: non-leaf me record pointer nahi.
