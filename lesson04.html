Relational Model — relation, tuple, attribute, domain, schema
Table jaisi dikhne wali cheez ka sahi mathematical naam, aur uske rules. Degree, cardinality, instance, schema — sab saaf.

4.1 · Relational model hai kya? pehle picture, phir naam

Socho tumhare paas ek register hai jisme school ke students ki details likhi hain: har line mein ek student, aur har column mein ek cheez (roll number, naam, age). Ye hi relational model ka dil hai. 1970 mein E. F. Codd ne kaha: “data ko seedhe-saadhe tables mein rakho, aur un par maths (set theory + logic) chalao.” Aaj ke saare popular databases (MySQL, PostgreSQL, Oracle, SQL Server) isi idea par bane hain.

Ek hi picture mein saare naam: relation, attribute, tuple, schema, instance, domain, degree, cardinality.

Relation = TABLE  ·  Tuple = ROW  ·  Attribute = COLUMN. Design = schema, current rows = instance. Columns ginti = degree, rows ginti = cardinality.

4.2 · Domain aur atomic value har column ki “laxman rekha”

Domain = us attribute ki saari allowed values ka set. Jaise bus ki seat number 1 se 40 tak hi hota hai — 0 ya “hello” seat number nahi ho sakta.

Atomic ka matlab

Relational model mein har cell mein sirf ek single (indivisible) value hoti hai — ek cell mein list {9876, 9123} nahi chalegi. Isi ko First Normal Form (1NF) ki shart kahte hain (Lesson 11 mein detail). ER model ke multivalued attribute ko relational model mein alag table banakar rakhte hain.

NULL kya hai?

NULL = “value pata nahi / hai hi nahi / lagu nahi”. NULL 0 nahi hai aur khali string bhi nahi. Har domain mein ek extra special value NULL maani ja sakti hai (jab tak NOT NULL na lage). NULL ke saath comparison ka result unknown aata hai (Lesson 8-9 mein detail).

Trap

“NULL = NULL” SQL mein true nahi, unknown hota hai. Isiliye NULL se kisi row ko “match” nahi karte (join aur foreign key mein bhi).

4.3 · Relation ko maths ki nazar se GATE kabhi-kabhi yahan se poochta hai

Formal definition: attributes A1, A2, …, An ke domains D1, D2, …, Dn hon, to relation r ek subset hai:

r ⊆ D1 × D2 × … × Dn
Notation / matlab (pehle ye letters samjho)
  • A1, …, An = relation ke columns (attributes). Example: STUDENT(RollNo, Name, Age) mein n = 3.
  • Di = i-th attribute ka domain, yaani us column mein aa sakne wali saari values ka set. Example: DAge = {0,1,…,120}.
  • |Di| = us set mein kitni values hain. DAge ke liye 121.
  • D1 × D2 = cross product: D1 ki har value ko D2 ki har value ke saath jodkar saare pairs. {1,2} × {x,y} = {(1,x), (1,y), (2,x), (2,y)}.
  • r ⊆ X = “r, X ka subset hai” (r ke saare tuples X mein bhi hain; r khali ya poora X bhi ho sakta hai).
  • r = table ke abhi ke rows (instance); R = table ka schema (naam + columns).

Yaani relation = possible tuples ke bade set ka ek hissa. Jaise duniya ke sab (RollNo, Age) joda banana possible hain, par table mein sirf wo hain jo asal mein true hain.

Kaise bani? Upar ki table ke har number ki ginti (|DA| = 3, |DB| = 2)
  1. Possible tuples = 6: ek tuple banane ke liye A ki value chuno (3 tareeke) aur har ek ke saath B ki value chuno (2 tareeke) → 3 × 2 = 6. Upar ki table mein yahi 6 pairs likhe hain.
  2. Instances = 26 = 64: in 6 possible tuples mein se har ek ke liye bas ek sawaal: “table mein hai ya nahi?” (2 jawab). 6 independent haan/naa choices → 2 × 2 × 2 × 2 × 2 × 2 = 64. (Isme khali table aur poori 6-row table dono shamil hain.)
  3. Exactly k = 2 tuples wale instances = C(6,2) = 15: C(N,k) ka matlab “N cheezon mein se k chunne ke tareeke” = N! / (k! × (N−k)!). Yahan 6!/(2!×4!) = (6×5)/(2×1) = 15.
  4. Max cardinality jab A key ho = 3: key ka matlab do tuples ki A value same nahi. A ki 3 values hain, har value se zyada se zyada 1 tuple → 3.
  5. Check: sab k ke C(6,k) ka jod = 1+6+15+20+15+6+1 = 64 = 26 ✓.
Last formula kyun? (A key wala)

Har A value (1, 2, 3) ke liye 3 choices hain: ya to table mein hai hi nahi, ya (A, x) ke saath hai, ya (A, y) ke saath. Teen A values → 3 × 3 × 3 = 27. Ek A ke saath do B nahi aa sakte kyunki A key hai (do tuples same A nahi rakh sakte).

Ab tum try karo

R(A,B,C) ke domain sizes 2, 3, 2 hain. (a) possible tuples? (b) possible instances?

Ans: (a) 2×3×2 = 12. (b) 212 = 4096.

4.4 · Schema vs Instance blueprint vs furniture

Kya haiRelation ka naam, attributes, domains, constraintsUs pal ke tuples ka set

Database schema = saari relations ke schemas + unke beech ke constraints (jaise foreign keys). Database state/instance = saari tables ke rows ek saath.

Valid state kise kahte hain?

Wo instance jo schema ke saare constraints (domain, key, NOT NULL, foreign key, CHECK) satisfy kare. Koi INSERT/UPDATE/DELETE jo state ko invalid bana de, DBMS use reject kar deta hai — yahi Lesson 5 ka integrity constraints topic hai.

Trap: “key” schema ki property hai, instance ki nahi

Agar kisi instance mein Name ki saari values alag dikhein, to bhi Name key nahi ban jaata. Key ka matlab hai “har possible valid instance mein unique”. Ye schema-level declaration hai (Lesson 5 mein detail).

4.5 · Degree aur Cardinality ER wale words se alag!

Relation ki degree

Degree = attributes (columns) ki sankhya. STUDENT(RollNo, Name, Age) → degree = 3. Rows add karne se degree nahi badalti.

Relation ki cardinality

Cardinality = tuples (rows) ki sankhya. Agar 50 students hain to cardinality = 50. Naya student add → 51.

ER model mein same shabd, alag matlab

ER model mein “degree of relationship” = kitne entity types juDe hain (binary = 2, ternary = 3). “Cardinality ratio” = 1:1, 1:N, M:N. Relational model mein degree = columns aur cardinality = rows. Sawaal ka context padho: ER ki baat ho rahi hai ya table ki.

Kaun-sa operation kya badalta hai?

OperationDegreeCardinalitySchema badla?

DELETE k rowssame−kNahi
UPDATE kisi cell kosamesameNahi
ALTER TABLE ADD COLUMN+1sameHaan
ALTER TABLE DROP COLUMN−1same (SQL table mein)Haan

Relational algebra ke baad degree / cardinality

(Detail Lesson 6 mein; yahan bas jhalak.) |R|, |S| = cardinalities (rows ki ginti); deg(R), deg(S) = degrees (columns ki ginti). Symbols ka matlab: σc = condition c par rows chhanno (selection); πX = sirf columns X rakho (projection); R × S = R ki har row ko S ki har row se jodo (cross product); ∪ union (dono mein se koi bhi row); ∩ intersection (jo dono mein ho); − difference (R mein ho par S mein nahi). ∪, ∩, − ke liye R aur S ke columns same hone chahiye.

R − Sdeg(R)max(0, |R|−|S|) … |R|
Kaise bani? Ek chhota example se table ka har range dekho

R(A,B) = {(1,x), (2,x), (3,y)} → |R| = 3, deg = 2. S(A,B) = {(2,x), (4,z)} → |S| = 2.

  1. σB='x'(R): rows jinme B = x → (1,x), (2,x) = 2 rows (0 se 3 ke andar), degree 2 hi rahi.
  2. πB(R): sirf B column = x, x, y; duplicates hataye → {x, y} = 2 rows (3 se kam), degree = |{B}| = 1.
  3. R × S: 3 × 2 = 6 rows, degree 2 + 2 = 4.
  4. R ∪ S: R ki 3 rows + S ki 2 rows = 5, par (2,x) dono mein hai, ek hi baar → 4 rows (max(3,2) = 3 se 3+2 = 5 ke andar ✓).
  5. R ∩ S: sirf (2,x) → 1 row (0 se min(3,2) = 2 ke andar ✓).
  6. R − S: R se (2,x) hatao → (1,x), (3,y) = 2 rows (max(0, 3−2) = 1 se 3 ke andar ✓).
Ab tum try karo

R(A,B,C) mein 5 tuples, S(D,E) mein 4 tuples. R × S ki degree aur cardinality?

Ans: Degree = 3 + 2 = 5; cardinality = 5 × 4 = 20.

Note: attribute order

Rows ka order kabhi matter nahi karta (relation set hai). Columns ka order: agar tuple ko ordered n-tuple (D1×…×Dn wali definition) maanein to order matter karta hai; agar attribute ko naam se pehchanein (SQL/named view) to nahi. GATE option mein sirf “tuples ka order” ho to answer: matter nahi karta. Sawaal ka apna rule sabse upar.

4.9 · Practice 12 questions — pehle khud, phir answer

Q1. R(A,B,C,D) mein 40 rows hain. Degree aur cardinality? Phir ek naya column add karo aur 2 rows insert karo.
✔ Shuru mein: degree 4, cardinality 40. Baad mein: degree 5, cardinality 42.
ADD COLUMN degree badhata hai (+1), INSERT cardinality (+2).
Q2. R(A,B,C) ke domain sizes 4, 5, 2. Maximum possible tuples? Kul possible instances?
✔ 40 tuples; 240 instances
Product of domain sizes; har tuple ya hai ya nahi.
Q3. Upar wali R mein A key hai. Max cardinality? Instances ki sankhya?
✔ Max cardinality = 4. Instances = (1 + 5×2)4 = 114 = 14641.
Har A value ke liye: absent ya 10 (B,C) pairs mein se ek.
Q4. R(A,B), dom(A) = dom(B) = {0,1}. Exactly 3 tuples wale kitne instances? Kul instances?
✔ 4 aur 16
Possible tuples 4: C(4,3) = 4; total 24 = 16.
Q5. True/False: Relation mein do identical tuples ho sakte hain.
✔ False
Relation set hota hai. (SQL table mein ho sakte hain.)
Q6. STUDENT mein 4 rows, Dept values CSE, CSE, ECE, ME. SQL SELECT Dept FROM STUDENT aur algebra πDept(STUDENT) ke row counts?
✔ SQL: 4, Algebra: 3
SQL bag; algebra set.
Q7. Kaunsa schema hai, kaunsa instance? (i) EMP(ID, Name, Sal) (ii) {(1, Ravi, 5000), (2, Asha, 7000)}
✔ (i) schema, (ii) instance
Design vs current rows.
Q8. R(A,B,C) mein 100 tuples aur A key hai. πA,B(R) ki cardinality?
✔ Exactly 100
A key hai, isliye (A,B) ke pairs bhi alag-alag; duplicates nahi hatenge.
Q9. R(A,B,C) 6 tuples, S(C,D) 3 tuples. R × S ki degree aur cardinality?
✔ Degree 5, cardinality 18
Product mein common naam wale columns alag rehte hain (rename ke saath); degree 3+2.
Q10. Age ka domain 0–120. Insert (105, “Ravi”, −5). Kaunsa constraint toota?
✔ Domain constraint
Value domain ke bahar hai.
Q11. R(A,B) mein 5 tuples, S(A,B) mein 3 tuples (same schema). R ∪ S, R ∩ S aur R − S ki cardinality ka minimum aur maximum?
✔ R ∪ S: 5 se 8. R ∩ S: 0 se 3. R − S: 2 se 5.
Union: kam se kam max(5,3) (S ⊆ R ho to), zyada se zyada 5+3 (koi common nahi). Difference: kam se kam 5−3 = 2 (S ke teeno R mein hon), zyada se zyada 5.
Q12. STUDENT(RollNo, Name) mein RollNo PRIMARY KEY hai. INSERT (NULL, 'Ravi') chalega?
✔ Nahi, reject (entity integrity: PK mein NULL nahi).
NULL ka matlab “value pata nahi”; PK ko row pehchanni hoti hai, isliye NULL allowed nahi (Lesson 5).

4.10 · Lesson 4 cheat box

Yaad rakho
  • Relation=table, tuple=row, attribute=column.
  • Degree=#columns; cardinality=#rows.
  • Relation = set → no duplicates, no row order.
  • Schema = design, instance = current rows.
  • r ⊆ D1×…×Dn.
  • Possible tuples = ∏|Di|; instances = 2that.
  • A key hai: max rows = |dom(A)|; instances = (1+∏others)|dom A|.
Traps
  • Sample rows se key ya domain prove nahi hota.
  • ER ka degree/cardinality ≠ table ka degree/cardinality.
  • SQL duplicates allow karta hai, relation nahi.
  • NULL ≠ 0 ≠ “”.
  • ADD COLUMN schema badalta hai; INSERT sirf instance.
