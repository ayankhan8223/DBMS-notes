7.1 · Big idea — recipe nahi, order bolo RA vs TRC

Restaurant analogy 🍽️

Relational Algebra = recipe: “pehle pyaaz kaato, phir tel mein daalo, phir…”. Aap kaise banana hai wo steps batate ho (σ, π, ⋈ ek ke baad ek).

Tuple Relational Calculus = menu se order: “mujhe aisi dish do jo paneer wali ho aur teekhi ho.” Aap sirf bolte ho kaisi chahiye — kaise banegi, kitchen sochega.

7.2 · Formula kaise banta hai atoms + connectives + quantifiers

TRC formula Lego jaisa hai: chhote tukde (atoms) ko connectives se jodo, aur beech mein quantifier (∃/∀) laga do.

Atom type 1: range

R(t) ya t ∈ R
“t relation R ki ek row hai.”

Eg: STUDENT(s), e ∈ ENROLL

Atom type 2: var vs var

s.A θ t.B
do variables ke attributes ki tulna. θ ∈ {=, ≠, <, ≤, >, ≥}

Eg: e.ID = s.ID (ye join ka kaam karta hai!)

Atom type 3: var vs constant

s.A θ c
attribute ko ek fixed value se tulna.

Eg: s.Dept = 'CSE'

Formula banane ke rules

  1. Har atom ek formula hai.
  2. P, Q formulas hain to P ∧ Q, P ∨ Q, ¬P, P ⇒ Q bhi formulas hain.
  3. P(t) formula hai to ∃t ∈ R (P(t)) aur ∀t ∈ R (P(t)) bhi formulas hain.
  4. Brackets se grouping. Precedence: ¬ > ∧ > ∨ > ⇒. Shaque ho to bracket lagao!

Implication P ⇒ Q ka matlab

“Agar P true hai to Q bhi true hona chahiye.” Sirf ek hi halat mein false hota hai: P true aur Q false. Isliye:

P ⇒ Q  ≡  ¬P ∨ Q
PQP ⇒ Q
TTT
TFF
FTT
FFT
Trap: “P galat ho to implication apne aap true”

Jab P false hai, P ⇒ Q true ho jaata hai (vacuously). Isi liye ∀ ke saath ⇒ aata hai, aur ∃ ke saath ∧ — ulta karoge to formula pagal ho jaayega (7.4 mein dekho).

7.3 · Free aur Bound variables kaun “bahar se aaya”, kaun “andar ka loop”

Programming analogy

for i in range(n):      # i = bound (loop ke andar)
    total += x[i]       # x, total = free (bahar se aaye)
  • Bound variable = jise ∃ ya ∀ ne “pakad” liya (quantifier ke scope mein). Wo loop variable jaisa hai: kisi ek specific row ka matlab nahi, “koi bhi/har row”.
  • Free variable = jise kisi ne pakda nahi. Uski value bahar se aati hai — query mein ye output variable t hai.
Golden rule

{t | P(t)} mein t hi akela free variable hona chahiye P mein. Baaki saare variables bound (∃/∀ ke andar). Agar koi aur variable free reh gaya to query ka matlab hi nahi banta.

Bound variable ka naam kuch bhi rakho

∃e ∈ ENROLL (e.ID = t.ID) aur ∃x ∈ ENROLL (x.ID = t.ID) same hain (jaise Σi aur Σj). Par t ka naam badla to answer ka naam badla.

Classify karo: {t | STUDENT(t) ∧ ∃e ∈ ENROLL (e.ID = t.ID ∧ e.CID = 'C1')}

VariableKahan aayaFree ya Bound?Kyun
t{t | …} aur STUDENT(t), e.ID = t.IDFREEkoi quantifier nahi pakadta; ye output tuple hai
e∃e ∈ ENROLL ( … )BOUND∃ ne pakda; scope = bracket ke andar. “koi ek enrollment e”

Thoda tricky: ek formula mein dono roop

STUDENT(s) ∧ ∃s ∈ ENROLL(…) ❌ — “s” ek jagah free, ek jagah bound. Aisa mix mat banao; har variable ka alag naam rakho (s, e, c, e1, e2…).

7.4 · ∃ aur ∀ — “koi ek” aur “har ek” quantifiers

∃ “there exists” = KAM-SE-KAM EK

∃e ∈ ENROLL (P(e)) true hai agar ENROLL ki koi bhi ek row P satisfy kare.

Python: any(P(e) for e in ENROLL)
Logic: P(e1) ∨ P(e2) ∨ … (sab ka OR)

∀ “for all” = HAR EK

∀c ∈ COURSE (P(c)) true hai agar COURSE ki har ek row P satisfy kare.

Python: all(P(c) for c in COURSE)
Logic: P(c1) ∧ P(c2) ∧ … (sab ka AND)

Example par check: kya Rahul (ID=1) ne C2 liya?

∃e ∈ ENROLL (e.ID = 1 ∧ e.CID = 'C2') — ENROLL ki har row ko dekho:

ee.ID = 1 ?e.CID = C2 ?dono (∧)

Ek row mein dono true → ∃ true. (Ek bhi row mil jaaye to baaki dekhna zaroori nahi.)

Empty set ka rule (GATE ka chhupa trap)

Agar range khali ho…ResultKyun
∃x ∈ ∅ (…)FALSEkoi row hai hi nahi jo satisfy kare
∀x ∈ ∅ (…)TRUEkoi row “fail” karne wali hai hi nahi — vacuously true

Negation ke niyam (De Morgan for quantifiers)

¬ ∃x P(x)≡∀x ¬P(x)¬ ∀x P(x)≡∃x ¬P(x)
  • “Koi nahi hai jo P kare” = “sab P nahi karte”.
  • “Sab P nahi karte (ye galat hai)” = “koi na koi hai jo P nahi karta”.
∀ ko ¬∃¬ mein badalna (3 steps)
  1. Likho: ∀x ∈ R (P(x))
  2. Double negation: ¬¬∀x P(x)
  3. Andar ghusao: ¬ ∃x ∈ R (¬P(x))

Padho: “aisa koi x nahi hai jo P fail kare.”

Sabse zyada kaam aane wala pattern

∀x (P(x) ⇒ Q(x))

≡ ∀x (¬P(x) ∨ Q(x))

≡ ¬∃x (P(x) ∧ ¬Q(x))

“Aisa koi x nahi jo P ho par Q na ho.”

Quantifier ke saath connective ki 2 classic galtiyan
  • ∀ ke saath ∧ nahi: ∀c ∈ COURSE (c.CID='C1' ∧ taken) kehta hai “har course C1 hai” — jhooth (C2 bhi hai). Sahi: ∀c (c.CID='C1' ⇒ taken).
  • ∃ ke saath ⇒ nahi: ∃c ∈ COURSE (c.CID='C1' ⇒ taken) — C2 jaise koi bhi course jahan antecedent false hai, formula ko trivially true bana deta hai. Sahi: ∃c (c.CID='C1' ∧ taken).

Yaad: ∃ → ∧   |   ∀ → ⇒

Ab tum try karo

Q. ¬∃c ∈ COURSE (c.Credits > 4) ko ∀ mein likho, aur ye true hai ya false?

Answer: ∀c ∈ COURSE (c.Credits ≤ 4). Credits 4,3,4 → sab ≤ 4 → TRUE.

7.5 · RA ↔ TRC: har operator ka TRC roop translation dictionary

Lesson 6 ke har operator ka TRC mein ek seedha jawab hai. Ye table yaad kar lo — GATE mein yahi aata hai.

RATRCKaise padho

7.6 · 4 patterns: “not”, “both”, “all”, “sabse bada” English → TRC → RA

GATE ke 90% TRC sawaal inhi 4 shapes mein aate hain. Har ek ko recipe se likho:

  1. Output variable chuno (t ya s) aur uski range likho: STUDENT(s).
  2. Seedhi condition ho to bas ∧ se jodo (σ jaisa).
  3. Doosri table ki zarurat ho to ∃ e ∈ ENROLL laao aur link atom likho: e.ID = s.ID (ye join hai).
  4. “nahi” shabd → ¬∃. “har / all” → ∀ ya ¬∃¬.
  5. Check: s ke alawa har variable ∃/∀ ke andar hai? (free-bound rule)
¬∃

7.7 · Safe expressions “answer finite hona chahiye”

Problem kya hai?

Calculus “condition” batata hai, par ye nahi batata ki candidate tuples kahan se laane hain. Agar hum kuch rok-tok na lagayein to candidates = duniya ke saare possible tuples (saare integers, saare strings…) — infinite!

{t | ¬ STUDENT(t)}

“Wo saare tuples jo STUDENT mein nahi hain” — (99, xyz, …), (100, abc, …) … anant. Database ke kisi data se ye answer bana hi nahi sakte. Aisi expression UNSAFE hai.

Safe expression ki definition

Ek TRC expression safe hai agar uska answer hamesha finite ho aur uske har tuple ki har value expression ke “domain” mein se aaye — yaani un values mein se jo formula mein mentioned relations ke andar hain ya constants jo formula mein likhe hain.

(Isi ko “domain independent” bhi kehte hain.)

Safe ya Unsafe? Pehchaan karo

ExpressionSafe?Kyun
{t | STUDENT(t) ∧ t.Age > 20}SAFEt ko positive atom STUDENT(t) ne bandh diya: sirf STUDENT ki rows
{t | ¬ STUDENT(t)}UNSAFEsirf negation: universe ke saare baaki tuples
{t | t.Age > 20}UNSAFEt kisi relation se bandha nahi; Age > 20 ke anant tuples
{t | STUDENT(t) ∨ t.Age > 30}UNSAFE∨ ke doosre hisse mein t free hai, kisi relation se tied nahi → anant answers
{t | STUDENT(t) ∧ ¬∃e ∈ ENROLL (e.ID = t.ID)}SAFEnegation ke saath positive STUDENT(t) bhi hai (¬ sirf “filter” hai)
{t | ∃s ∈ STUDENT (t.Name = s.Name)}SAFEt.Name sirf STUDENT ke Name values mein se hi aa sakta hai
{t | ∀s ∈ STUDENT (s.Age > t.Age)}UNSAFEt unrestricted: har Age < 19 wala t pass → anant
Thumb rule (exam ke liye)
  1. Output variable t ke liye ek positive range atom hai (R(t) / t ∈ R / ∃r ∈ R (t.A = r.A))?
  2. Har ¬ ya ∀ kisi already bandhe variable par laga hai?

Dono “haan” → safe. Nahi → unsafe.

Codd's theorem (bahut important)

Relational Algebra ≡ Safe TRC ≡ Safe DRC (domain calculus). Yaani jo query RA mein likh sakte ho wo safe TRC mein bhi, aur ulta bhi.

Dono se nahi ho sakta: aggregates (COUNT, SUM, AVG) aur recursion/transitive closure (“saare ancestors”). SQL ne ye extra add kiye.

Safe TRC=Relational Algebra=Safe DRC⊂SQL (aggregates, recursion, bag semantics)
TRC vs DRC ek line mein

TRC: variable poori row (tuple) ko represent karta hai (t.Name). DRC (Domain RC): variable ek single value ko represent karta hai: {<n, d> | ∃i, a (STUDENT(i, n, d, a) ∧ a > 20)}. Syllabus mein sirf tuple calculus hai; DRC kam important — bas jaankari ke liye.

TRC aur SQL ka rishta

SQL ke tuple variables = aliases (FROM STUDENT s). SQL ka EXISTS = ∃, NOT EXISTS = ¬∃. “All” ke liye SQL mein ∀ nahi hai, to double NOT EXISTS (¬∃¬) use hota hai.

-- Pattern 1 (not):     SELECT s.Name FROM STUDENT s
--                      WHERE NOT EXISTS (SELECT * FROM ENROLL e WHERE e.ID = s.ID);
-- Pattern 3 (all of C1,C2):  SELECT s.Name FROM STUDENT s WHERE NOT EXISTS (
--     SELECT * FROM COURSE c WHERE c.CID IN ('C1','C2') AND NOT EXISTS (
--         SELECT * FROM ENROLL e WHERE e.ID = s.ID AND e.CID = c.CID));
Ab tum try karo

Solution — step by step

  1. Free/bound: t free (output). z aur m bound (∃). Formula teen ∧-juri hui conditions hai — t tabhi answer mein jab teeno true.
  2. Condition 1: t ∈ X — t ko X ki hi rows mein se lena hai (safe, finite). Candidates = 3 rows.
  3. Condition 2: ∃z ∈ X (t[P] = z[P]) — kya X mein koi z hai jiska P = t ka P? Haan, z = t khud! Isliye ye har t ke liye true hai. (Trick condition — kuch filter nahi karti.)
  4. Condition 3: ∃m ∈ Y (m[P] = t[P] ∧ m[S] > 1) — Y mein koi row jiska P same aur S strictly 1 se bada ho. Row-by-row dekho (niche table).

Is PYQ se seekha
  • Aise sawaal mein har tuple ko ek-ek karke test karo — “candidate table” banao.
  • ∃z ∈ X (t[P] = z[P]) jaisi condition (khud ko match karne wali) hamesha true hoti hai — ye distractor hai.
  • Teesri condition ek semi-join hai: X ⋉ σS>1(Y) on P → RA: X ⋈ πP(σS>1(Y)).

Koi counter-example row nahi, koi witness row nahi.

Lesson 7 cheat box — last-night revision
  • {t | P(t)} = “sab tuples t jinke liye P true”. t = akela free variable; baaki sab ∃/∀ se bound.
  • Atoms: R(t) (range), s.A θ t.B, t.A θ c. Connectives ∧ ∨ ¬ ⇒; P ⇒ Q ≡ ¬P ∨ Q. Precedence ¬ > ∧ > ∨ > ⇒.
  • ∃ = any = OR over rows (khali par false); ∀ = all = AND over rows (khali par true).
  • ¬∃x P ≡ ∀x ¬P  |  ¬∀x P ≡ ∃x ¬P  |  ∀x(P ⇒ Q) ≡ ¬∃x(P ∧ ¬Q). Yaad: ∃ ke saath ∧, ∀ ke saath ⇒.
  • RA ↔ TRC: σ → ∧cond; π/⋈/× → ∃; ∪ → ∨; ∩ → ∧; − → ∧ ¬; ÷ → ∀ (¬∃¬).
  • “not” → ¬∃ (quantifier ke bahar)   “both” → do alag ∃ variables   “all” → ∀⇒∃   “max” → ¬∃ bada.
  • Safe = finite answer; har free var kisi relation se bandha. ¬R(t), t.A > 5 akele → unsafe. Safe TRC ≡ RA (Codd). Aggregates / recursion TRC-RA mein nahi.
  • Strict vs non-strict (> vs ≥), z = t wali self-match conditions, aur empty-set vacuous truth — teen favourite traps.
