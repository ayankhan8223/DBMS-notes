10.2 · FD ki definition aur data se check formal + practical

X → Y   holds in R  ⇔   har do tuples t₁, t₂ ke liye:   t₁[X] = t₂[X]  ⇒  t₁[Y] = t₂[Y]

10.3 · Armstrong ke axioms aur derived rules FD se naye FD banane ke rules

Agar kuch FDs diye hon (set F), to unse kai aur FDs logically nikalte hain. Un sab ka set = F⁺ (closure of F). Naye FD banane ke teen basic rules (Armstrong 1974) hain:

1. Reflexivity

Agar Y ⊆ X to X → Y.

Example: ABC → AB, A → A.

(Trivial FDs yahin se aate hain.)

2. Augmentation

Agar X → Y to XZ → YZ (kisi bhi Z ke liye).

Example: A → B ⇒ AC → BC.

Dono taraf ek hi cheez jodo.

3. Transitivity

Agar X → Y aur Y → Z to X → Z.

Example: A → B, B → C ⇒ A → C.

Chain: A se B, B se C.

Y ⊆ X ⇒ X→YX→Y ⇒ XZ→YZX→Y, Y→Z ⇒ X→Z

Sound = in rules se sirf sahi FDs nikalte hain (galat nahi). Complete = jo bhi FD logically sahi hai (F⁺ mein hai) wo in teen rules se hi nikal sakti hai. Isliye closure algorithm (10.4) kaam karta hai.

Derived rules (teenon se saabit hote hain — GATE mein seedhe use kar sakte ho)

RuleStatementSaabit kaise?
UnionX→Y aur X→Z ⇒ X→YZX→Y ko X se augment: X→XY. X→Z ko Y se augment: XY→YZ. Transitivity: X→XY, XY→YZ ⇒ X→YZ.
DecompositionX→YZ ⇒ X→Y aur X→ZYZ→Y reflexivity se. X→YZ aur YZ→Y ⇒ transitivity se X→Y.
Pseudo-transitivityX→Y aur WY→Z ⇒ WX→ZX→Y ko W se augment: WX→WY. WX→WY aur WY→Z ⇒ WX→Z.

3 jaal jinse log phanste hain (ye rules NAHI hain)
  • RHS toot sakti hai, LHS nahi: X → YZ ⇒ X → Y ✔ (decomposition). Par XY → Z ⇏ X → Z. Jaise (RollNo, Subject) → Marks se RollNo → Marks nahi nikalta.
  • Ulti direction nahi: A → B se B → A nahi nikalta.
  • Alag-alag FDs ko galat jodna: A → B aur C → D se A → D nahi nikalta. Sirf AC → BD nikalta hai (composition).

Worked example: Armstrong se FD derive karna

Given: F = { A → B, B → C, CD → E }. Prove: AD → E.

  1. A → B aur B → C ⇒ A → C  (transitivity)
  2. A → C ko D se augment: AD → CD  (augmentation)
  3. AD → CD aur CD → E (given) ⇒ AD → E  (transitivity)

Ye bahut lamba padh gaya? Isiliye closure (agla section) har baar axioms lagane se behtar hai: (AD)⁺ = {A,D} → A→B: ABD → B→C: ABCD → CD→E: ABCDE ⇒ E ∈ (AD)⁺ ✔. Exam mein hamesha closure use karo; axioms sirf theory-based (“kaunsa rule”) sawaalon ke liye.

Ab tum try karo

Q. Given A → B aur A → C. Kaunsa derived rule ye deta hai: A → BC?

Answer: Union rule. Aur A → BC ⇒ A → B (Decomposition).

10.4 · Attribute closure X⁺ FD ka sabse bada hathiyaar

Idea: snowball

X⁺ = X ke attributes se jo jo attributes pakke nikalte hain, un sabka set (X khud bhi). Socho ek snowball jo ludhakta hua apne saath aur barf (attributes) chipkata jaata hai — jab tak naya chipkane ko kuch na bache.

X = {A}
→A → BC
{A, B, C}
→C → D
{A, B, C, D}
→BD → E
{A, B, C, D, E}

Algorithm

  1. Shuru: closure = X.
  2. Scan: F ki har FD (L → R) dekho. Agar L ke saare attributes closure mein hain, to R ke saare attributes closure mein daal do.
  3. Repeat step 2 jab tak ek poore round mein kuch naya nahi judta.
  4. Stop. Jo bacha wahi X⁺.
closure = X
repeat
    for each FD  L -> R  in F:
        if L is a subset of closure:  closure = closure union R
until closure stops changing

Closure ke 3 use (har sawaal inhi mein se ek hota hai)

1. Superkey test

X⁺ = R (saare attributes) ⇒ X superkey.

2. FD implied?

X → Y ∈ F⁺ ⇔ Y ⊆ X⁺.

3. FD sets ki barabari

F ≡ G ke liye har FD ka LHS closure dusre set mein nikalo (10.7).

Closure ki properties
  • X ⊆ X⁺ (reflexive).
  • X ⊆ Y ⇒ X⁺ ⊆ Y⁺ (monotone).
  • (X⁺)⁺ = X⁺ (idempotent).
  • Khali set ka closure ∅⁺ = {} sivay jab koi FD ∅ → Y ho.

10.5 · Kya ye FD implied hai? closure se 1 line mein jawab

F ⊨ X → Y  ⇔  Y ⊆ X⁺  (X⁺, F ke saath nikala)

Example A

F = { A → B, BC → D, D → E }. Kya AC → E implied hai?

  1. (AC)⁺ shuru: {A, C}.
  2. A → B: A hai ⇒ B judega: {A, B, C}.
  3. BC → D: B, C dono hain ⇒ D: {A, B, C, D}.
  4. D → E ⇒ E: {A, B, C, D, E}.
  5. E ∈ (AC)⁺ ⇒ haan, AC → E implied hai.

Example B (negative)

Wahi F. Kya A → E implied hai?

A⁺ = {A, B} (A → B). BC → D ke liye C chahiye, jo nahi hai. ⇒ A⁺ = {A, B}, E ∉ A⁺ ⇒ nahi.

Example C: “Is FD ko saabit karne ke liye kaun si FD kam hai?”

Aise sawaal mein option ke FD ko F mein jodkar closure dobara nikalte hain, aur dekhte hain konsa option implied banata hai.

Worked example: F = { A → B, BC → D, D → E }. Hume A → E chahiye. Neeche mein se kaun si ek FD F mein jodne se A → E implied ho jaayegi?  (i) A → C  (ii) B → C  (iii) E → A  (iv) D → A

Jodi hui FDA⁺ (F + FD ke saath)E aaya?
(i) A → C{A} → B ⇒ {A,B}; A→C ⇒ {A,B,C}; BC→D ⇒ +D; D→E ⇒ +E = {A,B,C,D,E}✔
(ii) B → C{A} → B ⇒ {A,B}; B→C ⇒ {A,B,C}; BC→D ⇒ +D; D→E ⇒ +E✔
(iii) E → A{A,B} — E→A ke liye E chahiye, BC→D ke liye C chahiye✘
(iv) D → A{A,B} — D kabhi nahi aata✘

Answer: (i) aur (ii). Idea: kami wahi hai jo A⁺ ko C tak le jaaye (BC → D tab chalegi). E → A aur D → A ulti taraf ki FDs hain, A⁺ ko badhati nahi.

Common misconception
  • Closure LHS ka nikalte hain, RHS ka nahi. X → Y check = X⁺ mein Y dhoondo.
  • “Y ke saare attributes X⁺ mein hone chahiye” — ek bhi missing to FD implied nahi.
  • F ke FDs hi F⁺ mein hote hain, par F⁺ mein bahut zyada FDs hote hain (trivial wale bhi).
Ab tum try karo

Q. F = {A→B, C→D}. Kya AC → BD implied hai? Kya A → D?

Answer: (AC)⁺ = {A,B,C,D} ⊇ {B,D} ⇒ haan. A⁺ = {A,B} ∌ D ⇒ A → D nahi.

  1. Attributes ko N, L, R, B teams mein baanto.
  2. Core = N ∪ L (har key mein jo zaroor honge). Core⁺ nikalo.
  3. Agar Core⁺ = R ⇒ Core hi akeli candidate key hai. Khatam — koi doosri key ho hi nahi sakti (kyunki har key ⊇ Core aur Core minimal hai).
  4. Warna B team se attributes core mein jodo: pehle ek-ek, phir do-do, … (chhote size pehle). Jis combination ka closure R ho wo key.
  5. Jis combination mein koi pehle se mili key ka superset ho use skip karo (minimal nahi hoga). R team ke attributes kabhi mat jodo.

Superkeys, keys ki ginti — GATE ke counting questions

Ek hi candidate key K, |K| = k, R mein n attributes

K ke superset = K + baaki (n − k) attributes ka koi bhi subset ⇒ superkeys = 2n−k.

Example: R(A,B,C,D,E), akeli key A ⇒ 2⁴ = 16 superkeys. Key AB hoti to 2³ = 8.

Do ya zyada keys

Inclusion–exclusion ya size-wise ginti. R(A,B,C,D,E), keys A aur BC:
A ke superset = 2⁴ = 16; BC ke superset = 2³ = 8; dono (ABC ke superset) = 2² = 4.
Superkeys = 16 + 8 − 4 = 20.

Size-wise ginti (R(A,B,C,D), keys AB, AD, BC, CD — example 2 wali): size 2: 4 keys. Size 3: ABC ⊇ AB ✔, ABD ⊇ AB ✔, ACD ⊇ AD ✔, BCD ⊇ BC ✔ = 4. Size 4: ABCD = 1. Superkeys = 4 + 4 + 1 = 9.

Ek relation mein kitni zyada se zyada candidate keys? (Sperner)

n = 3 → 3 (A, B, C — cyclic example). n = 4 → 6 (saare 2-attribute pairs). n = 5 → 10.

  • Superkeys mein minimal wali bhi gini jaati hain (keys ⊂ superkeys).
  • Khali set ko key mat maano (sivay jab ∅ → R ho, jo rare hai).
  • “Kitni candidate keys?” = minimal wali. “Kitni superkeys?” = sab jinka closure R.

10.7 · FD sets ki equivalence F ≡ G ?

Do alag-alag likhe FD sets ek hi jaankari de sakte hain. Ise equivalence kehte hain.

F ≡ G  ⇔  F⁺ = G⁺  ⇔  (F covers G)  aur  (G covers F)
  • F covers G ⇔ G ki har FD, F se implied hai (yaani G ⊆ F⁺).
  • Test: G ki har FD X → Y ke liye, F ke saath X⁺ nikalo aur dekho Y ⊆ X⁺. Phir ulta (F ki har FD G ke saath).
  • Agar sirf ek taraf covers ho to equivalent nahi: ek set doosre se zyada majboot hai.

Example 1: F = { A→B, B→C, A→C }, G = { A→B, B→C }

Dekho: G ki FDs F se nikal aati hain, par F ki B → C G se nahi nikalti. G kamzor hai. Isliye “G se F banta hai?” jaise sawaal mein direction dhyaan se.

Traps
  • Sirf ek direction check karke “equivalent” mat bol dena.
  • FD sets ke size alag hone se equivalence nahi tootti (Example 1: 3 FD vs 2 FD, phir bhi ≡).
  • Closure hamesha us set ke saath nikalo jisme check kar rahe ho (F covers G ⇒ F ke saath closure).
Ab tum try karo

Q. F = {A → BC}, G = {A → B, B → C}. Kya F ≡ G?

Answer: G covers F? A⁺(G) = {A,B,C} ∋ B,C ✔. F covers G? A→B ✔ (decomposition), B → C: B⁺(F) = {B} ✘. ⇒ Equivalent nahi (G ⊋ F).

10.8 · Minimal (canonical) cover FD set ko sabse chhota banana

Kyun?

Diya hua F kabhi-kabhi faltu cheezon se bhara hota hai: aisi FD jo doosri FDs se nikal aati ho, ya LHS mein aisa attribute jo zaroori nahi. Minimal cover = wahi jaankari, sabse kam likhawat mein. 3NF synthesis (Lesson 12) isi par chalti hai.

Definition — 3 shartein

#ConditionMatlab
1Har FD ka RHS ek hi attributeX → AB ko X → A, X → B mein tod do
2LHS mein koi extraneous attribute nahiXA → B mein agar A hataane par bhi B nikalta ho (X → B) to A faltu hai
3Koi FD redundant nahiAgar kisi FD ko hata kar bhi F ka closure same rehta ho to wo faltu hai

Aur minimal cover Fc, F ke equivalent hona chahiye (Fc ≡ F).

Algorithm

  1. Split RHS: har X → A₁A₂… ko X → A₁, X → A₂, … mein todo. Duplicate hata do.
  2. Extraneous LHS: jis FD ka LHS ek se zyada attribute ka ho, uske har attribute A ke liye test karo: (LHS − A)⁺ (original F se) ⊇ RHS? Haan ⇒ A faltu, hata do.
  3. Redundant FD: har FD f ko ek-ek karke hatao; agar baaki FDs se hi f nikal aaye (f ka LHS⁺ baaki set mein RHS rakhta ho) to f permanently hata do.
Order matter karta hai

Step 2 pehle, step 3 baad mein. Pehle LHS chhota karo, phir redundant FDs hatao — ulta karne par kabhi-kabhi ek faltu FD reh jaati hai. Aur step 3 mein ek-ek karke hatao (har baar jo baaki bacha uske saath test).

Worked example 1 — F = { A→BC, B→C, A→B, AB→C }

  1. Split: A→BC ⇒ A→B, A→C. Baaki: B→C, A→B (dup), AB→C. Set: { A→B, A→C, B→C, AB→C }.
  2. Extraneous LHS (sirf AB→C mein dono attribute hain): A faltu? (B)⁺ = {B, C} ∋ C ⇒ haan A faltu. AB→C ban gayi B→C (jo already hai, duplicate hataya). Set: { A→B, A→C, B→C }.
  3. Redundant FD: A→B ko hatao: A⁺ baaki mein = {A, C} ∌ B ⇒ zaroori. A→C ko hatao: A⁺ = {A, B, C} (A→B, B→C) ∋ C ⇒ redundant, hata do. B→C ko hatao: B⁺ = {B} ∌ C ⇒ zaroori.
Minimal cover
A → B, B → C   (4 FD ke badle 2)

Worked example 2 — ek hi F ke do alag minimal covers

F = { A→B, B→A, B→C, A→C, C→A }. Step 1 ke baad sab RHS single hain. Step 2 mein sab LHS single-attribute hain, kuch hatane ko nahi. Step 3 mein redundant FDs ka choice order se badal jaata hai:

Cover 1 (A→C aur B→A hataye)

A→C redundant: A→B, B→C se. B→A redundant: B→C, C→A se.

A → B, B → C, C → A  (3 FDs)

Cover 2 (B→C hataya)

B→C redundant: B→A, A→C se.

A → B, B → A, A → C, C → A  (4 FDs)

Dono F ke equivalent hain aur dono minimal hain (har FD zaroori, LHS single). Minimal cover unique nahi hota, aur uske FDs ki ginti bhi alag ho sakti hai. GATE mein jab “the” minimal cover poochhte hain to options aksar sirf ek valid cover rakhte hain, ya poochhte hain “kaunsa a minimal cover hai”.

Worked example 3 — teeno steps ek saath: F = { A→BC, B→C, AB→D, D→E, CD→E }

  1. Split: A→B, A→C, B→C, AB→D, D→E, CD→E.
  2. Extraneous LHS (original set ke saath):
    • AB→D: A faltu? (B)⁺ = {B, C} ∌ D ✘. B faltu? (A)⁺ = {A, B, C, D, E} (A→B, A→C, AB→D…) ∋ D ✔ ⇒ B hataya ⇒ A→D.
    • CD→E: C faltu? (D)⁺ = {D, E} ∋ E ✔ ⇒ C hataya ⇒ D→E (dup). D faltu? (C)⁺ = {C} ✘.
    Set: { A→B, A→C, B→C, A→D, D→E }.
  3. Redundant:
    • A→B: baaki se A⁺ = {A, C, D, E} ∌ B ⇒ zaroori.
    • A→C: baaki se A⁺ ∋ B ⇒ B→C ⇒ C ✔ ⇒ redundant.
    • B→C: B⁺ = {B} ⇒ zaroori. A→D: A⁺ = {A, B, C} ∌ D ⇒ zaroori. D→E: D⁺ = {D} ⇒ zaroori.
Minimal cover
A → B, B → C, A → D, D → E

Check: (A)⁺ = {A, B, C, D, E} — original F wali saari jaankari bachi hai ⇒ equivalent ✔.

Canonical cover (alag name?)

Silberschatz jaisi kitabein canonical cover Fc ko aise define karti hain: Fc ≡ F, koi extraneous attribute nahi (LHS ya RHS mein), aur har LHS unique (same LHS wali FDs ko union se jod do: A→B, A→D ⇒ A→BD). Hamara “minimal cover” GATE/Navathe style hai (RHS single). Dono ka algorithm same, bas end mein canonical mein same-LHS wali FDs ko jod dete hain: example 3 ka canonical cover = { A → BD, B → C, D → E }.

Traps
  • Redundant FD hataane ke baad doobara check karo ki dusri FDs ab bhi zaroori hain (har hatane ke baad updated set se).
  • Extraneous test original F ke saath hota hai, jisme wo FD khud bhi shaamil hai.
  • Minimal cover ek se zyada ho sakte hain — answer mein koi ek valid dena kaafi hai.
  • RHS ko todna hamesha safe hai; LHS ko todna sirf tab jab extraneous ho.
Ab tum try karo

Q. F = {A → B, AB → C}. Minimal cover?

Answer: Step 1: RHS pehle se single. Step 2: AB → C mein B faltu? (A)⁺ poore F ke saath = A → B ⇒ {A, B}; AB → C ⇒ {A, B, C} ∋ C ✔ ⇒ B extraneous ⇒ AB → C ban gayi A → C. (A faltu? (B)⁺ = {B} ∌ C ✘.) Set: {A → B, A → C}. Step 3: A → B hatao ⇒ A⁺ = {A, C} ∌ B ⇒ zaroori; A → C hatao ⇒ A⁺ = {A, B} ∌ C ⇒ zaroori. ⇒ Minimal cover = {A → B, A → C} (canonical form: A → BC).

✔ Sirf A

✔ AB
A, B L-team ⇒ core AB; (AB)⁺ = ABCD ⇒ akeli key.
Q4. R(A,B,C,D,E), F = {AB → C, C → D, D → E, E → A}. Saari candidate keys?
✔ AB, BC, BD, BE
B L-team ⇒ core {B}; B⁺ = {B}. B + A: AB → C → D → E ✔. B + C: C → D → E → A ✔. B + D: D → E → A ⇒ AB → C ✔. B + E: E → A ⇒ AB → C → D ✔. Sab size 2.
Q5. Upar wale relation mein kitni superkeys hain?
✔ 15
Har key mein B hai. B ke saath {A, C, D, E} ka koi bhi non-empty subset superkey (A, C, D, E mein se ek bhi B ke saath jud jaaye to key ban jaati hai). 2⁴ − 1 = 15. Akeli {B} superkey nahi.
Q6. F = {A → B, B → C} aur G = F ∪ {A → C}. Kya F ≡ G?
✔ Haan
A → C pehle se F⁺ mein hai (transitivity); G ke har FD F se implied aur ulta.
Q7. F = {A → B, A → C} aur G = {A → BC}. Equivalent?
✔ Haan
Union aur decomposition rules.
Q8. F = {AB → C} aur G = {A → C}. Kaun kisko cover karta hai?
✔ G covers F; F covers G nahi

Q9. R(A,B,C), F = {A → B, B → C}. Kya C → A implied hai?

C⁺ = {C} ∌ A.

✔ AB, BC, BD

Q18. True/False: Agar K candidate key hai to K ka har superset candidate key hai.
✔ False
Superset superkey hota hai, minimal nahi.
Q19. R(A,B,C,D), F = {A → B, B → C, AB → C, AC → D}. Ek minimal cover likho.
✔ {A → B, B → C, A → D}
Split: sab RHS single. Extraneous: AB → C mein A faltu? B⁺ = {B,C} ∋ C ⇒ AB → C = B → C (dup). AC → D mein C faltu? A⁺ (original F) = {A,B,C,D} ∋ D ⇒ AC → D = A → D. Redundant check: A → B, B → C, A → D sab zaroori.
Q20. F = {A → BC, C → D, AB → D, B → D}. Ek minimal cover likho.
✔ {A → B, A → C, B → D, C → D}
Split ⇒ A→B, A→C, C→D, AB→D, B→D. AB → D: A faltu? B⁺ = {B,D} ∋ D ✔ ⇒ B → D (dup). Set: {A→B, A→C, C→D, B→D}. Redundant check: har FD hatakar dekho — A → B hatao to B kahin se nahi aata, A → C hatao to C nahi aata, B → D aur C → D hatane par D nahi aata ⇒ chaaron zaroori.
Q21. F = {AB → C, B → C}. Minimal cover?
✔ {B → C}
AB → C mein A faltu: B⁺ = {B,C} ∋ C ⇒ AB → C ban gayi B → C, jo already hai. Ek hi FD bachi.
Q22. R(A,B,C,D,E,F), F = {A → B, B → C, CD → E, E → D}. Saari candidate keys aur superkeys ki ginti?
✔ Keys: ADF, AEF; superkeys = 12
A (sirf LHS) aur F (kisi FD mein nahi) core. (AF)⁺ = {A,B,C,F} ≠ R. D jodo: ADF ⇒ CD → E ⇒ ABCDEF ✔. E jodo: AEF ⇒ E → D ⇒ ABCDEF ✔. B ya C jodne se D/E nahi aate ✘. Superkeys: ADF ke superset (B, C, E ka koi bhi subset) 2³ = 8, AEF ke 2³ = 8, dono ke (ADEF ke superset) 2² = 4 ⇒ 8 + 8 − 4 = 12.
Q23. R(A,B,C,D,E,F), F = {AB → C, C → D, D → E, E → B, F → A}. Candidate keys?
✔ BF, CF, DF, EF
F kisi RHS mein nahi ⇒ core F; F⁺ = {F, A}. Ek jodo: B: BF ⇒ A,B ⇒ AB → C → D → E ✔. C: CF ⇒ D → E → B ⇒ AB → C ✔ (ABCDEF). D: DF ⇒ E → B ⇒ ABF… ✔. E: EF ⇒ B ✔. A ke saath (AF) ⇒ sirf AF ⇒ ✘. Chaaron size 2.
Q24. F = {A → B, B → C, C → A}, G = {A → B, B → C, A → C, C → B}. Kya F ≡ G?
✔ Nahi
F covers G? A → C: A⁺(F) = {A,B,C} ✔; C → B: C⁺(F) = {C,A,B} ✔ ⇒ F covers G. G covers F? C → A: C⁺(G) = {C, B} ∌ A ✘. Sirf ek taraf ⇒ equivalent nahi.
Q25. F = {A → B, AB → C, C → A}, G = {A → BC, C → A}. Kya F ≡ G?
✔ Haan
G covers F: A → B ✔ (A⁺(G) = {A,B,C}), AB → C ✔, C → A ✔. F covers G: A → BC: A⁺(F) = {A,B,C} (A→B, AB→C) ✔; C → A ✔.

Definitions
  • X→Y: t₁[X] = t₂[X] ⇒ t₁[Y] = t₂[Y].
  • Trivial: Y ⊆ X. Instance sirf refute kar sakta hai.
  • Trivial FDs (non-empty): 3ⁿ − 2ⁿ.
  • Superkey: K⁺ = R. Candidate key: minimal superkey. Prime = kisi key ka part.
Axioms
  • Reflexive: Y ⊆ X ⇒ X→Y
  • Augment: X→Y ⇒ XZ→YZ
  • Transitive: X→Y, Y→Z ⇒ X→Z
  • Union, decomposition (RHS only!), pseudo-transitivity, composition.
  • XY→Z ⇏ X→Z.
Closure algorithm

closure = X; jab tak badle: har L→R mein L ⊆ closure to R jodo. FD implied ⇔ RHS ⊆ X⁺.

Candidate keys (5 steps)
  1. N, L, R, B teams.
  2. Core = N ∪ L (har key mein); R team kisi key mein nahi.
  3. Core⁺ = R ⇒ ek hi key.
  4. Warna B se 1, 2, 3 … attributes jodo.
  5. Pehle mili key ke superset skip.
Counting

Ek key, |K|=k: superkeys = 2n−k. Do keys: inclusion–exclusion. Max keys = C(n, ⌊n/2⌋).

Traps
  • Closure ek pass mein mat roko.
  • F ≡ G: dono taraf covers check karo.
  • Minimal cover: pehle LHS extraneous, phir redundant FDs; unique nahi hota.
  • FD data se saabit nahi hoti, sirf toot sakti hai.
