11.1 · Anomalies — problem kya hai? pehle bimari, phir dawai

Socho ek school ka register jisme har baar student ka naam aur course ka title poora likha jaata hai. Jitni baar student kisi course mein baithe, utni baar naam repeat. Yahi problem hai.

ENROLL_ALL (ek hi bhaari table)

Primary key = (SID, CID). Yellow = baar-baar repeat hone wali jaankari

Hidden rules (FDs) jo is table mein chhupe hain:

  • SID → SName — ek SID ka ek hi naam.
  • CID → CTitle — ek CID ka ek hi title.
  • SID, CID → Grade — ek student ka ek course mein ek hi grade.
Update anomaly

“DBMS” ka naam badalkar “Database Systems” karna hai. “DBMS” 3 rows mein hai. 2 update ho gayi, 1 reh gayi → table mein ek hi course ke 2 alag naam. Data inconsistent!

Insertion anomaly

Naya course C4 “ML” aaya, abhi koi student nahi. Row daalne ke liye SID chahiye, par SID primary key ka hissa hai → NULL nahi ho sakta. Course insert hi nahi hoga.

Deletion anomaly

Neha (SID 4) ne C3 chhod diya, uski row delete. Wo C3 ki akeli row thi, to “C3 = Maths” wali jaankari bhi hamesha ke liye gayab.

Root cause (asli wajah)

Ek table mein alag-alag cheezon ke facts (student ke, course ke, enrollment ke) mix ho gaye. Student ka fact SID se decide hota hai, course ka fact CID se, par key dono (SID, CID) hai. Iske liye ilaaj: har fact apni table mein:

Ab tum try karo

Q. STUDENT(SID, Name, DeptID, DeptName) mein ek hi department ke 500 students hain. Dept ka naam badalna ho to kitni rows update? Kaunsi anomaly?

Ans. 500 rows — update anomaly. Fix: DEPT(DeptID, DeptName) alag table.

Yaad rakho

Anomalies ki jad = redundancy (data ka duplicate hona), aur redundancy ki jad = aisa FD jiska left side key nahi hai. Isi liye normal forms FDs aur keys par based hain.

11.2 · Pehle ke tools: closure, keys, prime attributes 2-minute revision

(a) Closure — X+ kaise nikalte hain

X+ = X se jo bhi attributes pakke taur par nikal sakte hain. Algorithm:

  1. Shuru: X+ = X.
  2. Koi FD L → R dekho jiska poora L abhi X+ mein hai. Uska RHS X+ mein jodo.
  3. Jab tak kuch naya judta rahe, step 2 dohrao.

(b) Superkey aur Candidate key

  • Superkey = aisa set K jiska K+ = saare attributes of R.
  • Candidate key (CK) = minimal superkey: usme se koi bhi attribute hatao to wo superkey nahi rahta.
  • Ek table ki kai candidate keys ho sakti hain. Primary key unme se ek chuni hui hoti hai — normal form ke tests mein saari CKs lagti hain.

(c) Prime aur Non-prime

Prime = kisi bhi candidate key ka hissaNon-prime = kisi bhi CK ka hissa nahi

(d) Saari candidate keys nikalne ka recipe

  1. Teen group banao: (i) jo attribute kisi FD ke RHS par kabhi nahi aata → har key mein hoga (“core”). (ii) jo sirf RHS par aata hai (kabhi LHS par nahi) → kisi key mein nahi. (iii) baaki dono taraf aane wale → shayad.
  2. Core ka closure nikalo. Agar wo saare attributes deta hai → core hi akeli candidate key hai. Ruk jao.
  3. Nahi to core mein (iii) wale attributes ek-ek karke, phir do-do karke jodo jab tak closure = R. Jo minimal milein wahi CKs.
  4. Jis set mein pehle se koi CK hai, uske supersets mat banao (wo minimal nahi honge).
Example: R(A,B,C,D), F = {AB → C, C → D, D → A}
AttributeRHS par aata hai?LHS par aata hai?Faisla
Ahaan (D → A)haanshayad
Bnahihaan (AB → C)har key mein zaroor
Chaan (AB → C)haan (C → D)shayad
Dhaan (C → D)haan (D → A)shayad

Hal: Core = {B}. B+ = B (kuch nahi nikla). Ab ek-ek jodo:

  • (AB)+: A,B → AB → C ⇒ C → D ⇒ ABCD ✔ superkey.
  • (BC)+: C → D ⇒ D → A ⇒ ABCD ✔.
  • (BD)+: D → A ⇒ AB → C ⇒ ABCD ✔.

Teeno 2-size ke hain aur B akela nahi chalta ⇒ teeno minimal. CKs = {AB, BC, BD}. Prime = {A, B, C, D} (sab), Non-prime = koi nahi.

Do aur patterns

Cycle: R(A,B,C), F = {A → B, B → C, C → A}: koi attribute “RHS par nahi” wala nahi, A+ = B+ = C+ = ABC ⇒ teeno akele CK (3 keys).

Koi FD nahi: R(A,B,C), F = ∅ ⇒ poori ABC hi akeli key (sab attributes core).

Trap: attribute ka check

Prime / non-prime tay karne se pehle saari CKs nikalo. Ek CK dekhkar ruk gaye to kaafi attribute galat se non-prime ban jaate hain (jaise upar: sab attributes prime hain, kyunki B ke saath A, C, D mein se har ek kisi na kisi CK mein hai).

Ab tum try karo

Q. R(A,B,C,D,E), F = {A → B, B → C, D → E}. Candidate key? Prime attributes?

Ans. RHS par nahi aate: A, D ⇒ core = AD. (AD)+: A → B → C, D → E ⇒ ABCDE ✔. CK = AD (akeli). Prime = {A, D}; non-prime = {B, C, E}.

11.3 · 1NF — har cell mein ek hi value sabse neeche ki seedhi

Definition: Relation 1NF mein hai agar har attribute ki har value atomic (ek, aur aage na tootne wali) ho. Cell mein list, set, ya repeating group nahi.

Do fix ke tareeke:

  1. Rows badhao (har value ki alag row) — upar wali tarah; key ban jaati hai (StudentID, Phone).
  2. Alag table banao: STUDENT(StudentID, …) aur STUDENT_PHONE(StudentID, Phone) — design ke liye sabse achha.
  • Composite attribute (jaise Address = street + city + pin) ko bhi toda jaata hai (street, city, pin) jab alag-alag use hon.
  • Multivalued attribute (Phone, Skills) ke liye alag relation. (Isi wajah se 2026 Q61 mein A22 ke liye alag table chahiye thi — aage PYQ section dekho.)
Relational model mein 1NF “mufte” mein

Relational model ki definition mein hi relation = atomic values wali table. Isliye GATE mein jab bhi “relation” bola jaye, wo by definition 1NF hoti hai. Real sawaal 2NF se shuru hote hain; “highest normal form” poochhne par kam se kam 1NF to hamesha hai.

Trap

Atomic hona application par bhi depend karta hai: agar “Name” ko hamesha ek poora text maana jaye to wo atomic hai. Par “comma-separated phones” ko ek value maanna design ki galti hai.

Ab tum try karo

Q. COURSE(CID, Title, Teachers) jisme Teachers = “Rao, Sen”. 1NF? Fix?

Ans. 1NF nahi. COURSE(CID, Title) + COURSE_TEACHER(CID, Teacher).

11.4 · 2NF — key ke tukde par nirbharta nahi partial dependency

Analogy

Maan lo school mein ID card number = (Class, RollNo) dono milkar. Ab “class teacher ka naam” sirf Class par depend karta hai, RollNo se kuch lena-dena nahi. To class teacher ka naam poori key ki jagah sirf aadhi key par tika hua hai. Wohi partial dependency hai.

ENROLL_ALL: key (SID, CID). SName sirf SID par, CTitle sirf CID par tike hain (partial). Grade ko poori key chahiye (full).

Definition (exact)

2NF = 1NF + koi non-prime attribute kisi candidate key ke proper subset par depend na kare.

Matlab: aisa FD S → A nahi hona chahiye jahan S kisi CK ka proper subset ho aur A non-prime ho.

2NF test — step by step

  1. Saari candidate keys nikalo, phir prime / non-prime alag karo.
  2. Agar saari CKs single-attribute hain → proper (non-empty) subset hota hi nahi → 2NF automatically. Ruk jao.
  3. Har aisi CK ke liye jisme ≥ 2 attributes hain, uske har non-empty proper subset S ka closure S+ nikalo.
  4. Agar kisi S+ mein koi non-prime attribute aaya → 2NF violation. Warna 2NF ✔.

Worked example 1 — ENROLL_ALL

R(SID, SName, CID, CTitle, Grade); F = {SID → SName, CID → CTitle, (SID,CID) → Grade}.

  • RHS par nahi aane wale: SID, CID ⇒ core = {SID, CID}. (SID,CID)+ = sab ⇒ CK = (SID, CID).
  • Prime = {SID, CID}; Non-prime = {SName, CTitle, Grade}.
  • Proper subsets: SID+ = {SID, SName} → SName non-prime ✘ partial. CID+ = {CID, CTitle} → CTitle ✘ partial.

Natija: 2NF nahi. Fix: partial wale FD alag table: STUDENT(SID, SName), COURSE(CID, CTitle), ENROLL(SID, CID, Grade).

Worked example 2 — partial dependency jo seedha likha nahi hota

R(A,B,C,D,E), F = {AB → E, A → C, C → D}.

  • RHS par nahi: A, B ⇒ core AB; (AB)+ = A,B → E (AB→E), C (A→C), D (C→D) = ABCDE ✔. CK = AB.
  • Prime = {A, B}; non-prime = {C, D, E}.
  • A+ = {A, C, D} → C aur D non-prime ✘. B+ = {B} theek.

2NF violation hai — jabki “A → D” FD kahin likhi nahi thi! Wo closure se nikli. Isiliye sirf given FDs dekhna kaafi nahi, S+ nikalo.

Traps (2NF)
  • Prime attribute ka partial dependency allowed hai (2NF sirf non-prime ki baat karta hai).
  • Ek hi CK nahi, har CK ke subsets check karo.
  • Agar non-prime attribute hi nahi hai (sab prime), to 2NF (aur 3NF) khud-ba-khud ✔.
Ab tum try karo

Q. R(A,B,C,D), F = {AB → C, B → D}. 2NF?

Ans. CK = AB (A, B RHS par nahi; (AB)+ = ABCD). Non-prime = C, D. B+ = {B, D} → D non-prime ⇒ 2NF nahi (highest 1NF).

11.5 · 3NF — non-key se non-key ka sambandh nahi transitive dependency

Analogy

Student → Department → Department ka naam. Student ke department ka naam seedha student se nahi, department ke raaste pata chalta hai. Ek hi department ke 500 students ho to naam 500 baar repeat. Yeh transitive dependency hai.

Key (EmpID) → non-key (DeptID) → non-key (DeptName): beech wala DeptID superkey nahi hai.

3NF ki exact definition (yahi GATE mein lagao)

Relation R 3NF mein hai agar har non-trivial FD X → A ke liye (jahan A ek single attribute):

(1) X superkey ho  YA  (2) A prime attribute ho

Trivial FD = jisme A ⊆ X (ise ignore karo). RHS multi-attribute ho to pehle split karo (A → BC ⇒ A → B, A → C).

3NF test — step by step

  1. Candidate keys aur prime / non-prime nikalo.
  2. Har FD ke RHS ko single attributes mein todo. Trivial FD hata do.
  3. Har bacha hua FD X → A ke liye: kya X superkey hai (X+ = R)? Haan → theek.
  4. Nahi to kya A prime hai? Haan → theek. Nahi → 3NF violation.
  5. Ek bhi violation mili → 3NF nahi. Koi nahi → 3NF ✔.

Worked example — EMP

R(EmpID, EName, DeptID, DeptName), F = {EmpID → EName, EmpID → DeptID, DeptID → DeptName}.

  • EmpID RHS par nahi ⇒ core; EmpID+ = sab ⇒ CK = EmpID. Prime = {EmpID}; non-prime = {EName, DeptID, DeptName}.
  • EmpID → EName, EmpID → DeptID: LHS superkey ✔.
  • DeptID → DeptName: DeptID+ = {DeptID, DeptName} ≠ R ⇒ superkey nahi; DeptName prime nahi ⇒ 3NF violation ✘.

Fix: EMP(EmpID, EName, DeptID) aur DEPT(DeptID, DeptName). Dono mein sab FDs ke LHS keys hain ⇒ 3NF (aur BCNF bhi).

Zaruri relations
  • 3NF ⇒ 2NF. Kyun? Partial dependency S → A (S ⊂ CK, A non-prime) mein S superkey nahi (kyunki S minimal CK ka proper subset hai) aur A prime nahi ⇒ wo 3NF ko bhi tod deti hai. To 3NF wali table mein partial dependency ho hi nahi sakti.
  • Agar saare attributes prime hain ⇒ rule (2) hamesha sach ⇒ 3NF khud-ba-khud ✔.
Trap: “prime exception”

Sirf “no transitive dependency” yaad karne se tricky sawal galat jaate hain. Rule (2) ka prime RHS wala chhoot (exception) hi 3NF aur BCNF ka asli farak hai — agle section mein.

Ab tum try karo

Q. R(A,B,C), F = {A → B, B → C}. 3NF?

Ans. CK = A (A+ = ABC). B → C: B superkey nahi (B+ = BC), C non-prime ⇒ 3NF nahi. Par 2NF ✔ (CK single attribute). Highest = 2NF.

11.6 · BCNF — sabse strict: sirf superkey Boyce–Codd Normal Form

BCNF ki definition

Relation R BCNF mein hai agar har non-trivial FD X → Y (jo F+ mein ho) ke liye X superkey ho. Bas. Koi “ya prime attribute” wali chhoot nahi.

Test shortcut: R ke liye BCNF check karte waqt sirf given FDs (F) dekhna kaafi hai — har FD ka LHS closure nikalo; agar kisi ka closure ≠ R ⇒ BCNF nahi. (Dhyan: decomposed sub-relations ke liye yeh shortcut nahi chalta, wahan projected FDs dekhne padte hain — Lesson 12.)

Example jisme 3NF ✔ par BCNF ✘

TEACH(Student, Course, Instructor). Rules: (i) ek student ek course ke liye ek hi instructor; (ii) har instructor sirf ek course padhata hai, par ek course ke kai instructors ho sakte hain.

F = {(Student, Course) → Instructor, Instructor → Course}

Rao hamesha DBMS hi padhata hai — par har student ke saath yeh jodi repeat hoti hai
  • Core: Student (RHS par nahi). Student+ = Student ✘. (Student,Course)+ = + Instructor ✔. (Student,Instructor)+: Instructor → Course ⇒ + Course ✔.
  • CKs = (Student, Course) aur (Student, Instructor). Prime = sab teeno attributes.
  • 3NF: Instructor → Course: LHS superkey nahi, par Course prime ⇒ allowed ✔. Baaki FD ka LHS key ✔. ⇒ 3NF ✔.
  • BCNF: Instructor → Course: Instructor superkey nahi ⇒ BCNF ✘.

Teen kaam ki baatein
  • 2 attributes wali koi bhi relation BCNF mein hoti hai (R(A,B): jo bhi nontrivial FD hoga uska LHS key hi hoga).
  • Sirf ek CK ho ⇒ 3NF ⇔ BCNF. Kyun? 3NF ko BCNF se alag karne wala FD X → A (A prime, X superkey nahi) ek doosri CK paida karta hai.
  • Agar koi FD sirf superkeys se aaye ⇒ BCNF. “Sab attributes prime” se sirf 3NF pakka hota hai, BCNF nahi.
BCNF ka sabse bada trap

BCNF mein koi “prime” wali chhoot nahi. Agar sawal mein kisi bhi non-trivial FD ka LHS superkey nahi ⇒ seedha BCNF fail. Ye bhi: FD “A → B” ka LHS A primary key ho tab bhi dekho ki A superkey hai ya nahi (A+ = R?).

Ab tum try karo

Q. R(A,B,C), F = {AB → C, C → B}. 3NF? BCNF?

Ans. A core. A+ = A ✘. (AB)+ = ABC ✔; (AC)+: C → B ⇒ ABC ✔. CKs = AB, AC; sab attributes prime ⇒ 3NF ✔. C → B: C+ = CB ≠ R ⇒ BCNF ✘.

Jawab: BCNF
  1. Saari CKs nikalo (11.2 ka recipe). Prime / non-prime tay karo.
  2. BCNF test: har non-trivial FD X → Y ka X superkey? Sab ✔ ⇒ BCNF. Ruk jao.
  3. Nahi to 3NF test: har FD X → A: X superkey YA A prime? Sab ✔ ⇒ 3NF. Ruk jao.
  4. Nahi to 2NF test: CK ke proper subsets S ke closure mein non-prime? Koi nahi ⇒ 2NF.
  5. Wo bhi fail ⇒ 1NF (relation hamesha 1NF).

Kaise nikala? — upar ki 6 rows ka poora derivation

Har row mein wahi 3 kaam: (1) CK nikalo, (2) prime / non-prime baanto, (3) BCNF → 3NF → 2NF tests (jahan pehli baar pass ho wahi answer).

  1. R(A,B,C,D), F = {AB → C, B → D}. RHS par nahi: A, B ⇒ core AB. (AB)+: AB → C ⇒ ABC; B → D ⇒ ABCD ✔ ⇒ CK = AB. Prime = {A,B}, non-prime = {C,D}. BCNF: B → D mein B+ = BD ≠ R ⇒ ✘. 3NF: B superkey nahi aur D non-prime ⇒ ✘. 2NF: AB ke proper subsets A, B: A+ = A; B+ = BD, usme D non-prime ⇒ partial ✘. Teeno fail ⇒ 1NF.
  2. R(A,B,C,D), F = {A → B, B → C, C → D}. A RHS par nahi ⇒ core; A+ = ABCD ⇒ CK = A, prime = {A}. BCNF: B → C, B+ = BCD ≠ R ⇒ ✘. 3NF: C non-prime ⇒ ✘. 2NF: CK mein 1 hi attribute ⇒ proper subset hai hi nahi ⇒ ✔. Answer 2NF.
  3. R(A,B,C), F = {AB → C, C → B}. Neeche “Ek example poora lamba (Example 3)” mein poora derivation hai: CKs = AB, AC, sab prime, BCNF ✘, 3NF ✔ ⇒ 3NF.
  4. R(A,B,C,D), F = {A → B, B → C, C → D, D → A}. Koi attribute “RHS par nahi” wala nahi. A+ = ABCD; B+: B → C, C → D, D → A ⇒ BCDA ✔; C+ ✔, D+ ✔ ⇒ CKs = A, B, C, D. Har FD ka LHS (A, B, C, D) superkey ⇒ BCNF ✔ ⇒ BCNF.
  5. R(A,B,C,D,E), F = {AB → E, A → C, C → D}. RHS par nahi: A, B ⇒ core AB; (AB)+: E, C (A → C), D (C → D) ⇒ ABCDE ✔ ⇒ CK = AB. Non-prime = {C,D,E}. A+ = ACD (A → C, phir C → D) ⇒ C, D non-prime hain aur A (CK AB ka hissa) se nikal aaye ⇒ partial ✘ ⇒ 2NF fail. (A → C mein A superkey nahi, C non-prime ⇒ 3NF aur BCNF bhi fail.) Answer 1NF.
  6. R(A,B,C,D), F = {AB → C, C → D, D → A}. B RHS par nahi ⇒ core; B+ = B. Jodo: (AB)+: C, D ⇒ ABCD ✔. (BC)+: D, A ⇒ ABCD ✔. (BD)+: A, phir AB → C ⇒ ABCD ✔ ⇒ CKs = AB, BC, BD; prime = A,B,C,D (sab). Sab prime ⇒ 3NF ✔. BCNF: C → D mein C+ = CDA ≠ R ⇒ ✘ ⇒ 3NF.

Ek example poora lamba (Example 3)

R(A,B,C), F = {AB → C, C → B}

  1. Keys: A RHS par nahi ⇒ core. A+ = A. Jodo B: (AB)+ = ABC ✔. Jodo C: (AC)+ = A,C → B ⇒ ABC ✔. CKs = {AB, AC}. Prime = {A, B, C}.
  2. BCNF: AB → C ✔ (AB superkey). C → B: C+ = {C, B} ≠ ABC ✘ ⇒ BCNF fail.
  3. 3NF: AB → C ✔. C → B: LHS superkey nahi, par B prime ✔ ⇒ 3NF ✔.

Answer: 3NF.

Aam galtiyaan
  • Sirf primary key le kar test karna — hamesha saari CKs.
  • Sirf likhe hue FDs se partial dependency dhundna — S+ nikalo (Example 5).
  • “Sab attributes prime” ⇒ BCNF maan lena. Nahi! 3NF tak (Example 3, 6).
  • Trivial FDs (AB → A) ko violation maan lena.
  • Question “kya R 2NF mein hai?” aur “highest NF?” alag hain. R BCNF ho to wo 2NF mein bhi hai.
Ab tum try karo

Q. R(A,B,C,D), F = {A → B, C → D}. Highest NF?

Ans. Core = AC; (AC)+ = ABCD ⇒ CK = AC. Non-prime = B, D. A+ = AB ⇒ B non-prime partial ⇒ 2NF ✘ ⇒ 1NF.

11.8 · Table ko BCNF mein todna decomposition algorithm

Notation — BCNF decomposition ke letters

Ri = abhi wali table jo BCNF nahi (shuru mein poori R). X = us violating FD ka left side (jo superkey nahi). Y = X ke closure se mile naye attributes, yaani Y = (X+ ∩ Ri) − X. (∩ = common, − = hata do, ∪ = milao.) R1, R2 = Ri ke do nayi chhoti tables.

Mini example: R(A,B,C,D), F = {A → B, B → C, C → D}. Violating FD B → C: X = B. X+ = BCD ⇒ Y = BCD − B = {C, D}. R1 = X ∪ Y = BCD; R2 = R − Y = ABCD − CD = AB. (B dono mein common hai — wahi jod-ne wala column.)

Jab R BCNF nahi hai, to hum use todte hain. Algorithm:

  1. Result = {R}.
  2. Result ki koi relation Ri aisi chuno jo BCNF nahi. Uske liye X ⊆ Ri dhundo jahan Y = (X+ ∩ Ri) − X khali nahi aur X+ ⊉ Ri (yaani X → Y non-trivial aur X, Ri ka superkey nahi).
  3. Ri ko do mein todo: R1 = X ∪ Y aur R2 = Ri − Y.
  4. Jab tak koi relation BCNF se bahar ho step 2-3 dohrao.
Lossless kyun hota hai?

R1 ∩ R2 = X, aur X → Y, jahan Y = R1 − X. Yani common part R1 ko determine karta hai ⇒ binary lossless rule (Lesson 12). Isliye BCNF decomposition hamesha lossless.

Example 1 — chain (sab FD bach jaate hain)

R(A,B,C,D), F = {A → B, B → C, C → D}. CK = A (A+ = ABCD).

  1. B → C: B+ = BCD ≠ R ⇒ violation. X = B, Y = {C, D}. R1 = BCD, R2 = R − CD = AB.
  2. AB: FDs A → B, A key ⇒ BCNF ✔.
  3. R1(B,C,D): FDs jo dikhte hain: B → C, C → D (aur B → D). Key = B. C → D: C+ ∩ R1 = CD ≠ R1 ⇒ violation. X = C, Y = D. R11 = CD, R12 = R1 − D = BC.

Final: {AB, BC, CD}. Teeno BCNF. A → B, B → C, C → D teeno kisi na kisi relation mein hain ⇒ dependency-preserving bhi.

Example 2 — BCNF mein FD kho jaata hai (classic GATE trap)

TEACH(Student, Course, Instructor), F = {(Student,Course) → Instructor, Instructor → Course} (11.6 wali).

  1. Violation: Instructor → Course. X = Instructor, Y = Course. R1 = (Instructor, Course), R2 = R − Course = (Student, Instructor).
  2. R1: Instructor key ✔. R2: koi nontrivial FD nahi ⇒ BCNF ✔.

Lossless? R1 ∩ R2 = Instructor; Instructor → Course = R1 − R2 ✔ ⇒ lossless.

Preserving? (Student, Course) → Instructor ke teeno attributes alag tables mein bikhar gaye (Course R1 mein, Student R2 mein). Dono tables ke FDs mein sirf Instructor → Course hai. Z = {Student, Course} se Instructor nikalna possible nahi ⇒ FD kho gayi. Is relation ka koi bhi BCNF decomposition dependency-preserving nahi ho sakta.

GATE trap

“Har relation ka BCNF decomposition lossless aur dependency-preserving ho sakta hai?” — Galat. 3NF ka ho sakta hai, BCNF ka nahi. (Isi liye real databases mein kabhi-kabhi 3NF pe ruk jaate hain.)

Aage kya?

Lesson 12 mein: lossless ko chase table se kaise prove karein, dependency preservation ka closure-based test, aur 3NF synthesis algorithm jo hamesha lossless + preserving deta hai. 4NF/MVD: syllabus ke bahar — skip. Is book mein normal forms sirf BCNF tak.

PYQ 1 · GATE DA 2025 · Q57 Keys + BCNF · MSQ · 2 marks

Relation R(A,B,C,D,E,F,G), F = {A → BCEF, E → DG, BC → A}. Sahi statement(s)?

  • (A) A is the only candidate key of R
  • (B) A, BC are the candidate keys of R
  • (C) A, BC, E are the candidate keys of R
  • (D) Relation R is not in BCNF
  1. Closures: A+: A → BCEF ⇒ ABCEF; E → DG ⇒ ABCDEFG = sab ✔. A superkey; single attribute ⇒ CK.
  2. (BC)+: BC → A ⇒ ABC ⇒ (upar jaisa) sab ✔. B+ = B, C+ = C ⇒ BC minimal ⇒ CK.
  3. E+ = {E, D, G} ≠ R ⇒ E CK nahi. Aur koi CK? CK mein A ya (B aur C dono) aana hi padega (B, C sirf A se nikalte hain, A sirf A ya BC se). ⇒ CKs = {A, BC}.
  4. BCNF: E → DG: E+ = EDG ≠ R ⇒ E superkey nahi ⇒ BCNF ✘.
Derived answer
B and D. (A galat: BC bhi key. C galat: E key nahi. D sahi.) (Official key paper PDF mein nahi hai; yeh answer khud solve karke nikala hai.)

Extra: highest NF? Prime = A, B, C; non-prime = D, E, F, G. E → D: E non-superkey, D non-prime ⇒ 3NF ✘. 2NF: A single; BC ke subsets: B+ = B, C+ = C ⇒ partial nahi ⇒ highest = 2NF.

PYQ 2 · GATE DA 2026 · Q17 Candidate keys · MCQ · 1 mark

R(A,B,C,D,E), F = {A → BC, CD → E, E → A}. Which statement is correct?
(A) AD, ED and CD are the only candidate keys of R  (B) AD and ED are the only candidate keys  (C) A, E and CD are the only candidate keys  (D) A and CD are the only candidate keys

  1. D kisi FD ke RHS par nahi ⇒ har key mein D. D+ = D ✘ (core akela nahi chalta).
  2. B sirf RHS par aata hai (A → BC mein), LHS par kabhi nahi ⇒ B kisi key mein nahi. To D ke saath A, C, E mein se ek-ek jodo.
  3. (AD)+: A → BC ⇒ ABCD; CD → E ⇒ ABCDE ✔. (ED)+: E → A ⇒ AED; A → BC ⇒ ABCDE ✔. (CD)+: CD → E ⇒ CDE; E → A ⇒ A; A → BC ⇒ ABCDE ✔.
  4. Teeno 2-size, D akela nahi ⇒ teeno minimal. (BD)+ = BD ✘. CKs = {AD, ED, CD}.
Derived answer
Option A. B galat (CD bhi key); C, D galat (A, E, “A akela” key nahi — D zaroori). (Official key paper PDF mein nahi hai; yeh answer khud solve karke nikala hai.)

Extra — highest NF? Prime = {A, C, D, E}; non-prime = {B}. A → B: A non-superkey (A+ = ABC), B non-prime ⇒ 3NF ✘. 2NF: A ⊂ AD aur A+ ∋ B (non-prime) ⇒ partial ⇒ 2NF ✘. Highest = 1NF.

11.10 · Practice questions jawab ke saath

Q1. R(A,B,C,D), F = {A → B, C → D}. Highest normal form?
✔ 1NF.
Core = AC; (AC)+ = ABCD ⇒ CK = AC; non-prime B, D. A+ = AB ⇒ B partial ⇒ 2NF ✘.
Q2. R(A,B,C), F = {A → B, B → C, C → A}. Candidate keys? Highest NF?
✔ Keys A, B, C (3 keys); BCNF.
A+ = B+ = C+ = ABC ⇒ har LHS superkey ⇒ BCNF.
Q3. R(A,B,C,D), F = {AB → CD, C → A}. Candidate keys? Highest NF?
✔ Keys AB, BC; 3NF (BCNF nahi).
Core B. (AB)+ = ABCD ✔. (BC)+: C → A ⇒ ABC ⇒ AB → CD ⇒ ABCD ✔. Prime A, B, C; non-prime D. C → A: C+ = CA ≠ R ⇒ BCNF ✘ par A prime ⇒ 3NF ✔. Partial: A+ = A, B+ = B, C+ = CA (A prime) ⇒ no problem.
Q4. R(A,B,C,D,E), F = {A → B, B → C, C → D, D → E}. Highest NF?
✔ 2NF.
CK = A (A+ = ABCDE). CK single ⇒ 2NF ✔. B → C: B non-superkey, C non-prime ⇒ 3NF ✘.
Q5. R(A,B,C,D), F = {A → B, B → A, AC → D}. Keys? Highest NF?
✔ Keys AC, BC; 3NF.
RHS par nahi: C ⇒ core. C+ = C. (AC)+ = ABCD ✔ (A → B, AC → D). (BC)+: B → A ⇒ ABC ⇒ AC → D ⇒ ABCD ✔. Prime = A, B, C; non-prime = D. A → B, B → A: LHS non-superkey, RHS prime ⇒ 3NF ✔. BCNF ✘ (A+ = AB).
Q6. R(A,B,C,D), F = {A → B, B → C, C → D, D → B}. Highest NF?
✔ 2NF.
A RHS par nahi ⇒ core; A+ = ABCD ⇒ CK = A only. Single-attribute CK ⇒ 2NF ✔. B → C: B+ = BCD ≠ R, C non-prime ⇒ 3NF ✘.
Q7. R(A,B,C,D,E), F = {AB → C, C → D, D → E, E → A}. Kitni candidate keys? Highest NF?
✔ 4 keys: AB, BC, BD, BE; 3NF.
Core = B (RHS par nahi). B+ = B. (AB)+: C ⇒ D ⇒ E ✔. (BC)+: D ⇒ E ⇒ A ✔. (BD)+: E ⇒ A ⇒ C ✔. (BE)+: A ⇒ C ⇒ D ✔. Sab 2-size ⇒ 4 CKs. Sab attributes prime ⇒ 3NF ✔; C → D: C+ = CDEA ≠ R ⇒ BCNF ✘.
Q8. R(A,B,C) mein sirf F = {A → B, A → C} hai. Kitne superkeys hain?
✔ 4.
CK = A. Superkeys = wo sab subsets jo A ko contain karein: A, AB, AC, ABC = 2² = 4. (Formula: agar ek hi CK ho jisme k attributes hain aur total n attributes, superkeys = 2n−k.)
Q9. (MSQ) Kaun se statements sahi hain? (a) 2 attributes wali har relation BCNF mein hai. (b) Agar relation 3NF mein hai aur uski sirf ek candidate key hai, to wo BCNF mein bhi hai. (c) Har 3NF relation 2NF mein hoti hai. (d) Agar R ke saare attributes prime hain, to R BCNF mein hai.
✔ (a), (b), (c) sahi; (d) galat.
(d) ka counter-example: R(A,B,C), F = {AB → C, C → B} — sab prime, 3NF ✔ par BCNF ✘. (a): R(A,B) mein jis non-trivial FD ka LHS ek attribute ho (A → B), A+ = AB ⇒ superkey. (b): BCNF tootne ke liye prime A wala X → A chahiye, jo doosri CK banata hai. (c): 11.5 ka argument.
Q10. ORDER_ITEM(OrderID, ProductID, ProductName, Price, Qty), F = {(OrderID,ProductID) → Qty, ProductID → ProductName, ProductID → Price}. 2NF tak kaise todein?
✔ PRODUCT(ProductID, ProductName, Price) aur ORDER_ITEM(OrderID, ProductID, Qty).
CK = (OrderID, ProductID). ProductID+ = {ProductID, ProductName, Price} ⇒ partial dependency. Partial wale FD alag table mein; baaki (OrderID, ProductID, Qty) mein. Dono ab BCNF.
Q11. R(A,B,C,D), F = {A → B, C → D}. BCNF decomposition karo.
✔ {AB, CD, AC}.
CK = AC. A → B violation: X = A, Y = B ⇒ R1 = AB, R2 = ACD. R2 mein C → D (C+ ∩ ACD = CD) violation ⇒ CD aur AC. Final AB, CD, AC. Dono FD (A→B, C→D) bach gaye; lossless by construction.
Q12. R(A,B,C), F = {AB → C, C → A}. BCNF decomposition karo. Kya AB → C preserve hua?
✔ {CA, CB}; AB → C preserve nahi hua.
Keys AB, BC. C → A violation: R1 = CA, R2 = R − A = CB. AB → C: Z = AB; CA se: A+ = A ⇒ kuch nahi; CB se: B+ = B ⇒ kuch nahi ⇒ Z = AB, C ∉ Z ⇒ ✘. Phir bhi R 3NF mein tha (sab prime).

Yaad rakho
  • BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF.
  • RHS par nahi aane wala attribute ⇒ har key mein.
  • Sirf RHS par aane wala ⇒ kisi key mein nahi.
  • Saari CKs ⇒ prime tay ⇒ tests.
  • Sab prime ⇒ 3NF ✔ (BCNF nahi pakka).
  • Single-attribute CKs ⇒ 2NF ✔.
  • 2-attribute relation ⇒ BCNF ✔.
  • Ek hi CK ⇒ 3NF = BCNF.
  • Superkeys (ek CK, k attrs, total n) = 2n−k.
Traps
  • Derived partial dependency: S+ nikalo.
  • BCNF decomposition lossless par preserving nahi hamesha.
  • DB normalization ≠ data normalization (min-max).
  • Primary key hi nahi — saari CKs.
