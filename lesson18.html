18.1 · Sampling kyun? poora data nahi, ek chhota representative hissa

Real-life picture

Daal pakne ke baad tum ek chammach chakhte ho, poori degchi nahi. Agar daal achhe se hilayi (mix) hai to ek chammach poori degchi ka swaad bata deta hai. Sampling yahi hai: population (poora data) ke andar se ek sample (chhota subset) chuno aur uske upar analysis karo.

  • Population: saare records jinke baare mein jaanna hai (e.g. 10 crore customers).
  • Sample: chuna hua subset (e.g. 1 lakh customers). Size = n, population size = N.
  • Sampling frame: population ka asli list jisme se hum chunte hain.
  • Sampling bias: chunne ka tareeka galat, jisse kuch groups zyada ya kam aa jaate hain (e.g. sirf Delhi ke customers pe survey).

Faida: time aur cost kam, experiments tez. Nuksan: sampling error, rare events miss ho sakte hain.

Notation / matlab — N, n, k, σ, SE, Nh, nh, C(N,n)
  • N = population ka size (kul units); n = sample ka size. Example: 1000 students mein se 100 chune → N = 1000, n = 100.
  • σ = population ki standard deviation (values kitni phaili hain). SE = standard error = sample-average mein typical galti.
  • k = systematic sampling mein interval (har k-th unit).
  • Nh, nh = stratum (group) number h ka population size aur usme se liya sample size. σh = us stratum ki SD.
  • C(N, n) = “N mein se n chunne ke tareeke” (order ignore) = N!/(n!(N−n)!). Example C(5,2) = 5!/(2!·3!) = 120/12 = 10.

Sampling error ka intuition (kyun bada sample behtar)

Sample se nikala hua average poori population ke average se thoda alag hoga — ye sampling error hai. Standard error of mean:

SE = σ / √n    (population SD σ, sample size n)

Words mein: sample jitna bada, average utna sahi. Substitute: σ = 20, n = 100 → SE = 20/√100 = 20/10 = 2.

kam important Proportion ke liye: SE = √(p(1−p)/n). p = 0.5 hone par n = 100 → 0.05; n = 400 → 0.025; n = 2500 → 0.01. 95% confidence ka margin ≈ 1.96 × SE; ±3% margin ke liye n = 1.96² × 0.25 / 0.03² = 1067.1 → 1068 chahiye. (Population ka size almost irrelevant hai jab tak n, N se chhota ho.)

kam important Finite population correction (WOR): SE = (σ/√n) × √((N−n)/(N−1)). N = 1000, n = 100, σ = 20 → 2 × √(900/999) = 1.898. Jab n, N ka bada hissa ho tab asar dikhta hai.

Sampling kab theek hai?
  • Sample random ho aur population ka representative (taaki bias na ho).
  • Size itna ho ki error acceptable ho (n badhao to SE ∝ 1/√n ghatta hai).
  • Rare groups (fraud, urban 10%) ko dhyaan se: stratified ya oversampling.

18.2 · Sampling ke tareeke

A. Simple random sampling (SRS)

Har unit ko ek barabar chance; koi pattern nahi (lottery). Do versions:

SRSWOR (without replacement)SRSWR (with replacement)
Draw ke baadChuni hui unit wapas nahi daalteChuni hui unit wapas daalte hain
RepeatsNahi (sab distinct)Haan (same unit dobara aa sakti hai)
Ordered samples ki gintiN(N−1)(N−2)…(N−n+1)Nn
Unordered distinct subsetsC(N, n)(distinct subsets nahi, ordered tuples gino)
P(ek khaas unit sample mein)n/N1 − (1 − 1/N)n
Draws independent?NahiHaan

Worked example — N = 5 units {A, B, C, D, E}, n = 2

  1. SRSWOR: C(5,2) = 10 samples: AB, AC, AD, AE, BC, BD, BE, CD, CE, DE. Har ek ki probability 1/10.
  2. P(A sample mein) = jin samples mein A hai = AB, AC, AD, AE = 4 → 4/10 = 0.4 = n/N ✔.
  3. SRSWR (ordered draws): 5 × 5 = 25 equally-likely tuples (AA, AB, AC … EE).
  4. P(A kam se kam ek baar) = 1 − (4/5)² = 1 − 16/25 = 9/25 = 0.36. Yaani WR mein A ke aane ki chance (0.36) WOR (0.4) se kam hai, kyunki ek draw "waste" ho sakta hai duplicate pe.
  5. WR mein expected distinct units = 5 × (1 − (4/5)²) = 5 × 9/25 = 1.8 (2 nahi).
Formulas kahan se aaye (N = 5, n = 2 par check)
  • SRSWOR unordered: C(5,2) = 5!/(2!·3!) = 10 — upar wali list mein gin lo, 10 hi hain.
  • SRSWOR ordered: pehli draw 5 tareeke, doosri draw mein ek kam → 5 × 4 = 20 (= 10 × 2! orderings).
  • SRSWR ordered: har draw mein phir se 5 option → 5 × 5 = 52 = 25 = Nn.
  • P(A WOR): A wale samples = A ke saath baaki 4 mein se 1 chuno = C(4,1) = 4; 4/10 = 0.4 = n/N.
  • P(A WR): “A kabhi nahi aaya” = (4/5)×(4/5) = 16/25; to A aaya = 1 − 16/25 = 9/25 = 0.36 = 1 − (1 − 1/N)n.
Traps
  • "Kitne possible samples" mein order matter karta hai ya nahi, ye sawal se dekho. WOR unordered → C(N,n). WR ordered → Nn.
  • WR sample mein size n hone par bhi distinct units kam ho sakte hain.
  • Bahut bade N ke liye WR aur WOR practically same.

B. Systematic sampling

Ek random start choose karo, phir har k-th unit lo. Interval k = N/n.

Example: N = 1000, n = 100 → k = 10. Random start = 4 (1 se 10 ke beech) → 4, 14, 24, …, 994 (100 units). Check: i-th unit = 4 + (i − 1) × 10; 100th unit = 4 + 99 × 10 = 994 ✓. Simple aur sasta (list se seedhi), spread achha.

Periodicity trap

Agar data mein koi cycle hai (jaise har 7th record Sunday ki sale) aur k = 7 (ya uska multiple) to saare chune hue records Sunday ke honge → bias. Systematic sampling tabhi safe hai jab list random order mein ho ya k, data ke period se unrelated ho.

C. Stratified sampling

Population ko pehle homogeneous groups (strata) mein baanto (department, gender, region), phir har stratum se sample lo. Fayda: har group ka representation guaranteed, aur variance kam.

  • Notation: Nh = stratum h ke units, N = sab strata ka sum, n = total sample, nh = stratum h se kitne lene hain. Rule: jo stratum population mein jitna bada hissa, sample mein utna hi hissa.
  • Proportional allocation: nh = n × Nh / N. College: 600 CSE + 400 ECE = 1000, n = 100 → CSE = 100 × 600/1000 = 60, ECE = 100 × 400/1000 = 40.
  • Teen strata 500, 300, 200 aur n = 50: 25, 15, 10 (check: 25 + 15 + 10 = 50 ✔).
  • kam important Optimum (Neyman) allocation: nh ∝ Nh · σh. N1 = 400 (σ1 = 10), N2 = 600 (σ2 = 5), n = 70: products 4000 aur 3000, total 7000 → n1 = 70 × 4000/7000 = 40, n2 = 70 × 3000/7000 = 30. Jis stratum mein zyada variation, wahan zyada sample.

Kyun zaroori: 90% rural + 10% urban population mein SRS se n = 20 lene par ek bhi urban na aane ki probability = ∏i=0..19 (90−i)/(100−i) [∏ = guna karte jao: pehli draw rural: 90/100, doosri: 89/99, teesri: 88/98 ... bees draws tak] ≈ 0.095 (~9.5%). Proportional stratified sampling mein urban ke 2 units pakke aayenge.

D. Cluster sampling

Population ko natural groups (clusters) mein baanto (school, ward, class). Kuch clusters randomly choose karo aur chune hue clusters ke saare units le lo (one-stage), ya unmein se phir sample (two-stage). Fayda: sasta (geographically paas-paas). Example: 50 classes × 40 students, 3 classes randomly = 120 students.

18.3 · Compression — kam jagah mein wahi information

Compression = data ko kam bits/bytes mein represent karna. Faida: storage aur network bandwidth ki bachat. Do kism:

Lossless

Decompress karne par bilkul original wapas. Text, database records, medical data, source code. Examples: RLE, Huffman, LZW/ZIP, PNG.

Lossy

Thodi information permanently kho jaati hai (jo insaan ko noticeable nahi). Images, audio, video. Examples: JPEG, MP3, MPEG. Compression ratio bahut zyada.

Compression ke numbers

Compression ratio = original size / compressed size
Space saving = 1 − (compressed / original)

Words mein: original size = compress hone se pehle ki size; compressed size = baad ki. Ratio batata hai “kitni guna chhota”; saving batata hai “kitna % bacha”. Substitute: original = 2,359,296 B, compressed = 294,912 B → ratio = 2,359,296/294,912 = 8 (8:1); saving = 1 − 294,912/2,359,296 = 1 − 0.125 = 87.5%.

  • Ratio 4:1 → space saving = 1 − 1/4 = 75%. Ratio < 1 matlab file badh gayi (expansion).

18.4 · Run-Length Encoding (RLE) lagatar same cheez ko ginti se likho

Idea: "AAAA" ko "4A" likho. Jahan lambi repeated runs hain wahan bahut kaam ka.

String AAAABBBCCAAAA (13 chars) = 4×A, 3×B, 2×C, 4×A → (A,4)(B,3)(C,2)(A,4). Agar har run (symbol + count) = 2 bytes lete hain to 4 runs × 2 = 8 bytes vs 13 → ratio 13/8 = 1.625.

Bitmap row (24 bits): 10 zeros, 4 ones, 10 zeros. Pehla bit 0 maan kar sirf run-lengths store karo: 10, 4, 10. 4 bit har count ke → 12 bits vs 24 → ratio 2.

RLE bekaar kab?

Jab runs chhote hon: ABCD → (A,1)(B,1)(C,1)(D,1) = 8 bytes vs 4 → ratio 0.5 (file double!). Isliye RLE sorted/low-cardinality columns (jaise Gender sorted) aur simple graphics ke liye achha; random text ke liye nahi. Aur count ke digits (run > 9) ka format fix hona chahiye.

Dictionary aur Delta encoding (database columns ke liye)

  • Dictionary encoding: repeated strings ("CSE" 1 lakh baar) ko chhote codes ({1: CSE, 2: ECE}) se replace. Upar wala 40× example.
  • Delta encoding: sorted/slowly changing numbers ka pehla value + differences. 100, 105, 106, 110 → 100, +5, +1, +4 (chhote numbers kam bits lete hain). Timestamps ke liye kamaal.

18.5 · Huffman coding lossless, variable-length, prefix-free

Real-life picture

Morse code mein sabse common letter "E" ko sabse chhota code (·) milta hai aur rare "Q" ko lamba. Huffman yahi karta hai: jo symbol zyada aata hai usko chhota bit-code, jo kam aata hai usko lamba. Fixed-length (jaise 3 bit har symbol) se average kam bits lagte hain.

Prefix-free hona zaroori hai: koi bhi code kisi doosre code ka shuruaati hissa (prefix) na ho. Tabhi bit-stream ko bina separator ke ek-ek karke decode kar sakte ho.

Algorithm (greedy)

  1. Har symbol ko uski frequency ke saath ek node banao.
  2. Dohrao: sabse chhoti do frequencies wale nodes chuno, unko ek naye parent ke neeche jodo (parent ki frequency = dono ka sum). Ek ko left (0), doosre ko right (1) label karo.
  3. Jab tak ek hi node (root) na bache, step 2 repeat.
  4. Root se kisi leaf tak ke edge labels (0/1) = us symbol ka code.

Full worked example — 100 characters ki file

  1. Total bits (Huffman) = Σ freq × length = 45 + 39 + 36 + 48 + 36 + 20 = 224 bits.
  2. Shortcut check: total bits = saare internal nodes ke weights ka sum = 14 + 25 + 30 + 55 + 100 = 224 ✔ (har merge ek level jodta hai).
  3. Average code length = 224/100 = 2.24 bits/symbol.
  4. Fixed-length: 6 symbols → ⌈log₂6⌉ = 3 bits → 300 bits. Compression ratio = 300/224 = 1.339, space saving = 1 − 224/300 = 25.3%. (8-bit ASCII se compare: 800/224 = 3.57.)
  5. kam important Entropy H = −Σ p log₂ p = 2.220 bits (p = symbol ki probability = freq/100, jaise pA = 0.45; har term p·log₂(1/p): 0.518 + 0.383 + 0.367 + 0.423 + 0.313 + 0.216 = 2.220; Lavg = average code length = 2.24). Theory: H ≤ Lavg < H + 1 → 2.220 ≤ 2.24 < 3.220 ✔.
  6. kam important Kraft check (prefix-free complete tree): Σ 2−length = ½ + 3·⅛ + 2·1/16 = 0.5 + 0.375 + 0.125 = 1 ✔.
Codes kaise nikale (tree se padhna)
  1. Root se shuru; har left edge = 0, har right edge = 1 (figure mein neela/orange).
  2. A: root → left (0) → leaf A. Code = 0.
  3. C: root → right (1) [node 55] → left (0) [node 25] → left (0) [C]. Code = 100. Isi tarah B = 101 (1,0,1), D = 111 (1,1), F = 1100, E = 1101.
  4. Check: A sabse frequent (45) hai aur uska code sabse chhota (1 bit); F sabse rare (5) aur code sabse lamba (4 bits) ✓.

Encode / decode

  • Encode "ABAD": A = 0, B = 101, A = 0, D = 111 → 0 101 0 111 = 01010111 (8 bits; ASCII mein 32 bit).
  • Decode 110001101100: 1100 → F (aage koi code nahi jo 1100 ka prefix ho), 0 → A, 1101 → E, 100 → C. Result "FAEC". Bits padhte jao, jaise hi leaf aaye symbol likho, root par wapas jao.
Huffman ke traps
  • Ties (barabar frequencies) mein kaun pehle merge ho — alag trees/codes ban sakte hain, par total bits (aur average length) hamesha same aur optimal hota hai. Neeche ABRACADABRA mein dekho.
  • 0/1 labels left/right ka swap karne se codes badalte hain par lengths nahi.
  • Sabhi symbols ki frequency barabar aur 2k symbols → Huffman = fixed k-bit.
  • Code lengths symbols ke count se nahi, frequencies se decide hote hain.
  • n symbols → n − 1 internal nodes (merges); tree full binary hota hai (har internal node ke 2 bachhe).
  • Huffman lossless aur optimal prefix code hai (symbol-by-symbol).

Dusra example — "ABRACADABRA" (11 characters)

Frequencies: A = 5, B = 2, R = 2, C = 1, D = 1. Merge: C1 + D1 = 2 → B2 + R2 = 4 → (CD)2 + (BR)4 = 6 → A5 + 6 = 11. Codes: A = 0, C = 100, D = 101, B = 110, R = 111.

  1. Total bits = 5×1 + (2 + 2 + 1 + 1)×3 = 5 + 18 = 23. Internal weights: 2 + 4 + 6 + 11 = 23 ✔.
  2. Encoded: A B R A C A D A B R A → 0 110 111 0 100 0 101 0 110 111 0 = 01101110100010101101110 (23 bits).
  3. Fixed 3-bit (5 symbols): 33 bits → ratio 33/23 = 1.435. ASCII: 88 bits → 3.83.
  4. Tie check: agar B2 ko (CD)2 ke saath pehle merge karte (4), phir R2 + 4 = 6, phir A5 + 6 = 11 → lengths A1, R2, B3, C4, D4 → 5 + 4 + 6 + 4 + 4 = 23 ✔ (alag codes, wahi total).
Ab tum try karo

Q. Frequencies A = 40, B = 30, C = 20, D = 10. Huffman total bits aur fixed-length 2-bit se compare karo.

Answer: 10 + 20 = 30; 30 (B) + 30 = 60; 40 + 60 = 100. Internal sum = 30 + 60 + 100 = 190 bits. Lengths: A = 1, B = 2, C = D = 3 → 40 + 60 + 60 + 30 = 190 ✔. Fixed 2-bit: 200 bits. Saving = 5%.

18.6 · Lossy compression & data reduction information kam, size bahut kam

Lossy idea: chhote/kam-important details hata do (quantization). Example: values 13, 27, 41, 56 ko nearest 10 par round karo → 10, 30, 40, 60: kam distinct values = kam bits, par exact value kho gayi (errors 3, 3, 1, 4). JPEG: image ko frequency components (DCT) mein badalkar chhote components round-off; MP3: insaani kaan ko na sunayi dene wali frequencies hatana.

Syllabus mein nahi — skip

Dimensionality reduction (PCA, feature selection, wavelets), numerosity reduction (regression/histogram/clustering se data replace karna) aur LZ77/LZW jaise algorithms syllabus ke "compression" item mein explicitly nahi hain; PCA GATE DA ke ML section ka topic hai. Is book mein inhe nahi padhaya. Yahan sirf yaad rakho: sampling data ko chhota karne ka ek tareeka hai (rows kam), aur compression = bits kam.

18.8 · Practice questions answers ke saath

Q1. N = 200, n = 20: systematic interval k?
✔ k = N/n = 10.
Q2. N = 6, n = 2. SRSWOR mein kitne distinct (unordered) samples? SRSWR mein kitne ordered?
✔ C(6,2) = 15; 6² = 36.
Q3. Population 5 units, SRSWOR n = 3. Ek khaas unit ke sample mein hone ki probability?
✔ n/N = 3/5 = 0.6 (check: C(4,2)/C(5,3) = 6/10).
Q4. Wahi, SRSWR n = 3: P(ek khaas unit kam se kam ek baar)?
✔ 1 − (4/5)³ = 1 − 64/125 = 61/125 = 0.488.
Q5. 1500 Hindi + 500 English medium students; proportional stratified n = 100. Har stratum ka sample?
✔ Hindi: 100 × 1500/2000 = 75; English: 25.
Q6. (kam important) Strata: N1 = 300 (σ = 4), N2 = 200 (σ = 9); n = 60 Neyman allocation.
✔ Products: 1200 aur 1800 (sum 3000). n1 = 60 × 1200/3000 = 24; n2 = 36.
Q7. σ = 30. SE of mean n = 36? n = 144?
✔ 30/6 = 5; 30/12 = 2.5 (4 guna sample → SE aadha).
Q8. 20 schools mein se 4 randomly chuna aur un schools ke saare students liye. Kaun si technique?
✔ Cluster sampling.
Q9. Medical records ko compress karna hai, exact recover zaroori. Lossy ya lossless?
✔ Lossless.
Q10. "WWWWWBBWWW" ka RLE (symbol, count)?
✔ (W,5)(B,2)(W,3). Size 6 vs 10.
Q11. Frequencies A = 5, B = 9, C = 12, D = 13, E = 16, F = 45. Huffman total bits?
✔ Same as upar (permuted): merges 5+9 = 14, 12+13 = 25, 14+16 = 30, 25+30 = 55, 45+55 = 100 → 224 bits, code lengths F = 1, others 3/3/3/4/4.
Q12. Frequencies 1, 1, 2, 3, 5, 8, 13: Huffman total bits? Fixed-length compare?
✔ Merges: 1+1 = 2; 2+2 = 4; 3+4 = 7; 5+7 = 12; 8+12 = 20; 13+20 = 33. Sum = 2 + 4 + 7 + 12 + 20 + 33 = 78 bits (33 symbols, avg 2.36). Fixed ⌈log₂7⌉ = 3 bits → 99.
Q13. Kya {0, 10, 11} ek valid prefix code hai? {0, 01, 11}?
✔ {0, 10, 11}: haan, koi bhi code doosre ka prefix nahi. {0, 01, 11}: nahi, 0 is a prefix of 01.
Q14. 8 equally likely symbols ke liye Huffman average length?
✔ Har symbol 3 bits (full balanced tree) = fixed-length, average = 3.
Q15. Image 2000 × 1000, 24-bit raw; JPEG ke baad 250 KB (1 KB = 1000 B). Ratio?
✔ Raw = 2,000,000 × 3 = 6,000,000 B. Ratio = 6,000,000/250,000 = 24:1; saving = 1 − 1/24 = 95.8%.
Q16. MSQ: lossy hain? (a) JPEG (b) ZIP (c) MP3 (d) Huffman
✔ (a) aur (c).
