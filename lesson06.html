Teen golden rules (poore chapter ka nichod)
  1. Input table → Output table. Output bhi table hoti hai, isliye operators ko chain kar sakte ho.

  • Relational Algebra (RA) = tables par kaam karne ke chhote mathematical steps ka set.
  • RA procedural hai: aap bata rahe ho “kaise” (kaunse steps, kis order mein). SQL zyada declarative hai: aap bolte ho “kya chahiye”, “kaise” database sochta hai.

6.3 · Core 3: σ π ρ ek table par kaam karne waale operators

σ
Selection — ROWS chuno
Jo rows condition satisfy karti hain, sirf wahi rakho. Baaki hata do.

Real-life picture

Excel mein Filter laga diya: “sirf Dept = CSE dikhao”. Kuch rows gaayab, columns jaise ke taise.

Syntax

σcondition(Relation)

Padho: σc(R) = “table R mein se wo rows do jin par condition c true hai”. Jaise c = (Dept = 'CSE'), R = STUDENT.

Condition mein: = ≠ < > ≤ ≥ aur jodne ke liye ∧ (AND), ∨ (OR), ¬ (NOT).

Pehle ye samjho — “sigma”, “pi” kya hai?

Ye bas Greek akshar hain jo naam ki jagah symbol ban gaye. Jaise “+” ka matlab jodna, waise “σ” ka matlab filter rows.

Trick

σ → Select = Slice rows (Rows → σ). Subscript mein condition hoti hai, bracket mein table.

  4. Jo bachi wahi output hai — sab columns ke saath.

π ke rules

Size rules
  • Degree = jitne attributes likhe (yahan 1).
  • Rows ≤ original rows. Max = |R| (jab sab rows alag hon), Min = 1 (agar R khali nahi).
  • Agar key project ki, to rows kam nahi hongi (key unique hoti hai).
  • πA(πA,B(R)) = πA(R)
Traps
  • Jo column π ne hata diya, uspar baad mein σ nahi laga sakte! (agla section dekho)
  • Subscript mein comma se alag karo: πName, Dept.
  • Projection row hataata nahi (sirf duplicates ke alawa) — row filter = σ.

Q. R(A,B,C) mein 4 rows hain. πA(R) ki maximum aur minimum rows?

Answer: Max = 4 (saari A values alag), Min = 1 (saari A values same).

π ke rules — kyun sach hain?
  • πA(πA,B(R)) = πA(R): andar wala π A aur B rakhta hai, bahar wala sirf A. End mein A hi bachta hai — B ko pehle rakhna ya na rakhna fark nahi. (A, B = R ke columns.) Example: R = STUDENT, A = Dept, B = Age.

  • Max = |R|, Min = 1: sab rows alag → koi duplicate nahi hatta (|R|); sab rows same → ek hi row bachti hai (1).

Kaise nikle? P ∪ Q, P ∩ Q, P − Q, Q − P

  1. P ∪ Q: P ke saare ID {1,2,3} + Q ke saare {1,3}, dohraav hata do → {1, 2, 3}.
  2. P ∩ Q: wo ID jo P aur Q dono mein hain → 1 ✔ (dono mein), 2 (sirf P), 3 ✔ → {1, 3}.
  3. P − Q: P ki wo ID jo Q mein nahi → 1 (Q mein hai ✘ hata), 2 (Q mein nahi ✔ rakho), 3 (Q mein hai ✘) → {2}.
  4. Q − P: Q ki wo ID jo P mein nahi → 1 (P mein hai), 3 (P mein hai) → koi nahi → ∅.

Dekho: P − Q = {2} lekin Q − P = ∅ . Difference commutative nahi hai (order matter karta hai).

Size rules (R aur S union-compatible)

Example R=10, S=6: ∪ → 10..16, ∩ → 0..6, R−S → 4..10.

Yaad rakho
  • ∪ aur ∩ : commutative + associative.
  • − : na commutative, na associative.
  • ∩ ko − se bana sakte ho: R ∩ S = R − (R − S)
  • Degree: result ka degree = R ka degree.
Size rules kaise nikle? (R = 10 rows, S = 6 rows)
  • ∪ max: koi row common nahi → 10 + 6 = 16. ∪ min: S poora R ke andar → R hi bachta hai → 10 (= max(|R|,|S|)).
  • ∩ max: S poora R ke andar → common = chhoti table = 6. ∩ min: kuch common nahi → 0.
  • R − S max: kuch common nahi → R poora = 10. R − S min: S ki saari 6 rows R mein → 10 − 6 = 4.
Traps
  • Union ke baad bhi duplicates nahi — set hai.
  • Columns ka count alag ho to union allowed hi nahi (error). Isliye aksar pehle π lagate hain taaki dono table mein sirf ek-do matching columns bachein.
  • “A mein hai par B mein nahi” → A − B. Direction galat mat kar dena.

6.5 · Cartesian product × aur Join ⋈ do tables ko jodna

×
Cartesian Product — sab pairs
Pehli table ki har row ko doosri table ki har row ke saath jodo.

Real-life picture

4 shirts aur 3 pants hain. Kitne outfits ban sakte hain? Har shirt × har pant = 4 × 3 = 12. Chahe wo match karein ya nahi, sab combos aate hain.

STUDENT × COURSE = har student ko har course ke saath pair karo (chahe enroll hua ho ya nahi):

Isme Neha–C1 jaisi pairs bhi hain jo asal mein exist nahi karti. Isliye product akela kaam ka nahi — iske baad condition lagate hain (= join).
Size rules
  • Rows = |R| × |S| (exactly; koi bhi khali ho to result khali).
  • Columns = degree(R) + degree(S).
  • Example: R = 7 rows, 3 cols; S = 5 rows, 2 cols → 35 rows, 5 cols.
Traps
  • Dono mein same naam ka column (jaise ID) ho to result mein dono aate hain; naam R.ID, S.ID se alag karte hain.
  • Product bahut bada ho jaata hai — real DB mein avoid karte hain; join use karte hain.

Kaise bani? STUDENT × COURSE

  1. Pehli table ki pehli row (Rahul) lo → usse COURSE ki har row (C1, C2, C3) ke saath jodo → 3 pairs.
  2. Phir Aman → 3 pairs, Priya → 3 pairs, Neha → 3 pairs.
  3. Kul pairs = 4 × 3 = 12. Har pair mein STUDENT ke 4 columns + COURSE ke 3 columns = 7 columns (grid mein jagah bachane ke liye sirf (naam, course) likha hai).
  4. Koi condition nahi lagi, isliye Neha–C1 jaisi “bekaar” pairs bhi hain.

Notation: θ, theta / equi / natural — ek chhota example

θ (theta) = join ki condition (R ⋈θ S mein R aur S ko kis shart par jodna hai). Example: R(A) = {1,2,3}, S(B) = {2,3,4}, θ = (A < B).

Join ke size rules (GATE favourite)
  • Max = |R| × |S| (jab sab rows sab se match karein).
  • Min = 0 (koi match nahi).
  • Agar common column S ki key hai aur R ka foreign key (NULL nahi) → rows = exactly |R|.

6.6 · Outer Joins ⟕ ⟖ ⟗ jo match na hue unhe bhi sambhalo

Normal (“inner”) join mein unmatched rows gayab ho jaati hain (Neha, C3). Kabhi hum unhe bhi dekhna chahte hain: “saare students dikhao, aur unke courses bhi — jinke nahi hain unka NULL”. Ye kaam outer join karta hai.

Pehle notation (R, S, “common column”)

R = left table (jo symbol ke baayein likhi hai), S = right table. Jab hum R ⟕ S likhte hain, to hamesha natural join ki tarah chalta hai: dono tables mein same naam wale column(s) = “common column” — wahi match karne ka aadhaar hai. Jis row ka common column ki value doosri table mein kisi row se barabar ho, wo matched; warna unmatched.

Counter-example (π aur ∩/−)

R = {(1, x)}, S = {(1, y)}. R ∩ S = ∅ → πA = ∅. Par πA(R) = {1}, πA(S) = {1} → ∩ = {1}. Alag! Isi tarah − ke liye. π ko ∩ ya − ke andar ghusaana nahi.

Push-down rules (optimizer ke kaam ke) kam important
  • σc(R ∩ S) = σc(R) ∩ σc(S) — True.
  • Agar c sirf R ke attributes use kare: σc(R ⋈ S) = σc(R) ⋈ S (aur × ke liye bhi) — True. Isi se “filter pehle” rule bana.
  • σc1∧c2(R ⋈ S) = σc1(R) ⋈ σc2(S) jab c1 sirf R ka aur c2 sirf S ka ho.
  • σ aur π ki adla-badli: πL(σc(R)) = σc(πL(R)) sirf tab jab c ke saare attributes L mein hon. Warna right side invalid.
  • π ko join ke neeche push karte waqt join wale columns bachake rakho.

NULL ka asar

  • σ: condition mein NULL aaye to result unknown → row select nahi hoti. e.g. σAge>20 par NULL age wali row nahi aayegi (aur Age ≤ 20 mein bhi nahi!).
  • Join: NULL = NULL bhi true nahi hota → NULL wale keys par join match nahi karta. (2026 Q42 mein Z ki NULL wali row P4 ke saath hai; P4 X/Y mein hai hi nahi, to wo yaha koi role nahi nikhaati — par NULL se join nahi hota, ye rule yaad rakho.)
  • Outer join ke NULLs = “match nahi mila”.

Kaise nikle? (chhota example)

R(ID, Age): (1, 20), (2, NULL). σAge>20(R): row 1 → 20>20 = false ✘; row 2 → NULL>20 = unknown ✘ → 0 rows. σAge≤20(R): row 1 ✔; row 2 → unknown ✘ → 1 row. Dono ko jodo to bhi 1 row hi aayi (row 2 kisi mein nahi) — NULL wali row na “>” mein, na “≤” mein. Unknown ka matlab: condition true nahi → row select nahi.

Exam rule

Jab tak question SQL na ho aur “duplicates”/“bag” na likha ho: pure RA = set semantics maan lo. Jab SQL ho: duplicates rehte hain.
