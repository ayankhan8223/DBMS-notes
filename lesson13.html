13.1 · Pehle samjho: database aakhir rakha kahan hai? disk, track, sector, block

Real-life picture: socho ek bahut badi almari (disk) jisme lakhon pages ki files rakhi hain. Tumhe ek page chahiye. Tum almari tak jaate ho (time lagta hai), sahi shelf dhoondhte ho (time lagta hai), phir page padhte ho (thoda time). Ek page ke liye itni mehnat karne ke baad, tum poori file ka ek hissa ek saath utha laate ho — kyunki dobara jaana mehnga hai.

Computer me bhi aisa hi hai: RAM bahut tez par chhoti aur mehngi hai, disk bahut badi, sasti par lakh guna dheemi. Isliye DBMS ka sabse bada rule:

Golden rule of DBMS storage

Disk se data hamesha ek poora BLOCK (page) ke roop me aata hai, ek-ek record nahi. Aur disk padhna sabse mehnga kaam hai. Isliye GATE me cost = kitne blocks padhne/likhne pade (block accesses). CPU ka time ignore karte hain.

Disk ki body

  • Platter: gol chakri jis par data magnetic roop me likha hai. Ek disk me kai platters, har ka do surfaces (upar-neeche).
  • Track: platter par ek gol ring. Sector: track ka ek tukda (sabse chhoti physical unit, jaise 512 B).
  • Block (page): OS/DBMS ke liye I/O ki unit; 1 ya zyada sectors se banta hai (jaise 4 KB). Is course me: block size = B.

Notation / matlab · disk ke letters
  • RPM = rotations per minute (platter 1 minute me kitne chakkar). Ek chakkar ka time = 60/RPM seconds; ms me chahiye to ×1000 (7200 RPM → 60/7200 = 0.00833 s = 8.33 ms).
  • Seek = arm ko track par laane ka time (ms, diya hota hai). Transfer rate = data kitni tezi se padhta hai (MB/s). 40 MB/s ≈ 40 KB per ms.
  • Transfer time (1 block) = block size ÷ transfer rate = 4 KB ÷ 40 KB/ms = 0.1 ms.
  • Sector bytes = ek sector me bytes (512 B); sectors/track, tracks/surface, surfaces = ginti.
Worked example 1 · capacity

8 surfaces, 1000 tracks/surface, 256 sectors/track, 512 B/sector.

Capacity = 8 × 1000 × 256 × 512 = 1,048,576,000 B = 1000 × 220 B = 1000 MB (binary MB).

Worked example 2 · access time

Seek = 8 ms, 7200 RPM, block = 4 KB, transfer rate = 40 MB/s (= 40 KB per ms).

  • Rotation = 60/7200 s = 8.333 ms → avg latency = 4.167 ms
  • Transfer = 4 KB / 40 KB per ms = 0.1 ms
  • Random block access = 8 + 4.167 + 0.1 = 12.27 ms
  • 100 blocks contiguous = 8 + 4.167 + 100 × 0.1 = 22.17 ms — jabki 100 random blocks = 100 × 12.27 = 1227 ms!

Yaani sequential padhna lagbhag 55 guna sasta (1227/22.17 ≈ 55.3). Isi liye sorted/contiguous files aur range scans fast hote hain.

Ab tum try karo

6000 RPM disk ka average rotational latency kitna?

Answer: 1 chakkar = 60/6000 = 10 ms; aadha = 5 ms.

13.3 · Blocking factor aur blocks ki ginti floor vs ceiling — GATE ka sabse bada formula

Analogy: ek dabbe (block) me 1000 gram jagah hai aur har laddoo (record) 180 gram ka. Kitne laddoo fit honge? 1000/180 = 5.55 — par aadha laddoo to rakh nahi sakte (maan lo toda nahi ja sakta) → 5. Ab 103 laddoo ke liye kitne dabbe? 103/5 = 20.6 — 0.6 dabba to hota nahi, poora dabba khola → 21.

B = 1000, R = 180 → har block me 5 records (900 B) + 100 B waste (laal patti).
Teen symbols jo yaad rakhne hain
  • B = block size (bytes)  |  R = record size (bytes)  |  r = total records
  • bfr (blocking factor) = ek block me kitne records = ⌊ B / R ⌋ (unspanned)
  • b = total blocks chahiye = ⌈ r / bfr ⌉
Symbols ka substituted example (wahi laddoo wala)

B = 1000 B (dabba), R = 180 B (ek laddoo), r = 103 (kul laddoo; chhota r = ginti, bada R = size).

  • bfr = ⌊B/R⌋ = ⌊1000/180⌋ = ⌊5.55⌋ = 5 records per block (unit: records/block).
  • b = ⌈r/bfr⌉ = ⌈103/5⌉ = ⌈20.6⌉ = 21 blocks.
  • Waste per block = B − bfr×R = 1000 − 900 = 100 B.

"Capacity → ⌊ ⌋ | Zaroorat (count of containers) → ⌈ ⌉". Pehle bfr (floor), phir uspar blocks (ceil). Kabhi seedha ⌈r × R / B⌉ mat likh dena unspanned me — wo spanned ka formula hai!

Worked examples

Example 1 (basic)

B = 1024, R = 100, r = 30000.

  • bfr = ⌊1024/100⌋ = ⌊10.24⌋ = 10 (waste = 1024 − 1000 = 24 B per block)
  • b = ⌈30000/10⌉ = 3000 blocks
Example 2 (record size + deletion marker)

Upar wala STUDENT record R = 53 B, B = 1000 B, r = 5000.

  • bfr = ⌊1000/53⌋ = ⌊18.87⌋ = 18 (18 × 53 = 954; 19 × 53 = 1007 > 1000 ✗)
  • b = ⌈5000/18⌉ = ⌈277.78⌉ = 278
Example 3 (block header)

B = 1000, block header = 100 B, R = 180, r = 103 (unspanned).

  • Usable = 1000 − 100 = 900 → bfr = ⌊900/180⌋ = 5 (exactly 5)
  • b = ⌈103/5⌉ = ⌈20.6⌉ = 21

Trap: pehle usable space nikalo, phir divide.

Example 4 (bahut bada)

B = 4096, R = 150, r = 1,00,000.

  • bfr = ⌊4096/150⌋ = ⌊27.3⌋ = 27 (27 × 150 = 4050)
  • b = ⌈100000/27⌉ = ⌈3703.7⌉ = 3704 (3703 × 27 = 99,981 < 1,00,000 → ek aur block)
Trap: R > B/2

B = 1000, R = 600 → bfr = ⌊1.67⌋ = 1. Har block ka 40% waste! 100 records → 100 blocks (jabki asal data sirf 60,000 B = 60 blocks ka). Isi problem ko spanned organization solve karta hai.

Worked example 5 · same data, dono tarah

B = 1000, R = 180, r = 103.

  • Unspanned: bfr = 5, b = ⌈103/5⌉ = 21 blocks.
  • Spanned (no overhead): total bytes = 103 × 180 = 18,540 → ⌈18540/1000⌉ = ⌈18.54⌉ = 19 blocks.

Ab tum try karo

B = 512, R = 200, r = 1000. Unspanned aur spanned blocks?

Answer: bfr = ⌊512/200⌋ = 2 → ⌈1000/2⌉ = 500. Spanned: ⌈200000/512⌉ = ⌈390.6⌉ = 391.

Variable-length records ka GATE style

Variable-length me question aksar kehta hai "average record size = Ravg". Tab bfr ≈ ⌊B / Ravg⌋ aur b = ⌈r / bfr⌉ hi lagate hain. Agar spanned diya ho to ⌈r × Ravg / B⌉. Jo bhi question bole wahi maano.

13.4 · Teen tarah ki files: Heap, Sorted, Hash aur har ka access-cost

Analogy: ek bade school ke student ke forms. Heap = jaise aaye waise bori me dalte gaye. Sorted = roll number ke hisaab se file me lagate gaye. Hash = roll number ki ek formula se almari ka naam nikalte hain (jaise roll mod 100 = almari number) aur seedha wahin rakhte/dhoondhte hain.

Ab sabke liye symbol: b = file ke blocks. Cost = block accesses.

(a) Heap (unordered / pile) file

  • Record kahin bhi, jaha jagah mile (aksar file ke aakhir me) rakha jaata hai.
  • Insert: aakhri block padho + record daalo + wapas likho = 2 accesses (kabhi 1, agar block memory me ho).
  • Search (koi bhi field): linear scan. Key par equality: average b/2, worst b. Non-key par equality: hamesha b (kyunki ek se zyada match ho sakte hain, poori file dekhni padegi).
  • Delete: search + record ko "deleted" mark karke block wapas likhna = search cost + 1 write.
  • Range query / ORDER BY: poori file scan (+ sorting).

(b) Sorted (sequential / ordered) file

  • Records ordering field (jaise roll) ke order me. Blocks bhi usi order me.
  • Search by ordering key: binary search on blocks → ⌈ log₂ b ⌉ accesses.
  • Range query (roll 100 se 200): pehle binary search se start, phir aage ke blocks contiguous → ⌈log₂ b⌉ + (k − 1), jaha k = matching records wale blocks.
  • Insert: sahi jagah dhoondo (binary search), phir aage ke sab records khisko: average aadhi file move → ~ b/2 reads + b/2 writes. Isliye real systems overflow/ unordered area rakhte hain aur baad me merge karte hain.
  • Sorted file par bhi non-ordering field se search karo to wahi linear scan (b/2 ya b)!

(c) Hash file (external / static hashing)

  • File ko M buckets me baanta jaata hai; bucket = ek block (ya kuch blocks). Hash function h(key) → 0 … M−1 batata hai record kis bucket me.
  • Search / insert / delete by hash key (equality): 1 block access (agar bucket me overflow nahi) — sabse tez.
  • Range query / ORDER BY: hash order destroy kar deta hai → poori file b accesses.
  • Bucket full ho to overflow chain (extra blocks) → cost badhti hai. Isliye buckets itne rakhte hain ki load 70–80% rahe.
Buckets kitne chahiye? (worked)

r = 30000, bfr = 10 (bucket = 1 block), target fill 75%.

Records per bucket = 10 × 0.75 = 7.5 → buckets = ⌈30000/7.5⌉ = 4000 buckets. (100% bharna ho to 3000.)

Notation / matlab · is table ke letters
  • b = file ke total blocks (ye lesson me pichhle example se 3000).
  • k = wo blocks jinme range query ke matching records hain (example: 50 records, bfr = 10 → k = 5).
  • M = hash file ke buckets. ≈ 1 matlab 1 block access (overflow na ho to).

Worked example · teeno ek hi file par

r = 30000, R = 100, B = 1024 → bfr = 10, b = 3000 (pichla example).

  • Heap, key equality: avg 3000/2 = 1500, worst 3000.
  • Sorted, key equality: ⌈log₂ 3000⌉ = 12 (211 = 2048 < 3000 ≤ 4096 = 212) → 12.
  • Sorted, "roll BETWEEN … " jisme 50 records match: 50 records → ⌈50/10⌉ = 5 blocks (agar poori tarah align) → 12 + (5 − 1) = 16. (Agar boundary par cut ho to 6 blocks → 17. Question jo bole wo lo.)
  • Hash with 4000 buckets: equality ≈ 1; range = poori file 3000 (ya bucket count).
Trap 1 · binary search ka exact count

Aam GATE formula: ⌈log₂ b⌉. Par sach me worst-case = ⌊log₂ b⌋ + 1. Dono sirf tab alag hote hain jab b exactly power of 2 ho (b = 1024: ⌈log₂ 1024⌉ = 10, par ⌊10⌋+1 = 11). Jo question ya course use kare wahi lagao; agar b power of 2 nahi to dono same.

Trap 2 · "sorted" par kaunsi field?

File jis field par sorted hai, sirf usi field par binary search chalta hai. Dusri field par search = linear. Aur "key" ka matlab unique; non-key par ek value ke kai records hote hain.

Kaun kis ke liye
  • Zyada insert, kabhi-kabhi full scan → Heap
  • Range aur ordered access → Sorted (ya B+ tree)
  • Sirf exact-match lookups → Hash
Ab tum try karo

Heap file ke 2400 blocks me key search ka average? Sorted file me? Answer: Heap: 2400/2 = 1200. Sorted: ⌈log₂ 2400⌉ = 12 (2048 < 2400 ≤ 4096).

13.5 · Hashing ki basic baatein hash function, collision, linear probing, chaining

Analogy: hotel ki chaabi-wali board. Guest ka room number = uska "hash". Do guests ko ek hi room number mil jaaye = collision. Ab kya karein? Do tareeke: (1) us room me ek aur bed laga do (chaining), (2) agle khali room me bhej do (open addressing / linear probing).

  • Hash table: m slots (0 … m−1). Hash function h(k) → slot number. Jaise h(k) = k mod m.
  • Collision: alag keys, same slot. (Hash collision ka matlab same key nahi — alag keys, same slot.)
  • Load factor α = n / m (n keys, m slots).
Notation / matlab · hashing ke letters
  • k = key (jaise 15). m = hash table ke slots (jaise 7). h(k) = slot number jo function deta hai: h(15) = 15 mod 7 = 1.
  • n = abhi table me keys ki ginti. α = n/m = table kitna bhara (n = 5, m = 10 → α = 0.5).
  • M (file hashing me) = buckets ki ginti; ek bucket = ek block.
  • "mod" = bhaag ka bacha hua hissa: 14 mod 10 = 4.

Linear probing step-by-step · GATE DA 2025 Q18

Question: hash table size 10 (indices 0…9), h(x) = 3x mod 10, linear probing. Initially khali. Keys insert hoti hain: 1, 4, 5, 6, 14, 15. Keys 14 aur 15 kin indices par store hongi?  (A) 2 aur 5  (B) 2 aur 6  (C) 4 aur 5  (D) 4 aur 6

  1. Sabka hash nikalo: h(1) = 3 · h(4) = 12 mod 10 = 2 · h(5) = 15 mod 10 = 5 · h(6) = 18 mod 10 = 8 · h(14) = 42 mod 10 = 2 · h(15) = 45 mod 10 = 5.
  2. Insert 1 → slot 3 khali → 3. Insert 4 → slot 2 khali → 2. Insert 5 → slot 5 → 5. Insert 6 → slot 8 → 8.
  3. Insert 14: h = 2 → bhara (4 hai) → slot 3 try: bhara (1 hai) → slot 4 try: khali → 14 ko index 4 par rakho.
  4. Insert 15: h = 5 → bhara (5 hai) → slot 6 try: khali → 15 ko index 6 par rakho.
index0123456789
key--4114515-6-

Check: 6 keys → 6 bhare slots {2, 3, 4, 5, 6, 8}; slot 0, 1, 7, 9 khali. Probes: 1 → 1, 4 → 1, 5 → 1, 6 → 1, 14 → 3 (2, 3, 4), 15 → 2 (5, 6).

Answer (derived by simulation; paper PDF me official key nahi hai)
(D) 4 and 6.  Ye hash-table ke slots hain, keys nahi: slot 4 me key 14, slot 6 me key 15.
Traps
  • Pehle poora hash table banao, order me: 14 se pehle 4 hi slot 2 par aa chuka hai; 14 slot 3 par bhi nahi ja sakta kyunki wahan 1 baitha hai.
  • Probing me wrap-around: m − 1 ke baad 0 par jaao (mod m).
  • Search me: slot khali mil jaaye to key nahi hai (jab tak delete na hua ho).
Delete in open addressing

Bas slot khali mat karo! Wahan se guzarne wali kisi aur key ki probe chain toot jaayegi. Tombstone (deleted marker) lagao: search usse paar karta hai, insert usse reuse kar sakta hai.

Expected probes (theory — GATE DA 2024 Q21 jaisa)

Open addressing me uniform hashing maan kar, load factor α < 1 par:

Formula ko padho + substitute karo

α = n/m (n keys, m slots). Unsuccessful search / insert ≈ 1/(1 − α) probes (probe = ek slot check karna). Jitna α 1 ke paas, utna bada.

  • α = 0.5 → 1/(1 − 0.5) = 2
  • α = 0.75 (150 keys, 200 slots) → 1/0.25 = 4
  • α = 0.9 → 1/0.1 = 10
MethodUnsuccessful search / insertSuccessful search
Open addressing (uniform hashing)≤ 1 / (1 − α)≤ (1/α) ln(1/(1 − α))
Linear probing kam important≈ ½ (1 + 1/(1 − α)²)≈ ½ (1 + 1/(1 − α))

Matlab: table jitna bharta jaayega, cost bahut tezi se badhegi. α = 0.5 → uniform: 2 probes; α = 0.9 → 10 probes; α = 0.99 → 100 probes. (Linear probing wale formulas sirf jaankari ke liye hain, GATE me upar wala 1/(1−α) hi poocha gaya.)

Disk wali "external hashing" me kya alag hai?
  • Slot ki jagah bucket = block; ek bucket me bfr records.
  • Collision ka matlab "bucket me jagah khatam" → overflow block chain.
  • Static hashing: M buckets fix; file badhe to overflow chains lambi, search slow. Dynamic hashing (extendible, linear hashing) bucket directory ko badhaa-ghataa kar ye theek karta hai.
  • Fir bhi sirf equality ke liye; range ke liye nahi.
Ab tum try karo

h(k) = k mod 7, table size 7, linear probing. Keys 15, 22, 8, 1, 29 order me. Final table aur total probes?

Answer: sabka hash = 1 (15 mod 7 = 1, 22 → 1, 8 → 1, 1 → 1, 29 → 1). Slots: 15 → 1 (1 probe); 22 → 2 (2 probes); 8 → 3 (3); 1 → 4 (4); 29 → 5 (5). Table = [ – , 15, 22, 8, 1, 29, – ]; total probes = 1+2+3+4+5 = 15. (Ye clustering ka extreme udaharan hai.)

Is hash table me ek element insert karne me at most ______ probes, on average lagte hain.  (A) ln(1/(1−α))  (B) 1/(1−α)  (C) (1+α)/2  (D) 1/(1+α)

PYQ 3 · GATE DA 2024 · Q16 Data structures match · 1 mark, MCQ

Column 1: (p) FIFO, (q) Lookup operation, (r) LIFO. Column 2: (i) Stacks, (ii) Queues, (iii) Hash tables. Sahi match: (p) FIFO → Queues; (q) Lookup → Hash tables; (r) LIFO → Stacks = option (A). (Hash table ka kaam hi fast lookup hai.)

✔ 100 blocks vs 60 blocks
