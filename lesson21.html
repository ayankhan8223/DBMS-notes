21.1 · Measure aur aggregate kya hain? pehle picture

Pichhle lesson mein har cube cell mein ek number tha, jaise sales = 60. Wo number measure hai, aur jab hum cells ko jodte hain (roll-up) to us par ek aggregate function (SUM, AVG, MAX...) chalta hai.

Class ke result ki analogy: Ek school mein 3 sections hain. Principal ko poore school ka total marks chahiye. Har section teacher bas apna section ka total bata de, principal teeno jod dega — poore 150 bachon ki copies dobara check karne ki zarurat nahi. Par agar principal ko poore school ka median marks chahiye, to section-wise median kaafi nahi; use sab 150 marks ek saath sort karne padenge.

Yahi cube mein hota hai. Cube ke upar ke cuboids (roll-up) neeche ke cuboids se compute karna hai, original data dobara padhe bina. Ye tabhi possible hai jab aggregate function “partial results se combine” ho sake. Isi ki 3 categories hain.

Do alag classifications (confuse mat hona)
  1. Aggregate FUNCTION ki computation: distributive / algebraic / holistic (21.2 - 21.5). Sawaal: partial results se global result nikal sakte hain?
  2. MEASURE ki additivity: additive / semi-additive / non-additive (21.6). Sawaal: kya dimensions ke upar number jodna meaningful hai?

Yaad rakhne ka sutra

Distributive = ek number se kaam. Algebraic = kuch (fixed) numbers se kaam (AVG = SUM ÷ COUNT). Holistic = poora data chahiye.   D ⊂ A, aur H = baaki sab.

21.3 · Distributive: partial results ko seedha jodo

Do stores ki sales: Store 1 = [100, 200], Store 2 = [300, 400]. Poore data ka answer partition ke answers se milao:

Distributive: ek-ek number kaafi
FunctionStore 1Store 2Combine kaiseFinal
SUM300700SUM of sums: 300 + 7001000
COUNT22SUM of counts: 2 + 24
MIN100300MIN of mins: min(100, 300)100
MAX200400MAX of maxes: max(200, 400)400
COUNT ka combiner SUM hota hai

COUNT distributive hai, par partial counts ko COUNT nahi, SUM se jodte hain (2 + 2 = 4; COUNT(2, 2) = 2 galat hota). Isliye “wahi function lagao” ka matlab hai combiner ko theek chunna. Definition mein G (combiner) F se alag ho sakta hai.

NULL ka dhyan

SQL mein COUNT(col) NULL ko ignore karta hai aur SUM bhi; partial results bhi isi tarah NULLs ko skip karke bante hain, isliye combine karne par bhi wahi answer aata hai.

21.4 · Algebraic: M numbers yaad rakho, phir formula

AVG = SUM / COUNT

Store A: [10, 20] → avg 15. Store B: [40] → avg 40. Poora data [10, 20, 40]:

Galat: averages ka average

(15 + 40) / 2 = 27.5
Store A ke 2 data points hain, B ka sirf 1; par dono ko barabar weight de diya.

Sahi: (sum, count) jodo

A = (30, 2), B = (40, 1) → total (70, 3)
AVG = 70 / 3 = 23.33
Direct: (10+20+40)/3 = 23.33 ✓

Isliye cube cell mein AVG store karne ke bajay (SUM, COUNT) store karte hain aur avg tab nikalte hain jab user ko dikhana ho.

Cube mein ek worked example

  1. Roll-up Quarter → Year: SUM = 100 + 150 = 250, COUNT = 4 + 5 = 9.
  2. AVG(Delhi, 2026) = 250 / 9 = 27.78.

Kab averages ka average sahi?

Sirf jab sab groups ka COUNT barabar ho, ya properly weighted (count se multiply karke) kiya ho. Jaise do groups 3-3 elements, averages 20 aur 30: (20 + 30)/2 = 25 sahi. Par groups 3 aur 1 elements ke hon to 25 galat.

VARIANCE aur STD-DEV (M = 3)

Population variance σ² = (Σx²)/n − (Σx/n)². Isko 3 distributive numbers (n, Σx, Σx²) se nikala ja sakta hai. Isliye algebraic (M = 3).

  2. Variance (population) = 220 / 5 − 6² = 44 − 36 = 8. Std-dev = √8 ≈ 2.83.

21.5 · Holistic: partial result kaafi nahi

Median = sorted data ka beech wala. Principal ke school wale example mein, section-wise median se poore school ka median nahi bata sakte. Ek concrete saboot dekho: do alag datasets jinke partitions ke medians bilkul same hain, par overall median alag.

Same partial medians, different overall median
Group 1Group 2Median G1Median G2Merged (sorted)Overall median
Case 11, 2, 310, 11, 122111, 2, 3, 10, 11, 12(3+10)/2 = 6.5
Case 21, 2, 32, 11, 122111, 2, 2, 3, 11, 12(2+3)/2 = 2.5

Dono cases mein (median G1, median G2) = (2, 11) hai, par global median 6.5 vs 2.5. Matlab partial medians se global median nikal hi nahi sakta; poora distribution chahiye. Isliye holistic.

Mode ka bhi yahi haal: teen groups G1 = [a, a, b], G2 = [c, c, b], G3 = [d, d, b]. Har group ka mode alag (a, c, d), par poore data ka mode b (3 baar). Partial modes b ko dikha hi nahi sakte.

COUNT(DISTINCT x): Store 1 ke customers {1, 2, 3}, Store 2 ke {2, 3, 4}. Distinct per store = 3 aur 3; par overall distinct = 4 (sum 6 galat, kyunki 2 aur 3 dono stores mein hain). Combine karne ke liye actual set yaad rakhna padta hai, jo data ke saath badhta hai. Isliye exact COUNT DISTINCT ko holistic ki tarah treat karte hain (distributive nahi).

Holistic ka asli reason

Holistic ke liye storage data ke size ke saath badhta hai (median ke liye n values, distinct count ke liye poora set), jabki algebraic mein M constant hai. Yahi dono ko alag karta hai.

Practical baat

Real systems holistic measures ko approximate karte hain (histograms, sketches) taaki cube mein store ho sakein. GATE mein bas classification yaad rakhni hai: median / mode / rank / percentile = holistic.

GATE trap

“Median ya mode ko partitions se compute kar sakte hain?” → Nahi (holistic). “AVG distributive hai?” → Nahi, algebraic (ek number kaafi nahi, SUM aur COUNT dono chahiye). “MAX−MIN distributive?” → Nahi, algebraic (M = 2).

Ek alag sawaal: kya measure ko dimensions ke upar SUM karna meaningful hai? (Ye function ki nahi, measure ki property hai.)

Dono classifications ka rishta

Distributive/algebraic/holistic = function ke baare mein. Additive/semi/non = measure ke baare mein. Margin % ko SUM karna galat (non-additive), par uska sahi computation algebraic hai: do distributive pieces (SUM profit, SUM revenue) aur ek division.

21.8 · Cell counts, sparse aur dense cubes

Cube ka size samajhne ke liye cells ginna aana chahiye. Maano n dimensions hain, aur dimension i ke di distinct values (no hierarchy).

CheezFormulaKyun
Base cuboid ke maximum cellsd1 × d2 × ... × dnHar dimension se ek value chun ke ek cell
Koi bhi cuboid (dimensions ka subset S)Πi∈S di (max)Sirf S ki dimensions group-by mein
Poore cube (saare cuboids) ke max cellsΠ(di + 1)Har dimension par di values ya * (ALL): (d+1) choices
Hierarchy ke saath total cells (max)Πi (Σlevels membersi + 1)Har dimension par kisi bhi level ka koi member ya *

Worked example 1

Dimensions A, B, C mein d = 100, 50, 20 values. Fact table mein N = 1000 tuples (distinct combinations).

  1. Base cuboid max cells = 100 × 50 × 20 = 100,000. Density = 1000 / 100,000 = 1% → sparse.
  2. Poore cube max cells = 101 × 51 × 21 = 5151 × 21 = 108,171.
  3. Non-empty cells ka upper bound har cuboid mein min(N, product of d): ABC = min(1000, 100000) = 1000; AB = min(1000, 5000) = 1000; AC = min(1000, 2000) = 1000; BC = min(1000, 1000) = 1000; A = 100; B = 50; C = 20; () = 1.
  4. Total ≤ 4 × 1000 + 100 + 50 + 20 + 1 = 4171 non-empty cells, jab ki possible cells 108,171. Cube bahut sparse hai.
Density

Density = non-empty cells / total possible cells. Dense cube (density zyada): array storage (MOLAP) theek. Sparse cube (kam density): array mein bahut khali jagah waste hoti hai; isliye sparse representation (hash, (index, value) pairs, compression) ya ROLAP use karte hain. Higher-dimension aur zyada member counts = zyada sparse.

Worked example 2 (classic GATE-style)

Cube C ki n dimensions hain, base cuboid mein har dimension ki exactly p distinct values hain, koi hierarchy nahi. Cells ka maximum aur minimum?

SawaalAnswerKaise
Base cuboid ke max cellspnHar combination non-empty
Base cuboid ke min cellspHar dimension ki p values dikhni chahiye; ek cell mein har dimension ki ek value hoti hai, isliye kam se kam p cells
Poore cube C ke max cells(p + 1)nHar dimension par p values ya *
Poore cube C ke min cellsp(2n − 1) + 1Base mein p cells “diagonal” rakho (kisi do cells ki koi value same nahi). Tab har cuboid jis mein ≥ 1 dimension hai uski exactly p cells; apex 1 cell. Aise 2n − 1 cuboids.

Number check (n = 2, p = 3): max = 42 = 16 (9 + 3 + 3 + 1). Min: base cells (1,1), (2,2), (3,3) → (D1) 3 cells, (D2) 3 cells, apex 1 ⇒ 3 + 3 + 3 + 1 = 10 = 3 × (4 − 1) + 1 ✓.

Worked example 3 (hierarchy ke saath total cells)

Time: Quarter (8 members), Year (2 members). Location: City (6), Country (2). Total cells (max) in poora multi-level cube = (8 + 2 + 1) × (6 + 2 + 1) = 11 × 9 = 99.

Trap

Poore cube ke cells mein * ko ek extra value gino (d+1), warna 2n cuboids ke cells ka total galat aayega. Aur “cuboids ki sankhya” (2n ya Π(L+1)) alag cheez hai “cells ki sankhya” (Π(d+1)) se.

Iceberg cube (brief)

Sparse cube mein bahut saari cells ka count / sum bahut chhota hota hai aur kisi kaam ka nahi. Iceberg cube sirf wahi cells store karta hai jinka aggregate ek threshold se upar ho (jaise HAVING COUNT(*) ≥ 100). Jaise iceberg ka sirf upar ka hissa dikhta hai. COUNT jaise measures mein agar ek cell threshold se neeche hai to uske saare descendant cells (aur detailed) bhi neeche honge, isliye unhe compute hi nahi karte (pruning, Apriori jaisa). Ye cube computation ka optimization hai.

SELECT city, product, COUNT(*), SUM(sales)
FROM Facts GROUP BY CUBE (city, product)
HAVING COUNT(*) >= 100;   -- iceberg condition

21.9 · GATE-style problems categorization + computation

PYQ status

GATE DA 2024, 2025 aur 2026 ke papers mein distributive/algebraic/holistic ya additivity par koi seedha sawaal nahi aaya (data-warehouse ke 3 sawaal sab Lesson 20 mein hain). Syllabus mein “measures: categorization and computations” hai, isliye niche ke sawaal original, syllabus ke hisaab se banaye gaye hain aur har answer haath se verify kiya hai.

Computation

C1. G1 = [1, 3], G2 = [5, 7, 9]. Combined population variance partial stats se nikalo.
Solution: G1 = (n 2, Σx 4, Σx² 10); G2 = (3, 21, 25 + 49 + 81 = 155). Total (5, 25, 165). Mean = 5. Var = 165/5 − 5² = 33 − 25 = 8. Check: deviations from 5: 16, 4, 0, 4, 16 = 40; 40/5 = 8 ✓.

C2. A = [1, 5, 9], B = [2, 3]. Medians 5 aur 2.5; kya inka average 3.75 overall median hai?
Solution: Merged sorted: 1, 2, 3, 5, 9 ⇒ median = 3 ≠ 3.75. Isliye galat; median holistic hai.

C3. Poore data ke liye N = 20 tuples, d = (10, 20, 30). Poore cube ke max cells aur base cuboid ke max cells?
Solution: base max = 10 × 20 × 30 = 6000; poore cube = 11 × 21 × 31 = 231 × 31 = 7161. Par kyunki N = 20 hi tuples hain, base cuboid mein non-empty ≤ 20 (bahut sparse).

C4. n = 3, p = 4 (har dimension ki 4 values). Max aur min cells in C?
Solution: max = 53 = 125; min = 4 × (23 − 1) + 1 = 4 × 7 + 1 = 29.

21.10 · Practice questions 12, answers ke saath

1. (MCQ) Kaun-sa holistic hai? (a) SUM (b) AVG (c) MEDIAN (d) MAX
✔ (c) MEDIAN
2. (MCQ) AVG kis category ka hai aur kyun?
✔ Algebraic; AVG = SUM / COUNT, 2 distributive values (M = 2).
Distributive nahi kyunki ek number kaafi nahi.
3. (MSQ) Distributive functions chuno: COUNT, STDDEV, MIN, MODE, SUM
✔ COUNT, MIN, SUM
STDDEV algebraic, MODE holistic.
4. Group 1: 2 sales, avg 50. Group 2: 8 sales, avg 100. Combined avg?
✔ (2 × 50 + 8 × 100) / 10 = 900 / 10 = 90
Simple average 75 galat.
5. Store A balance (end of day) Mon 100, Tue 150. Total “balance across the week” ke liye 250 kyun galat?
✔ Balance semi-additive hai: time par SUM meaningless; AVG (125) ya last (150) lo.
6. Store 1 revenue 200 profit 50; Store 2 revenue 800 profit 100. Overall profit margin?
✔ (50 + 100) / (200 + 800) = 150 / 1000 = 15%
Margins ka average = (25% + 12.5%)/2 = 18.75% galat.
7. Ek cube mein har cell ka (sum, count) stored hai. Kya median nikal sakte hain? Kyun?
✔ Nahi; median holistic hai, (sum, count) se distribution ka pata nahi chalta.
8. Customers: Store X {1, 2, 3, 4}, Store Y {3, 4, 5}. COUNT(DISTINCT customer) per store aur overall?
✔ 4, 3 aur overall 5 (sum 7 galat)
Union = {1, 2, 3, 4, 5}.
9. 3 dimensions d = 4, 5, 6. Base cuboid max cells? Poore cube max cells?
✔ 4 × 5 × 6 = 120; 5 × 6 × 7 = 210
10. Same cube mein N = 30 non-empty tuples. Kya base cuboid dense hai? Density?
✔ Density = 30 / 120 = 25%; sparse-ish (upper bound se kam).
11. Variance ke liye kaun si 3 distributive quantities chahiye?
✔ n (COUNT), Σx (SUM), Σx² (SUM of squares)
Population variance = Σx²/n − (Σx/n)².
12. (MCQ) 2 dimension cube, har dimension ki p = 5 values. Poore cube ka minimum cells?
✔ 5 × (22 − 1) + 1 = 16
Diagonal: (D1) 5, (D2) 5, base 5, apex 1 = 16.
13. Iceberg cube kya store karta hai?
✔ Sirf wahi cells jinka aggregate (jaise COUNT) threshold se zyada/barabar ho.
Lesson 21 cheat box
  • Distributive: SUM, COUNT (combiner = SUM), MIN, MAX. Algebraic: AVG (sum, count), VAR / STDDEV (n, Σx, Σx²), RANGE, min_N / max_N. Holistic: MEDIAN, MODE, RANK, PERCENTILE, exact COUNT DISTINCT.
  • Algebraic = constant M numbers per partition. Holistic = storage data ke saath badhta hai.
  • Averages ka average galat jab tak weights (counts) barabar na hon: hamesha (Σsum) / (Σcount).
  • Additive (units) / semi-additive (balance, inventory: time par SUM nahi) / non-additive (ratios, prices: numerator & denominator alag jodo).
  • Cells: base = Πdi; poora cube = Π(di + 1); n dims, p values: max (p+1)n, min p(2n − 1) + 1. Density = non-empty / possible. Iceberg = threshold se upar wale cells.
