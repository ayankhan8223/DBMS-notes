8.1 · SQL kya hai? database se baat karne ki bhasha

Library counter analogy 📚

Librarian ko aap bolte ho: “Computer Science shelf se, jin books ka price 500 se kam hai, unke naam de do, sasti wali pehle.” Aap ye nahi batate ki librarian shelf tak kaise jayega — bas kya chahiye. SQL (Structured Query Language) bilkul yahi hai: declarative language.

Andar se database aapki query ko Relational Algebra mein badalta hai (σ, π, ×, ⋈ — Lesson 6) aur sabse sasta tareeka chuna jaata hai.

8.3 · DDL — table banana: CREATE TABLE & constraints structure ki rules

Analogy: CREATE TABLE ek form ka design hai: kaunse columns, kaisi values, kaunsi rules. Form chhapne ke baad hi entries (INSERT) bharte hain.

Poora example (hamari tables ka CREATE)

CREATE TABLE STUDENT (
  ID    INT PRIMARY KEY,
  Name  VARCHAR(30) NOT NULL,
  Dept  VARCHAR(5) DEFAULT 'CSE',
  Age   INT CHECK (Age >= 16)
);
CREATE TABLE COURSE (
  CID     CHAR(2) PRIMARY KEY,
  Title   VARCHAR(20) UNIQUE NOT NULL,
  Credits INT CHECK (Credits BETWEEN 1 AND 6)
);
CREATE TABLE ENROLL (
  ID   INT,
  CID  CHAR(2),
  PRIMARY KEY (ID, CID),
  FOREIGN KEY (ID)  REFERENCES STUDENT(ID) ON DELETE CASCADE,
  FOREIGN KEY (CID) REFERENCES COURSE(CID)
);

Kaun si operation kab violation karti hai? (Integrity check — bahut poochha jaata hai)

OperationParent table (referenced, e.g. STUDENT)Child table (referencing, e.g. ENROLL)
INSERTkabhi FK violate nahi (sirf PK/NOT NULL/CHECK)violate kar sakta hai — FK value parent mein honi chahiye
DELETEviolate kar sakta hai — child rows orphan ho jayengi → reject / CASCADE / SET NULLkabhi nahi
UPDATEkey badli to (orphan) — reject / CASCADEFK column badla to nayi value parent mein honi chahiye
ON DELETE / ON UPDATE actions
  • NO ACTION / RESTRICT (default): parent delete/update reject.
  • CASCADE: parent ke saath child rows bhi delete/update.
  • SET NULL: child ka FK column NULL ho jaaye (column NULL-able ho).
  • SET DEFAULT: child FK = default value.
Table ko badalna / hatana
  • ALTER TABLE STUDENT ADD Email VARCHAR(40); — column jodo (purani rows mein NULL).
  • ALTER TABLE STUDENT DROP COLUMN Email;
  • DROP TABLE T; — structure + data dono ud gaye.
  • TRUNCATE TABLE T; — saari rows ud gayi, structure bacha (DDL; WHERE nahi).
  • DELETE FROM T; — saari rows ud gayi (DML; WHERE de sakte ho).

Q. Agar ENROLL(ID, CID) ka FK ID → STUDENT(ID) SET NULL pe ho aur PRIMARY KEY (ID, CID) bhi ho, to kya STUDENT delete hone par SET NULL chalega?

Answer: Nahi — ID primary key ka hissa hai, NULL ho hi nahi sakta; delete reject ho jaayega. SET NULL sirf tab chalega jab FK column NULL-able ho.

AVG ka sabse bada trap

NULL ko 0 maan liya to average = 360000 ÷ 7 = 51428.57 ❌. Sahi: NULL ko ignore karo → 360000 ÷ 6 = 60000 ✔. Yaad: AVG(col) = SUM(col) / COUNT(col), na ki COUNT(*) se.

Khali table par

Koi row WHERE se na bachi to bhi aggregate query 1 row deti hai: COUNT = 0, par SUM, AVG, MIN, MAX = NULL (0 nahi!).

SELECT COUNT(*) AS c, SUM(Salary) AS s, MAX(Salary) AS m FROM EMP WHERE Salary > 100000

Aggregate ke niyam

  • GROUP BY ke bina aggregate wali query ka output hamesha ek row. Aise mein SELECT mein plain column mixed nahi kar sakte: SELECT Dept, COUNT(*) FROM EMP ❌ invalid (Dept kaunsi row ka?).
  • WHERE mein aggregate nahi: WHERE Salary > AVG(Salary) ❌ — WHERE rows par hai, aggregate rows ke set par. Iske liye HAVING ya subquery (Lesson 9).
  • Aggregate ke andar aggregate nahi (standard): MAX(COUNT(*)) ❌.
  • COUNT(1) = COUNT(*) (constant kabhi NULL nahi).

Min / max rows (GATE counting)

R mein m rows, S mein n rows (dono mein duplicates nahi, union-compatible):

  • R ∪ S: max(m,n) … m+n
  • R ∩ S: 0 … min(m,n)
  • R − S: 0 … m (minimum m−n ho jab S ⊆ R, agar m ≥ n)

Bag versions: UNION ALL = exactly m+n.

Traps
  • Set operators by default duplicates hatate hain (SELECT ke ulta!). ALL likho to rakhte hain.
  • Precedence: INTERSECT, UNION/EXCEPT se pehle; bracket lagao.
  • EXCEPT symmetric nahi: P−Q ≠ Q−P.
  • NULLs set-ops mein equal maane jaate hain (do NULL = ek).
Ab tum try karo

Q. R mein 5 rows (3 baar 'x', 2 baar 'y'), S mein 4 rows (1 baar 'x', 3 baar 'y'). R INTERSECT ALL S aur R EXCEPT ALL S ki rows?

Lesson 8 cheat box — last-night revision
  • Likhne ka order: SELECT [DISTINCT] → FROM → WHERE → GROUP BY → HAVING → ORDER BY. Chalne ka order: FROM → WHERE → GROUP BY → HAVING → SELECT → (DISTINCT) → ORDER BY → LIMIT.
  • SQL = bag (duplicates rehte hain); DISTINCT hatata hai; set-ops (UNION/INTERSECT/EXCEPT) by default hatate hain, ALL rakhta hai. Multiplicity: UNION ALL m+n, INTERSECT ALL min, EXCEPT ALL max(m−n,0).
  • WHERE = row filter (no aggregates). HAVING = group filter (aggregates ok). GROUP BY ke saath SELECT mein sirf group cols + aggregates.
  • COUNT(*) sab rows; COUNT(col) non-NULL; SUM/AVG/MIN/MAX NULL ignore; AVG = SUM/COUNT(col). Khali set: COUNT = 0, baaki NULL. Aggregate without GROUP BY = 1 row.
  • NULL comparison = UNKNOWN; WHERE sirf TRUE rakhta hai; IS NULL use karo; NOT IN + NULL ⇒ koi row nahi; CHECK UNKNOWN ko pass karta hai.
  • LIKE: % = 0+ chars, _ = exactly 1. BETWEEN inclusive. NOT > AND > OR.
  • PK: unique + NOT NULL (1 per table). UNIQUE: NULL ok. FK: NULL ok, parent mein hona chahiye. FK violate: child INSERT/UPDATE, parent DELETE/UPDATE. Actions: NO ACTION, CASCADE, SET NULL, SET DEFAULT.
  • DELETE (DML, WHERE) vs TRUNCATE (DDL, sab rows) vs DROP (poori table). UPDATE/DELETE bina WHERE = saari rows.
