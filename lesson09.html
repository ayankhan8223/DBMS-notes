Purani (comma) style = CROSS + WHERE

GATE ke purane sawaalon mein aksar “FROM A, B WHERE A.x = B.x” aata hai (2024 Q31, 2026 Q51 bhi). Ye wahi INNER JOIN hai: pehle product, phir WHERE se filter.

SELECT S.Name, E.CID
FROM STUDENT S, ENROLL E
WHERE S.ID = E.ID;
SELECT S.Name, E.CID
FROM STUDENT S
JOIN ENROLL E ON S.ID = E.ID;

Dono ka result bilkul same. Agar comma-style mein WHERE ki join condition bhool gaye to product (20 rows) milega.

USING keyword

Agar dono tables mein join column ka naam same ho to JOIN ENROLL E USING (ID) likh sakte ho. Result mein ID ek hi baar aata hai (natural join jaisa), par sirf tum bataye columns par match hota hai.

Kaise bani? LEFT JOIN: STUDENT ⟕ ENROLL (5 steps)
  1. Matching column: S.ID = E.ID. Left (preserved) table = STUDENT (iski koi row nahi girni chahiye).
  2. Inner rows pehle: wahi 5 matched pairs jo 9.2 mein bani (Rahul-C1, Rahul-C2, Aman-C1, Priya-C1, Priya-C2).
  3. Left ki unmatched rows dhoondo: Neha (ID = 4) — ENROLL mein ID 4 ki koi row nahi, isliye inner join mein uska partner nahi mila.
  4. NULL se padding: Neha ke liye ENROLL ke saare columns (ID, CID) ki jagah NULL daalo → (Neha, NULL).
  5. Jodo: 5 inner + 1 padded = 6 rows ✔. Column order: pehle left table ke columns, phir right ke.

Formula

FULL = LEFT ∪ RIGHT  ·  inner ⊆ left ⊆ full  ·  left ≥ |L| hamesha (har left row kam se kam ek baar aati hai).

Kaise bani? FULL JOIN: S (STUDENT) aur M (MARKS) — 5 steps
  1. Matching: S.ID = M.ID. Dono tables ki saari rows bachani hain, chahe match mile ya na mile.
  2. Inner pairs (jinka jodi mila): S ki ID 1 (Rahul) → M mein ID 1 hai (80) ✔ → (1, Rahul, 1, 80). S ki ID 2 (Aman) → M mein ID 2 nahi ✘. S ki ID 3 (Priya) → M mein ID 3 hai (75) ✔ → (3, Priya, 3, 75). Inner = 2 rows.
  3. Left-extra (S ki akeli): Aman (ID 2). M mein ID 2 nahi, to M ke columns (mID, Marks) NULL bharo → (2, Aman, NULL, NULL).
  4. Right-extra (M ki akeli): ID 4 (marks 60). S mein ID 4 nahi, to S ke columns (sID, Name) NULL bharo → (NULL, NULL, 4, 60).
  5. Jodo: inner 2 + left-extra 1 + right-extra 1 = 4 rows ✔. (LEFT JOIN = 2 + 1 = 3 rows, RIGHT JOIN = 2 + 1 = 3 rows, FULL = dono ko jodke 4.)

Q. STUDENT LEFT JOIN ENROLL ON … WHERE E.CID IS NULL aur … ON … AND E.CID IS NULL — dono ka result kya?

Answer: Pehla = {Neha}. Doosre mein ON me condition false (CID NULL kisi match mein nahi) → har student NULL ke saath aata hai = 4 rows.

Kaise bani? ON vs WHERE — dono query row-by-row
  1. Filter ON mein: match condition = (ID same AND CID = 'C2'). Rahul: (1,C1) ✘, (1,C2) ✔ → (Rahul, C2). Aman: (2,C1) ✘ → koi partner nahi → padding (Aman, NULL). Priya: (3,C2) ✔ → (Priya, C2). Neha: partner nahi → (Neha, NULL). Kul 4 rows (LEFT JOIN har left row bachata hai).
  2. Filter WHERE mein: pehle poora LEFT JOIN (6 rows: Rahul-C1, Rahul-C2, Aman-C1, Priya-C1, Priya-C2, Neha-NULL), phir E.CID = 'C2' har row par: sirf Rahul-C2 aur Priya-C2 TRUE; baaki FALSE ya UNKNOWN (NULL) → hat gayi → 2 rows.

Natural join ke 3 traps
  1. Same naam = match, chahe matlab alag ho. Agar STUDENT aur COURSE dono mein Name hota to wo bhi compare hota.
  2. Koi common column nahi to natural join = CROSS JOIN. Jaise STUDENT NATURAL JOIN COURSE → 4 × 3 = 12 rows (STUDENT: ID,Name,Dept,Age; COURSE: CID,Title,Credits — common kuch nahi).
  3. Baad mein koi column add/rename ho gaya to query ka matlab chupchaap badal jaata hai — isliye real life mein avoid karte hain.
Kaise bani? NATURAL JOIN STUDENT, ENROLL
  1. Common columns dhoondo: STUDENT(ID, Name, Dept, Age) aur ENROLL(ID, CID) → same naam sirf ID.
  2. Natural join = us common column par equality (S.ID = E.ID) → wahi 5 matched pairs jo 9.2 mein.
  3. Columns: common ID ek hi baar (pehle), phir STUDENT ke baaki (Name, Dept, Age), phir ENROLL ke baaki (CID). Rows 5 (Neha ka match nahi).

Uncorrelated vs Correlated — sabse zaroori fark

Uncorrelated (independent)

Inner query akeli bhi chal sakti hai — outer query ki kisi cheez ko use nahi karti.

Chalti hai sirf ek baar; uska result outer query ko de diya jaata hai.

Correlated (dependent)

Inner query outer ki current row ka column use karti hai (jaise E.ID = S.ID). Akeli nahi chal sakti.

Chalti hai outer ki har row ke liye ek baar (logically). Optimizer andar se rewrite kar sakta hai par answer wahi aana chahiye.

Execution: bahar se andar, row-by-row (nested loop).

Joins
  • INNER: sirf match · LEFT/RIGHT: ek taraf poori · FULL: dono · CROSS: |L|·|R|.
  • Rows = Σ (count in L) × (count in R) per key. NULL kisi se match nahi.
  • Left rows ≥ |L|; FK→PK (NOT NULL) inner join = |R_fk-table|.
  • NATURAL JOIN, koi common col nahi → CROSS.
  • Anti-join: LEFT JOIN … WHERE r.key IS NULL.
  • LEFT JOIN + WHERE on right column ⇒ inner join ban jaata hai. Filter ON mein rakho.
  • Self-join: alias zaroori; a.id < b.id se pairs ek baar.
Set ops

UNION / INTERSECT / EXCEPT dedupe karte hain; ALL versions: m+n, min(m,n), max(0,m−n). Set ops mein NULL = NULL.

Views

Virtual table = stored query. Updatable: single table, no DISTINCT/GROUP BY/aggregate. WITH CHECK OPTION ghost rows rokta hai. Materialized = stored result (refresh chahiye).

NULL / 3-valued logic
  • NULL se comparison → UNKNOWN; WHERE sirf TRUE rakhta hai.
  • AND = min, OR = max, NOT U = U (T=1, U=½, F=0).
  • = NULL hamesha galat; IS NULL use karo.
  • NOT IN + NULL in subquery ⇒ khali result. NOT EXISTS use karo.
  • COUNT(*) NULL ginta hai, COUNT(col) nahi; AVG/SUM NULL ignore.
  • GROUP BY, DISTINCT, UNION mein NULLs equal.
  • CHECK mein UNKNOWN pass hota hai.
Subqueries
  • Uncorrelated: ek baar chalti hai (inside-out). Correlated: har outer row ke liye.
  • x = ANY ≡ IN · x <> ALL ≡ NOT IN · > ALL ≡ > MAX · > ANY ≡ > MIN. ALL(empty)=TRUE, ANY(empty)=FALSE.
  • EXISTS kabhi UNKNOWN nahi.
  • Division (for all) = NOT EXISTS ( … NOT EXISTS ( … )) ya GROUP BY/HAVING COUNT = total.
  • FROM wale subquery ko alias chahiye; scalar subquery 1 row return kare.
