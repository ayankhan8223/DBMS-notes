GATE DA 2026 · Q.17 (1 mark, MCQ) — Candidate keys from FDs

QUESTION (as printed in the paper)

Let R(A,B,C,D,E) be a relational schema with functional dependency set F = {A→BC, CD→E, E→A}. Which of the following statements is correct?

(A) AD, ED and CD are the only candidate keys of R.
(B) AD and ED are the only candidate keys of R.
(C) A, E and CD are the only candidate keys of R.
(D) A and CD are the only candidate keys of R.

Step-by-step solution

Notation / matlab

R(A,B,C,D,E) = table ke 5 columns. F = given FDs. A→BC = A ki value se B aur C tay ho jaate hain. X+ (closure) = X se shuru karke FDs lagate-lagate jo saare attributes mil jaayein. Candidate key = sabse chhota attribute-set jiska closure poora R ho. Example: A+: A → B, C; ab C ka akela koi FD nahi (CD→E ko D chahiye) ⇒ {A,B,C}.

  1. Kaun kabhi RHS me nahi? RHS ke attributes: B, C (from A→BC), E, A. D kisi RHS me nahi aata, isliye D ko koi derive nahi kar sakta ⇒ D har candidate key me hoga.
  2. Closure of D alone: D+ = {D}. Kuch nahi. Isliye D ke saath kuch aur chahiye.
  3. D ke saath ek-ek attribute try karo:
TryClosure stepsResultKey?
ADA→BC gives B,C; now C,D → E{A,B,C,D,E}Yes (A+ ={A,B,C}, D+ ={D}: dono chhote fail)
EDE→A; A→BC; now have all{A,B,C,D,E}Yes (E+={E,A,B,C}: D missing)
CDCD→E; E→A; A→BC{A,B,C,D,E}Yes (C+={C}, D+={D})
BDno FD has LHS ⊆ {B,D}{B,D}No
Candidate key = chhota-se-chhota set jiska closure poora R ho

4. Aur koi key? Har key me D hai. 2-size keys: AD, ED, CD mil gayi, BD fail. Ab D ke saath A, C ya E me se koi bhi aaye to wo set AD / CD / ED ka superset hoga, yaani minimal nahi. Bacha sirf {B, D}, jo upar fail ho chuka hai. Isliye aur koi key nahi: keys = AD, ED, CD (exactly 3).

Shortcut

“A, E, CD” jaise options me D missing hai ⇒ turant galat (D to kisi RHS me hai hi nahi). Option (A) bachta hai.

ANSWER (derived): (A) AD, ED and CD are the only candidate keys
Trap
A akela ya E akela key nahi hai: A+={A,B,C} (D, E nahi). D hamesha chahiye.

GATE DA 2026 · Q.32 (1 mark, NAT) — B+ tree capacity

QUESTION (as printed in the paper)

In a relational database, a B+ Tree Index is to be constructed for a relation on a key field. In a B+ Tree, a Node Pointer points to a sub-tree and a Data Record Pointer points to a block of database records. Let Node size = 4096 bytes, Node Pointer size = 10 bytes, Search Key Field size = 11 bytes and Data Record Pointer size = 12 bytes. The maximum number of Node Pointers that can be present in a non-leaf node of the B+ Tree is ________. (Answer in integer)

Step-by-step solution

Notation (Lesson 15 wale letters)

B = node size = 4096 B. P = node pointer = 10 B (child ki taraf). K = search key = 11 B. Pr = data record pointer = 12 B. p = ek non-leaf node me node pointers ki max sankhya (order) — yehi sawaal ka jawab hai.

Picture

Non-leaf node (p pointers): [P1 | K1 | P2 | K2 | … | Kp−1 | Pp] → p node pointers, p−1 keys (pointers hamesha keys se 1 zyada). Total bytes = p×P + (p−1)×K. Non-leaf node me data record pointer nahi hota (wo sirf leaf me hota hai). 12 bytes ek distraction hai.

  1. Size inequality (pP + (p−1)K ≤ B): 10p + 11(p − 1) ≤ 4096
  2. 10p + 11p − 11 ≤ 4096  ⇒  21p ≤ 4107 (11 dono taraf jod diya)
  3. p ≤ 4107 / 21 = 195.57…  ⇒  pmax = 195 (floor, kyunki pointer aadha nahi hota)
  4. Check: p=195: 10×195 + 11×194 = 1950 + 2134 = 4084 ≤ 4096 ✓. p=196: 1960 + 11×195 = 1960 + 2145 = 4105 > 4096 ✗.
ANSWER (derived): 195
Trap
Leaf node ka formula alag hai: L×(K + Pr) + Pn ≤ B (L = leaf me max keys, Pn = next-leaf pointer). Yahan question non-leaf ka hai.

GATE DA 2026 · Q.41 (2 marks, MCQ) — B+ tree insertion

QUESTION (as printed in the paper)

Consider a B+ Tree where the maximum number of key values in each leaf node is 2 and the maximum number of pointers in each non-leaf node is 3. Let the content of the B+ Tree be as shown in the figure. Which of the following options denotes the key value(s) stored in the root node after inserting a key value 3 in the given B+ Tree?

(A) 5
(B) 8
(C) 3 and 5
(D) 3, 5 and 8
Figure (redrawn): root [5 | 8]; leaves [1 | 5] → [7 | 8] → [9 | 12] → NULL

Step-by-step solution

Rules from the question
  • Leaf: max 2 keys. Non-leaf: max 3 pointers ⇒ max 2 keys.
  • Figure ka convention: separator = left subtree ka maximum key (root key 5 = leaf [1|5] ka max; 8 = leaf [7|8] ka max). Matlab left child me keys ≤ separator.
  1. 3 kahan jayega? 3 ≤ 5, isliye leftmost leaf [1 | 5] me. Sorted: [1, 3, 5] → 3 keys > 2 ⇒ leaf overflow.
  2. Leaf split: [1, 3] aur [5]. Left leaf ka max = 3, isliye parent ko naya separator 3 milta hai.
  3. Root ab: keys [3, 5, 8], pointers 4 > 3 ⇒ root bhi overflow.
  4. Root split: beech wala key 5 upar jaata hai (new root). Left node [3] (children [1|3], [5]); right node [8] (children [7|8], [9|12]).
  5. New root = [5]. Dekho: left subtree ka max = 5 ✓.
After inserting 3: leaf split → parent overflow → root split. Root = 5, height 2 se 3.
Convention se farak nahi padta

Agar leaf ko [1] aur [3, 5] split karte (ya right-biased convention use karte), tab bhi root overflow hota aur beech wala key 5 hi upar jaata. Isliye answer robust hai: 5.

ANSWER (derived): (A) 5
Trap
Root me [3, 5, 8] rakhna galat hai: root ke max 3 pointers hain, matlab max 2 keys. Overflow ka matlab split.

Notation / matlab (practice ke letters)
  • B = block size, R = record size, r = #records, b = #data blocks, bfr = records per block = ⌊B/R⌋; bfri = index entries per block. Example: B=1024, R=100 ⇒ bfr = 10; r=10,000 ⇒ b = ⌈10000/10⌉ = 1000.
  • P = pointer size, K = key size, Pr = record pointer, Pn = next-leaf pointer, p = B+ tree order (max node pointers), L = max keys in a leaf (Lesson 15 wale letters).
  • X+ = closure of X (X se jo-jo milta jaye), F = FDs ka set, A→B = A ki value se B ki value tay.
  • Li = dimension i ke levels (ALL ke bina), di = dimension i ki distinct values, N = population size, n = sample size, k = sampling gap N/n.

A. ER, relational model, keys (L1–5)

P1 ER mapping An ER diagram has entities Doctor, Patient, Medicine and a ternary relationship Prescribes among all three (many-to-many-to-many). Minimum number of relations in the relational schema?
✓ 4
Three entity relations + one relation for the n-ary relationship (key = union of the three keys). Ternary M:N:N cannot be folded into any entity.
P2 Foreign key Dept(did PK) has did = 1, 2, 3. Emp(eid PK, did FK → Dept.did ON DELETE CASCADE) has rows (e1,1), (e2,1), (e3,2), (e4,NULL), (e5,3), (e6,3). After executing DELETE FROM Dept WHERE did = 1, how many rows remain in Emp?
✓ 4
Cascade deletes the 2 rows with did = 1 (e1, e2). e4 has NULL (no reference) and stays. Remaining: e3, e4, e5, e6 = 4. (With ON DELETE SET NULL it would stay 6; with no action the delete is rejected.)
P3 Relational model R has degree 5 and cardinality 12; S has degree 3 and cardinality 7. For R × S, what are the degree and the cardinality?
✓ Degree 8, cardinality 84
Degrees add (5+3), tuple counts multiply (12×7). Degree = columns, cardinality = rows.

B. Relational algebra and TRC (L6–7)

P4 RA counting R has 5 tuples, S has 4 tuples, both union-compatible, 2 tuples common. Find |(R − S) × (R ∪ S)|.
✓ 21
|R − S| = 5 − 2 = 3. |R ∪ S| = 5 + 4 − 2 = 7. Product = 3 × 7 = 21.
P5 Natural join R(A,B) has 6 tuples. S(B,C) has 5 tuples and B is the primary key of S. R.B is a NOT NULL foreign key referencing S.B. How many tuples does R ⋈ S have?
✓ 6
Each R tuple finds exactly one S tuple (B is unique in S and every R.B exists in S). So the join has exactly |R| = 6 tuples. (Without the FK it could be anywhere from 0 to 6.)
P6 Division Completed(Student, Course) = {(s1,c1), (s1,c2), (s2,c1), (s3,c1), (s3,c2), (s3,c3)}; Required(Course) = {c1, c2}. How many tuples in Completed ÷ Required?
✓ 2
Students who completed all required courses: s1 (c1,c2) yes; s2 (only c1) no; s3 (c1,c2,c3 ⊇ {c1,c2}) yes. Result {s1, s3}.
P7 TRC Emp(id) has ids 1,2,3,4,5. Dept(did, mgr) has rows (d1,1), (d2,3), (d3,3). How many tuples does { t | t ∈ Emp ∧ ¬∃d ∈ Dept (d.mgr = t.id) } return?
✓ 3
Managers present: {1, 3}. Employees that are NOT managers: 2, 4, 5. Answer 3. (Duplicate manager 3 does not matter.)

C. SQL (L8–9)

P8 SQL NULL T(x) holds the values 1, 2, 2, NULL, 5. What does SELECT COUNT(*) FROM T WHERE x <> 2 return?
✓ 2
x <> 2 is TRUE for 1 and 5. For 2: false. For NULL: UNKNOWN, and WHERE keeps only TRUE rows. So 2 rows. Trap: answer 3 (counting NULL as “not 2”).
P9 NOT IN trap S(a) = {1, 2, 3}, R(b) = {1, NULL}. How many rows does SELECT a FROM S WHERE a NOT IN (SELECT b FROM R) return?
✓ 0
a NOT IN (1, NULL) ≡ a≠1 AND a≠NULL. For a=1: false. For a=2,3: (TRUE AND UNKNOWN) = UNKNOWN → row rejected. So zero rows. (Remove the NULL and you would get 2 rows.)
P10 GROUP BY / HAVING Emp(dept, sal): (D1,10), (D1,20), (D2,30), (D2,NULL), (D3,5). How many rows are returned by SELECT dept FROM Emp GROUP BY dept HAVING AVG(sal) > 12?
✓ 2
AVG ignores NULL. D1: 15 ✓. D2: 30/1 = 30 ✓ (not 15). D3: 5 ✗. Rows: D1, D2.
P11 Outer join Table A has id values 1, 2, 3, 3. Table B has id values 3, 3, 4. How many rows does A FULL OUTER JOIN B ON A.id = B.id return?
✓ 7
Kaise bani: (1) matching column = id. (2) Inner pairs: A ke dono 3 × B ke dono 3 = 4 rows (1 aur 2 ka B me partner nahi). (3) A ke unmatched: id 1, 2 ⇒ B ke columns NULL ke saath 2 rows. (4) B ka unmatched: id 4 ⇒ A ke columns NULL ke saath 1 row. Total 4 + 2 + 1 = 7.

D. FDs, normal forms, decomposition (L10–12)

P12 Keys R(A,B,C,D,E) with F = {A→B, BC→D, D→E, E→A}. How many candidate keys does R have?
✓ 4 (AC, BC, CD, CE)
C never appears on an RHS, so every key contains C. AC: A→B, BC→D, D→E: all. BC: D, E, A: all. CD: E, A, B: all. CE: A, B, D: all. C alone gives only {C}. So every 2-set containing C is a key: exactly 4. (All five attributes are prime.)
P13 Minimal cover F = {A→BC, B→C, A→B, AB→C}. How many FDs are in a minimal cover?
✓ 2 ({A→B, B→C})
Split A→BC into A→B, A→C. In AB→C, B is extraneous because A→C (A+ = ABC), so it becomes A→C (duplicate). A→C is redundant: A→B→C. Left: A→B and B→C.
P14 FD derivation F = {A→B, C→D, BD→E}. Which are derivable (MSQ)? (a) AC→E (b) A→E (c) AD→B (d) BC→E
✓ (a), (c), (d)
AC+ = A,C → B,D → E: (a) ✓. A+ = {A,B}: (b) ✗. AD→B: A→B and decomposition/augmentation ✓. BC+ = B,C → D → BD gives E: (d) ✓.
P15 Normal form R(A,B,C) with F = {AB→C, C→B}. Highest normal form? (1NF / 2NF / 3NF / BCNF)
✓ 3NF
Keys: AB and AC (AC+ = ABC). All attributes are prime, so no partial or transitive trouble: 3NF holds (RHS B of C→B is prime). But C is not a superkey, so BCNF fails.
P16 Decomposition R(A,B,C,D), F = {A→B, C→D}. Decomposition R1(A,B), R2(C,D), R3(A,C). Which is true? (a) lossless only (b) dependency-preserving only (c) both (d) neither
✓ (c) both
Lossless: R1 ⋈ R3 on A: A is a key of R1 (A→B), so lossless, giving ABC. Then ⋈ R2 on C: C is a key of R2 (C→D), lossless. Result ABCD. Dependency-preserving: A→B lives in R1, C→D in R2.
P17 DP trick R(A,B,C), F = {A→B, B→C, C→A}. Is the decomposition {AB, BC} dependency-preserving?
✓ Yes
Projected FDs: on AB: A→B and B→A (B→C→A); on BC: B→C and C→B (C→A→B). The lost-looking C→A is recovered: C→B (in BC) and B→A (in AB). Never judge from the “obvious” FDs alone: use closures.

E. File organization, indexing, B+ tree (L13–15)

P18 Sparse index Block size 1024 B, record 100 B, unspanned. File of 10,000 records ordered on key field (12 B), block pointer 8 B. Primary (sparse) index, binary search on index. Block accesses to fetch one record?
✓ 6
bfr = ⌊1024/100⌋ = 10; data blocks = 1000. Index entries = 1000 (one per block), entry = 20 B, bfri = ⌊1024/20⌋ = 51, index blocks = ⌈1000/51⌉ = 20. Binary search: ⌈log2 20⌉ = 5, +1 data block = 6. (No index: ⌈log2 1000⌉ = 10.)
P19 Secondary index Same file, but the file is NOT ordered on the key and a dense secondary index is built on the key. Block accesses with binary search on the index?
✓ 9
Dense: 10,000 entries, bfri = 51, index blocks = ⌈10000/51⌉ = 197. Binary: ⌈log2 197⌉ = 8 (27=128 < 197 ≤ 256), +1 data block = 9.
P20 B+ tree order Block 512 B, node pointer 8 B, key 14 B, record pointer 8 B. Maximum node pointers in a non-leaf node of a B+ tree?
✓ 23
Letters: B=512, P=8, K=14, p = max node pointers. pP + (p−1)K ≤ B ⇒ 8p + 14(p−1) ≤ 512 ⇒ 22p ≤ 526 ⇒ p ≤ 23.9 ⇒ p = 23 (check: 8×23 + 14×22 = 184 + 308 = 492 ≤ 512; p=24: 192 + 322 = 514 > 512).
P21 B+ capacity Using the B+ tree of P20, the leaf holds L (key + record pointer) pairs and one next-leaf pointer Pn (8 B). What is the maximum number of keys in a 3-level B+ tree (root, one internal level, leaves) in which every node is full?
✓ 11,638
Leaf: L(K + Pr) + Pn ≤ B ⇒ 22L + 8 ≤ 512 ⇒ L ≤ 22.9 ⇒ L = 22. Root ke p = 23 children, har child ke 23 children ⇒ leaves = 23 × 23 = 529. Keys = 529 × 22 = 11,638.
P22 B-tree insertion Insert 10, 20, 30, 40, 50, 60, 70 in this order into an empty B-tree of order 3 (max 2 keys, 3 pointers per node; split promotes the median). What is the key in the root?
✓ 40
10,20 | +30 splits → root 20. +40, +50: right leaf 30,40,50 splits → root [20,40]. +60 → leaf [50,60]. +70: leaf [50,60,70] splits, 60 goes up, root [20,40,60] overflows, 40 goes up. New root [40]; children [20] and [60]. Height = 3.

F. Data transformation (L16–18)

P23 z-score Data: 2, 4, 4, 4, 5, 5, 7, 9. Using the population standard deviation, the z-score of 9 is?
✓ 2
Mean = 40/8 = 5. Variance = (9 + 1 + 1 + 1 + 0 + 0 + 4 + 16)/8 = 32/8 = 4, SD = 2. z = (9 − 5)/2 = 2. (With sample SD, √(32/7) = 2.14: z = 1.87. Read the question for “population”.)
P24 Binning Sorted data: 4, 8, 15, 21, 21, 24, 25, 28, 34. Equal-depth binning with 3 bins, then smoothing by bin means. What replaces 8?
✓ 9
Bins: [4,8,15], [21,21,24], [25,28,34] (3 values each). Bin 1 mean = 27/3 = 9. So 4, 8, 15 all become 9. (Bin 2 → 22, bin 3 → 29.)
P25 Sampling Population of 1000 records is sampled systematically with sample size 50 and random start 7. Which record number is the 6th sampled element?
✓ 107
k = N/n = 1000/50 = 20. Sample: 7, 27, 47, 67, 87, 107, … 6th = 7 + 5×20 = 107.
P26 Huffman Symbols with frequencies a:5, b:2, c:1, d:1. Total bits for the whole message under Huffman coding?
✓ 15
Merge c+d = 2; merge (cd)+b = 4; merge 4 + a = 9. Depths: a 1, b 2, c 3, d 3. Bits = 5×1 + 2×2 + 1×3 + 1×3 = 15 (fixed 2-bit code would cost 18).

G. Warehouse, cubes, measures (L19–21)

P27 Cube rows Fact table Sales(Product, Store, Day, amt) has 10 products, 5 stores, 30 days and every combination is present. How many rows does SELECT ... GROUP BY CUBE(Product, Store, Day) produce?
✓ 2046
Each dimension contributes (distinct values + 1 for ALL): (10+1)(5+1)(30+1) = 11 × 6 × 31 = 2046. (Check on 2025 Q46: (3+1)(2+1) = 12.)
P28 Cuboids A cube has 3 dimensions with concept hierarchies of 3, 2 and 4 levels (excluding ALL). How many cuboids?
✓ 60
∏(Li+1) = 4 × 3 × 5 = 60.
P29 Measure types Which statements are TRUE (MSQ)? (a) MIN is distributive (b) AVG is distributive (c) VARIANCE is algebraic (d) MEDIAN is holistic
✓ (a), (c), (d)
AVG is algebraic (needs SUM and COUNT), not distributive. Variance is algebraic (needs COUNT, SUM, SUM of squares). MEDIAN needs all values: holistic.
P30 OLAP ops Match: (i) Quarter → Month, (ii) Fix Year = 2020 only, (iii) Year in {2019, 2020} and Country in {IN, US}, (iv) swap axes. Operations: drill-down, slice, dice, pivot.
✓ (i) drill-down, (ii) slice, (iii) dice, (iv) pivot
Slice fixes one dimension to one value (dimension count drops by one). Dice picks a sub-cube on 2+ dimensions (dimensions stay). Pivot only rotates the view.
