14.1 · Index kyun chahiye? book ke peeche wala index

Picture: 1000 page ki ek kitaab me tumhe "Normalization" padhna hai. Option 1: har page palto (file scan). Option 2: kitaab ke peeche index dekho: "Normalization → page 125" — seedha wahan. Database index bhi yahi hai: ek chhoti alag file jisme (search key, pointer) ki entries hoti hain.

Search key (e.g. roll = 50)
→pointer
Data block / record

Index hamesha data file se bahut chhota hota hai (entry = sirf key + pointer, poora record nahi). Chhota matlab kam blocks → search ke liye index par binary search bahut sasta, phir sirf 1 data block padho.

GATE ka cost model (yaad rakho)

Hamesha block accesses ginte hain. Single-level index par:
cost = ⌈ log₂ (index blocks) ⌉ + 1  (1 = data block ka access)

Multilevel me: cost = (index levels) + 1.

Index ka nuksan

Extra jagah leta hai aur har insert / delete / update par index bhi update karna padta hai. Isliye har column par index nahi banate.

14.2 · Notation aur saare formulas ek hi jagah

Pehle data file (Lesson 13 se):

  • r = records, R = record size, B = block size → bfr = ⌊B/R⌋, data blocks b = ⌈r/bfr⌉.

Ab index file:

  • V = search-key field size, P = pointer size (block pointer / record pointer) → index entry size Rᵢ = V + P.
  • Index blocking factor bfrᵢ (isko fan-out fo bhi kehte hain) = ⌊ B / (V + P) ⌋.
  • E = index entries ki ginti (type par depend karta hai — niche table).
  • Index blocks bᵢ = ⌈ E / bfrᵢ ⌉.
Index typeEntries E (number of index entries)Dense / Sparse
Primary (data file ordered on key)b (ek entry har data block ki — "block anchor")Sparse (non-dense)
Clustering (data file ordered on non-key)#distinct values (ek entry har distinct value ki)Sparse (non-dense) — standard textbook
Secondary on key (file ordered on kuch aur)r (har record ki entry)Dense
Secondary on non-keyr (har record) ya #distinct values + pointer blocksDense (ya ek extra level)
Cost summary
  • Index se pehle (ordered file, key par): ⌈log₂ b⌉
  • Single-level index se: ⌈log₂ bᵢ⌉ + 1
  • Multilevel index se (t levels): t + 1
  • Secondary index se pehle (unordered file): b/2 avg, b worst (linear)

GATE trap · sparse sirf sorted file par

Sparse index ka logic ye hai: "largest key ≤ x wali entry ka block hi x ko rakhega". Ye tabhi sach hai jab data file usi key par sorted ho. Isliye unordered file par sparse index nahi bana sakte — wahan secondary (dense) hi chalega.

Ab tum try karo

Ek file ordered nahi hai, uske "Email" (unique) par index banana hai. Dense ya sparse? Kitni entries agar r = 10,000?

Answer: Dense (secondary index), E = r = 10,000 entries.

14.4 · Teen index types: kaunsa kab? primary · clustering · secondary

Do sawaal poochho: (1) data file kis field par physically sorted hai? (2) jis field par index banana hai, wo unique key hai ya nahi?

Data file is field par sorted hai?Field unique key?Index ka naamEntry kitni
HaanHaan (key)PRIMARY indexb (ek per block) — sparse
HaanNahi (non-key)CLUSTERING index#distinct values — sparse
NahiKey ho ya na hoSECONDARY indexr (dense) ya distinct + pointer blocks
Ek file par kitne index?

File physically ek hi order me sorted ho sakti hai, isliye ek file par max 1 primary ya 1 clustering index (dono nahi). Secondary index kitne bhi bana sakte ho.

Terminology warning

Commercial databases "primary index" us index ko bol dete hain jo primary key par ho. GATE / textbook (Elmasri-Navathe) me primary = file ordered on key. Question jo definition de, wahi maano.

(a) Primary index · worked example

Setup: r = 30,000, R = 100 B, B = 1024 B, key V = 9 B, pointer P = 6 B. File sorted on key.

  1. Data: bfr = ⌊1024/100⌋ = 10; b = ⌈30000/10⌉ = 3000 blocks.
  2. Index entry Rᵢ = 9 + 6 = 15 B; bfrᵢ = ⌊1024/15⌋ = ⌊68.27⌋ = 68.
  3. Primary index = ek entry per data block → E = b = 3000.
  4. Index blocks bᵢ = ⌈3000/68⌉ = ⌈44.1⌉ = 45. (44 × 68 = 2992 < 3000 → 45.)
  5. Search cost = ⌈log₂ 45⌉ + 1 = 6 + 1 = 7 (25 = 32 < 45 ≤ 64).
  6. Index ke bina (binary search on data) = ⌈log₂ 3000⌉ = 12.

Matlab 12 se 7 — index ne ~42% accesses bacha liye. (Index chhota hai isliye uska binary search kam steps leta hai.)

Dense primary index (agar har record ki entry ho): E = 30000 → bᵢ = ⌈30000/68⌉ = 442; cost = ⌈log₂ 442⌉ + 1 = 9 + 1 = 10 — sparse (7) se zyada bada aur dheema. Isiliye primary hamesha sparse banate hain.

(b) Clustering index · worked example

Picture: students file Dept par sorted hai (Dept non-key). Index me har distinct Dept ke liye ek entry, jo us Dept ke pehle block ko point karti hai. Aage ke blocks me wahi Dept contiguous.

Setup: wahi file (b = 3000, bfr = 10), Dept ki 500 distinct values, V = 4 B, P = 6 B.

  1. Rᵢ = 4 + 6 = 10; bfrᵢ = ⌊1024/10⌋ = 102.
  2. E = 500 distinct values; bᵢ = ⌈500/102⌉ = ⌈4.9⌉ = 5 (4 × 102 = 408 < 500).
  3. Records per Dept = 30000/500 = 60 → 60/10 = 6 data blocks per Dept (contiguous).
  4. Ek Dept ke saare records: index search ⌈log₂ 5⌉ = 3, phir 6 blocks → 3 + 6 = 9 accesses (agar group block ke start se shuru ho; boundary par 7 blocks ho to 10).
Clustering index me "dense" ka confusion

Elmasri-Navathe: clustering index non-dense (har distinct value ki ek entry). Kuch courses ise "dense on distinct values" bhi kehte hain. GATE numericals me entries = #distinct values hi use hote hain; question me agar "entry per block" likha ho to wo.

(c) Secondary index · worked example

Wahi file par (b = 3000) ab ek unique key field jis par file sorted nahi hai (jaise PAN no.). Same V = 9, P = 6 (record pointer).

  1. bfrᵢ = ⌊1024/15⌋ = 68 (pehle jaisa).
  2. Dense: E = r = 30000.
  3. bᵢ = ⌈30000/68⌉ = ⌈441.2⌉ = 442 (441 × 68 = 29988 < 30000).
  4. Search = ⌈log₂ 442⌉ + 1 = 9 + 1 = 10 (28 = 256 < 442 ≤ 512). Bina index: linear ≈ 3000/2 = 1500 avg (3000 worst).

Index file sorted hota hai (key order me), isliye uspar binary search ho sakta hai — data file chahe unsorted ho.

Secondary index on a non-key field (duplicates!)

Jaise Dept par secondary index, jabki file Dept par sorted nahi. Ek value ke kai records, alag-alag blocks me bikhre. 3 tareeke:

OptionKaiseKya hota hai
1. Dense, duplicate entriesHar record ki ek entry (key value repeat)E = r. Simple par badi.
2. Variable-length entryEk entry me value + saare pointers ki listEntry size alag-alag.
3. Extra level of indirection (Elmasri option 3)Index me har distinct value ki ek fixed-size entry → ek pointer-block jisme us value ke saare record pointersE = #distinct; ek aur block read
Worked example · option 3

r = 50,000, 500 distinct values, V = 10, P = 10, B = 1000. Entry 20 B → bfrᵢ = 50 → index blocks = ⌈500/50⌉ = 10. Har value ke 50000/500 = 100 record-pointers (10 B each) → ek block 100 pointers rakh sakta hai → 1 pointer-block per value (500 pointer blocks total).

Equality search (worst): ⌈log₂ 10⌉ = 4 (index) + 1 (pointer block) + up to 100 (data blocks, har record alag block me) = 105.

Trap · secondary ko sparse mat banao

Secondary index data file ki order ko follow nahi karta (data bikhra hai). Isliye dense hona hi padega (ya pointer-block wala rasta). "Secondary index sparse hota hai" — galat.

14.5 · Multilevel index index ka bhi index

Problem: index khud bahut bada ho sakta hai (442 blocks) aur binary search me abhi bhi ~9 steps. Idea: us index ko hi ek "file" maan lo aur uspar ek aur (sparse) index banao! Phir uspar bhi, jab tak top level me sirf 1 block na bache.

Real-life: kitaab ke index ka bhi ek mini-index: "A–F: page 480, G–M: page 495 …" — pehle ye dekho, phir sahi page, phir entry.

Rules
  • First level = given index (primary / clustering / secondary) — iske E aur bᵢ pehle jaise.
  • Har upar ka level sparse: uski entries = neeche wale level ke blocks ki ginti, ek entry per block.
  • Fan-out fo = bfrᵢ (ek index block me kitni entries).
  • Level k+1 ke blocks = ⌈ (level k ke blocks) / fo ⌉. Jab 1 aa jaaye, ruk jao.
  • Index levels t = jitne levels bane (top tak). Cost = t + 1 (t index blocks + 1 data block).
  • Shortcut: t = ⌈ logfo (b₁) ⌉ + 1, jaha b₁ = first-level index blocks (b₁ = 1 ho to t = 1).

Worked example A · primary index ka multilevel

Upar ka primary index: b₁ = 45 blocks, fo = 68.

  1. Level 1: 45 blocks (3000 entries ÷ 68).
  2. Level 2: entries = 45 (ek per level-1 block) → ⌈45/68⌉ = 1 block → top mil gaya.
  3. t = 2 index levels. Cost = 2 + 1 = 3.
  4. Check shortcut: ⌈log₆₈ 45⌉ + 1 = ⌈0.90⌉ + 1 = 1 + 1 = 2 ✔.
  5. Total index size = 45 + 1 = 46 blocks (single-level 45 se sirf 1 zyada).

Worked example B · secondary (dense) ka multilevel

  1. Level 1: 442 blocks (30000 entries ÷ 68).
  2. Level 2: ⌈442/68⌉ = ⌈6.5⌉ = 7 blocks (6 × 68 = 408 < 442).
  3. Level 3: ⌈7/68⌉ = 1 block → top.
  4. t = 3. Cost = 3 + 1 = 4. Shortcut: ⌈log₆₈ 442⌉ + 1 = ⌈1.44⌉ + 1 = 3 ✔.
  5. Total index blocks = 442 + 7 + 1 = 450.
Traps
  • Upar ke levels me entries = blocks ki ginti (E nahi, r nahi).
  • Har level par ceil, aur tab tak jab tak 1 na ho jaaye.
  • Multilevel me log₂ ka use nahi — har level me 1 block padhte hain (us level ka block seedha pointer se).
  • Multilevel index fixed fan-out par khade hain; insert/delete par sab levels badalte hain — isiliye dynamic version B+ tree hai (Lesson 15).
Kitne records address kar sakta hai?

Ek top block + fo = 100: top 100 entries → level-1 ke 100 blocks → 100 × 100 = 10,000 entries → 10,000 data blocks. Agar bfr = 20 → 2,00,000 records sirf 2 index levels se (3 levels se 106 blocks). Ye "fan-out ka kamaal" hai — isi se B+ tree height chhoti rehti hai.

Ab tum try karo

Level-1 index me 2000 blocks, fan-out 40. Index levels aur search cost?

Answer: 2000 → ⌈2000/40⌉ = 50 → ⌈50/40⌉ = 2 → ⌈2/40⌉ = 1. Levels = 4 (2000, 50, 2, 1). Cost = 4 + 1 = 5. Total index blocks = 2000 + 50 + 2 + 1 = 2053.

14.6 · ISAM Indexed Sequential Access Method

ISAM = sorted data file + multilevel sparse index, jo ek baar banaya jaata hai aur phir badalta nahi (static). Insert aane par kya ho? Index nahi badalta — agar data page full hai to overflow page jud jaata hai.

  • Banana: data sort karo → data pages allocate (aksar ~80% full chhodte hain) → upar sparse index levels banao.
  • Search: root se data page tak t index pages + 1 data page (+ overflow chain me jitne pages). t = ⌈logF N⌉ (N data pages, F fan-out).
  • Insert: sahi data page dhoondo; jagah ho to daalo, warna overflow page (chain). Delete: record hatao; khaali overflow page free.
  • Index pages kabhi change nahi hote → locking asaan, par structure "skewed" ho sakta hai.
Worked example (ISAM)

N = 10,000 data pages, fan-out F = 100. Level 1: ⌈10000/100⌉ = 100 pages; Level 2: ⌈100/100⌉ = 1 root page. t = 2. Search = 2 + 1 = 3 I/Os (overflow na ho to). Agar kisi page par overflow chain me 3 aur pages hon → us key ke liye 3 + 3 = 6.

ISAMB+ tree
Index structureStatic (bante waqt fix)Dynamic (split / merge se adjust)
Insert full page parOverflow chainPage split, balanced rehta hai
HeightFixed; overflow chain lambi ho sakti haiHamesha balanced, chhoti
Performance degrade?Haan, jaise-jaise inserts — periodic reorganizeNahi (gracefully)
Kab achhaMostly static / read-heavy dataUpdates wale data, general use

PYQ · GATE DA 2024 · Q55 MSQ · Indexing

OTT company ka bada disk-based relational database: Movie(ID, CustomerRating), Genre(ID, Name), Movie_Genre(MovieID, GenreID). Query:

SELECT * FROM Movie, Genre, Movie_Genre
WHERE Movie.CustomerRating > 3.4
  AND Genre.Name = "Comedy"
  AND Movie_Genre.MovieID = Movie.ID
  AND Movie_Genre.GenreID = Genre.ID;

Ye query kin indexing options se tez ho sakti hai?

OptionIndex choiceVerdict
AB+ tree on all the attributesHaan — range (>3.4), equality (Name) aur joins (ID) sab handle
BHash on Genre.Name + B+ tree on remainingHaan — Name = "Comedy" par hash best; CustomerRating par B+ range scan
CHash on Movie.CustomerRating + B+ on remainingNahi — CustomerRating > 3.4 range hai, hash isme madad nahi karta
DHash on all attributesNahi — range condition par hash bekaar
  1. Query ke operators likho: CustomerRating > 3.4 → range; Name = "Comedy" → equality; ID = ID joins → equality.
  2. Range ke liye ordered index (B+ tree) zaroori — hash fail.
  3. Equality ke liye hash ya B+ dono chalte hain.
  4. Isliye jis option me CustomerRating par B+ tree hai wahi range ko tez karta hai: A aur B. C aur D me rating par hash hai → range ka koi fayda nahi.
Answer
A and B (MSQ).  Trick: range ⇒ B+ tree; equality ⇒ hash/B+ dono. (Note: C me baaki attributes par B+ hone se joins thoda tez ho sakte hain, par jo condition question me khaas hai — rating range — usko C help nahi karta; handbook ke verified answer ke anusaar A, B.)
Chhota decision rule
  • Sirf = aur kabhi range nahi → Hash theek.
  • Kabhi range / sort / MIN-MAX → B+ tree.
  • Ek attribute par duplicates bahut zyada (low selectivity, jaise gender) → index kam faydemand.
  • File already sorted on a key → primary (sparse) index.
  • File sorted on non-key → clustering index.
  • Kisi aur column par search → secondary.

14.8 · Practice 12 questions

Setup dohrao

Q1-Q5 ek hi file par: r = 50,000, R = 100 B, B = 1000 B, V = 10 B, P = 10 B. Pehle bfr = 10, b = 5000, Rᵢ = 20, bfrᵢ = 50.

Q1. File key par sorted hai. Primary index: entries, index blocks, single-level search cost? Bina index?
✔ E = 5000; bᵢ = 100; cost = 8; bina index = 13
E = b = 5000; bᵢ = 5000/50 = 100; ⌈log₂ 100⌉ + 1 = 7 + 1 = 8; ⌈log₂ 5000⌉ = 13 (4096 < 5000 ≤ 8192).
Q2. Q1 ke primary index ko multilevel banao. Levels, cost, total index blocks?
✔ 3 levels; cost 4; 103 blocks
100 → ⌈100/50⌉ = 2 → ⌈2/50⌉ = 1. Levels 3, cost 3 + 1 = 4, total 100 + 2 + 1 = 103.
Q3. File non-key field par secondary index (key field jaise unique) — dense secondary: bᵢ aur single-level cost? Multilevel cost aur total?
✔ bᵢ = 1000; cost 11; multilevel cost 4; total 1021
E = 50000 → ⌈50000/50⌉ = 1000. ⌈log₂ 1000⌉ + 1 = 10 + 1 = 11. 1000 → 20 → 1: 3 levels, cost 4, total 1021.
Q4. File Dept par sorted (non-key), 200 distinct Dept. Clustering index blocks, aur ek Dept ke saare records laane ki cost (index single level)?
✔ bᵢ = 4; cost = 2 + 25 = 27
E = 200 → ⌈200/50⌉ = 4; ⌈log₂ 4⌉ = 2. Per Dept: 50000/200 = 250 records → 25 blocks. Total 2 + 25 = 27 (aligned).
Q5. Q1 ka primary index agar dense banaya jaaye to kitne extra blocks?
✔ 900 extra
Dense: ⌈50000/50⌉ = 1000 blocks. Sparse: 100. Fark = 900.
Q6. r = 10,00,000, R = 200 B, B = 4096 B, V = 12 B, P = 4 B. Primary index single-level cost? Multilevel?
✔ 9 aur 3
bfr = ⌊4096/200⌋ = 20; b = 50000. Rᵢ = 16, bfrᵢ = 256. bᵢ = ⌈50000/256⌉ = 196. Single: ⌈log₂ 196⌉ + 1 = 8 + 1 = 9. Multilevel: 196 → 1: 2 levels, cost 3.
Q7. Ek file par kitne primary + clustering index ho sakte hain? Secondary?
✔ Kul 1 (primary ya clustering); secondary any number
File ek hi field par physically sorted ho sakti hai.
Q8. T/F: "Secondary index on a key field sparse ho sakta hai."
✔ False
File us field par sorted nahi → block-anchor logic fail; dense chahiye.
Q9. Multilevel index, fan-out 100, top level 1 block. (a) 2 index levels (top + ek neeche) kitne data blocks address karte hain? bfr = 20 ho to records? (b) 3 index levels?
✔ (a) 10,000 blocks; 2,00,000 records (b) 106 blocks; 2 × 107 records
Top 1 block → 100 entries → 100 level-1 blocks → 100 × 100 = 10,000 entries → 10,000 data blocks → × 20 = 2,00,000 records. Ek level aur: × 100 → 106 blocks, 2 crore records.
Q10. ISAM me 10,000 data pages, fan-out 100: search I/Os? Ek page par 2-page overflow chain ho to us key ke liye?
✔ 3 aur 5
t = ⌈log₁₀₀ 10000⌉ = 2; 2 + 1 = 3. Overflow chain 2 pages jode → 3 + 2 = 5.
Q11. Query: SELECT * FROM Emp WHERE salary BETWEEN 30000 AND 50000 ORDER BY salary; kaunsa index? Aur WHERE empid = 77?
✔ Salary par B+ tree; empid par hash (ya B+)
Range + sort → ordered index. Equality-only → hash best.
Q12. Index entry = 8 B key + 4 B pointer, B = 512, 20,000 entries (single level). Index blocks, binary-search cost?
✔ bfrᵢ = 42; bᵢ = 477; cost = 9 + 1 = 10
⌊512/12⌋ = 42; ⌈20000/42⌉ = ⌈476.2⌉ = 477; 28 = 256 < 477 ≤ 512 → ⌈log₂ 477⌉ = 9; +1 data block = 10.

14.9 · Lesson 14 cheat box

Formulas
  • bfr = ⌊B/R⌋, b = ⌈r/bfr⌉
  • Rᵢ = V + P, fo = bfrᵢ = ⌊B/Rᵢ⌋
  • E: primary = b · clustering = #distinct · secondary = r
  • bᵢ = ⌈E / fo⌉
  • Single-level: ⌈log₂ bᵢ⌉ + 1
  • Multilevel: levels t (upar-upar ⌈/fo⌉ jab tak 1) → cost t + 1; t = ⌈logfo b₁⌉ + 1
  • ISAM: ⌈logF N⌉ + 1 (+ overflow)
Traps
  • Primary = file sorted on key; clustering = sorted on non-key; secondary = not sorted.
  • Sparse needs sorted file; secondary is always dense.
  • Max 1 primary/clustering per file.
  • Upar ke levels me entries = lower level ke blocks.
  • Hash index range ke liye bekaar.
  • Floor for fo, ceil for blocks.
  • Cost me +1 data block mat bhoolna.
